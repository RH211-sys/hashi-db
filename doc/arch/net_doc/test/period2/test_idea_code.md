# 测试方法：实现细节

## 正确性测试

网络正确性测试模块 `net_correctness_test`（验证协议解析、会话阶段、连接派发和服务端收发）使用内存传输替身承载请求与响应，避免顺序测试依赖外部网络。部分场景将读取拆成 5 字节片段、将写入限制为 3 字节，以覆盖 TCP 字节流分段和短写时的帧边界维护。

可控的命令执行器替身会记录已提交请求，并由测试逐项触发完成结果。因此，测试能够在 HELLO 或 AUTH 尚未完成时检查后续请求是否仍留在队列中，而不是依赖真实业务执行时间。

协商失败场景使用字段完整的排队请求，区分协议字段解析和会话阶段拒绝。协议错误场景则让网络帧本身可解析、但请求缺少必需字段，以单独检查错误是否等待前序请求完成。断言检查响应请求标识、成功或错误标记、派发次数，以及错误响应排空后的连接关闭状态。

半关闭场景在输入耗尽时模拟对端结束发送方向；测试逐项完成已接收请求，再检查所有响应是否写出以及连接是否在输出排空后关闭。

## 压力测试

网络压力测试模块 `net_stress_test` 通过同一连接提交 100,000 个请求，并在受限的读写预算下推进网络处理。测试记录输入与输出累计字节数、总耗时及请求吞吐量，用于确认大量请求能够完成且输出统计符合本轮测试记录。
