# 测试方法：核心逻辑

## 测试目标

验证同一连接上的请求按接收顺序处理，并确保响应顺序与请求顺序一致。客户端可以连续发送多个完整请求；服务端在当前请求完成前保留后续请求，待连接恢复空闲后再逐个处理。

## 正确性验证

1. **正常阶段推进**：发送 HELLO（协议版本协商请求）、AUTH（身份认证请求）和 GET（数据读取请求），逐个完成前序请求，确认后续请求只在前序完成后提交，并检查响应关联标识和顺序。
2. **协商失败**：令 HELLO 返回失败，再检查已经排队的 AUTH 与 GET 是否都被拒绝、是否没有进入业务处理，以及错误响应是否仍按请求顺序返回。
3. **协议错误延后**：在有效请求之后放置字段不完整的请求，确认有效请求先完成并先返回响应，随后才返回对应的协议错误并关闭连接。
4. **对端半关闭**：客户端发送完一批请求后结束发送方向，确认服务端仍处理已经接收的请求，并在响应写完后才关闭连接。
5. **既有基础行为**：覆盖帧编解码、命令字段校验、会话授权、非法网络帧处理及 Linux 回环收发。

## 压力验证

网络压力测试模块 `net_stress_test`（验证大量请求经过连接处理后的收发统计与完成情况）处理 100,000 个请求，并记录输入字节数、输出字节数、完成耗时和吞吐量。吞吐量用于描述本次环境下的实测表现，不作为其他硬件或构建配置的保证值。

本轮测试是单连接的大量请求，没有测试并发连接
