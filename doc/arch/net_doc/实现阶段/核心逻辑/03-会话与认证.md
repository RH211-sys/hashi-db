# 会话与认证

本篇说明一条连接从建立到“可以执行正常业务”要经过哪些阶段，每个阶段允许做什么，以及当前实现卡在哪里。

## 1. 三个阶段

除传输层握手之外，会话有明确的三个阶段：

```text
阶段一：未协商
   ↓ 收到并接受协商请求
阶段二：未认证
   ↓ 收到并接受认证请求
阶段三：就绪
   ↓
可以执行已授权的业务命令
```

连接的完整状态流转如下，括号里是会话层面的含义：

| 状态 | 含义 | 是否允许读取后续请求 |
|---|---|---|
| 已接受 | 传输刚建立 | 是 |
| 握手中 | 加密传输握手未完成 | 只推进握手 |
| 等待协商 | 阶段一，尚未完成版本协商 | 是（仅白名单内命令） |
| 等待认证 | 阶段二，已协商未认证 | 是（仅白名单内命令） |
| 就绪 | 阶段三 | 是 |
| 关闭中 | 停止收新请求，只写完剩余响应 | 否 |
| 已关闭 | 资源已释放 | 否 |

## 2. 各阶段的命令白名单

每个阶段允许执行的命令是固定的。不在白名单内的命令会被直接拒绝，并返回一个可以区分原因的失败：

| 阶段 | 允许的命令 | 拒绝时的结果 |
|---|---|---|
| 未协商 | 协商、探活、退出 | 坏帧，提示需要先协商 |
| 未认证 | 认证、探活、退出 | 未认证 |
| 就绪 | 全部已授权命令 | 无权限（ACL 未实现，当前一律放行） |

白名单的用意是把“协议还没谈好”和“身份还没确认”区分开：前者是协议用法错误，后者是权限问题。混在一起会让客户端不知道该先做什么。

探活和退出在三个阶段都放行，理由很实际：这两个命令不涉及业务数据，必须允许客户端在任何时候探测服务是否存活、以及主动断开。如果连退出都要先认证，客户端遇到认证服务异常时就只能用强制断连。

## 3. 协商规则

- 协商请求必须携带协议版本字段，长度正好 2 字节，内容为主版本 0、次版本 1。
- 版本不匹配时返回“不支持”，而不是“坏帧”——因为帧本身是合法的，是服务端能力不覆盖。
- 协商成功后，会话记录下协议版本和客户端声明的特性位，阶段推进到未认证。
- **已经协商成功的连接再次发协商请求，会被拒绝并按协议错误关闭连接**。重复协商会让“当前使用哪个版本”变得不确定，必须当作协议违规。

## 4. 认证规则

- 认证请求必须携带用户名和密码两个字段，缺一不可。
- 在没有完成协商之前发认证请求，会被拒绝并按协议错误关闭连接。顺序不能颠倒。
- 认证通过后，会话记录认证主体名称，阶段推进到就绪。
- 之后交到业务层的请求都会带上这个主体名称和对端地址，供业务侧记录与鉴权。

密码字段按二进制传输，不要求文本编码——这样可以使用任意字节的凭据，也避免了对密码做无意的文本处理。

## 5. 判定发生在哪一侧

会话判定在**连接侧**执行，发生在命令进入待执行队列之前。也就是说，未授权的命令根本不会离开网络层，不会占用执行线程，也不会被记进业务层。

这个位置是有意选的：越早拒绝，代价越小；同时业务层可以假定“收到的请求一定已经过了阶段检查”，不必重复判断会话状态。

## 6. 当前实现的实际表现

这一节描述的是当下事实，与设计目标不同，务必区分。

**协商和认证请求目前会被拒绝，会话无法推进到就绪。**
原因是这两个请求被交给了命令执行层处理，而当前挂上去的执行层是存储桥接——它只实现存储类命令，其余一律回“不支持”。协商和认证既不是存储命令，也没有别的实现接住它们，所以：

| 请求 | 当前返回 | 会话影响 |
|---|---|---|
| 协商 | 不支持 | 阶段不推进 |
| 认证 | 不支持 | 阶段不推进（且必须先协商，本来也到不了这一步） |
| 探活 | 成功 | 无 |
| 退出 | 成功，然后关闭连接 | 无 |
| 其余全部命令 | 坏帧（提示需要先协商）或未注册（查询/新增/修改） | 无 |

**因此当前端到端真正可用的只有探活和退出两条命令。** 其余命令要么被会话白名单拦下，要么被存储桥接回以“不支持”或“类型未注册”。

这里存在一个层次划分上的待确认点：**协议协商本质上是网络层的职责**——版本号和特性位由本层定义，本层也已经在收到结果后自己解析版本字段并推进阶段。把“是否接受这次协商”的决定权交给一个只懂存储的执行层，是当前实现里的一处别扭。认证则不同，它确实需要外部认证来源，交给外部实现是合理的。

在正式接入认证之前，建议先明确：协商由网络层直接裁决，执行层只处理业务命令。这一点需要与设计文档对齐后再动手。

## 7. 还没有的部分

- **没有真正的认证来源**：没有口令校验、没有凭据存储、没有第三方认证对接。
- **没有 ACL**：就绪之后所有命令一律放行，没有角色或权限模型。
- **没有认证超时**：设计文档提出过“超时未认证则关闭”，当前没有实现。
- **没有失败次数限制**：认证失败可以无限重试。
- **没有连接空闲超时**：长时间无数据的连接会一直保留，直到对端关闭或服务停止。

这些缺口意味着当前实现只适合本机开发与协议验证，不能暴露在不可信网络上。默认配置也印证了这一点：服务默认要求加密传输，而 TLS 尚未实现，所以默认配置会拒绝启动，必须显式打开明文开发许可。
