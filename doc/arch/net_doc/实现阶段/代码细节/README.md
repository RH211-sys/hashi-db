# 代码细节索引

本目录记录实现中值得记住的手法：为什么这样写、容易踩什么坑、整体逻辑怎么串起来。

与 [核心逻辑](../核心逻辑/) 的分工：那边讲“服务对外是什么行为”，这边讲“这行代码为什么这么写”。这里可以引用代码片段，但只引用说明问题所必需的最小片段。

## 记录标准

一篇合格的代码细节应当回答清楚三件事：

1. **要解决什么问题**：这段代码存在的必要性，不写会怎样。
2. **坑点在哪**：如果不这样写，会出什么错，错误的表现是什么。
3. **整体逻辑**：这段代码在完整链路里的位置，前后怎么衔接。

只贴代码不讲原因、或者只讲原因不贴关键语句，都不算合格。
