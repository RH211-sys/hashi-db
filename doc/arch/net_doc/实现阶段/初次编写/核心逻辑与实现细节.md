## 1. 职责与请求流转

术语说明：Acceptor 是监听端口并接纳新 TCP 连接的模块；Reactor 是独占维护一组连接状态的事件循环；ReactorGroup 负责管理多个 Reactor 并分配连接；Connection 保存单个连接的传输、会话、缓冲和请求状态；FrameCodec 在 TCP 字节流与完整帧之间转换；CommandParser 按命令规则校验字段；ICommandExecutor 是把结构化请求交给业务执行并接收异步结果的边界；Controller 是应用组装和控制网络服务的入口。

网络层把 TCP（传输控制协议，提供可靠有序字节流）输入转换成结构化命令，交给命令执行边界，再把异步结果送回原连接。网络层负责帧协议、连接会话及网络 I/O；命令含义、数据类型实体和存储接口映射由执行层负责。网络层不直接操作缓存表或磁盘文件，也不改变存储线程归属。

当前请求路径为：客户端连接进入 Controller，Controller 组装 NetworkServer；Acceptor 接入连接后交给 ReactorGroup；ReactorGroup 以轮询分配至一个 Reactor；该 Reactor 独占 Connection，完成帧解析和命令校验后提交给 ICommandExecutor。业务完成结果经有界消息队列回到同一个 Reactor，再由原连接编码并发送响应。

当前分配策略是轮询，而不是按连接数量均衡；本段记录的是源码现状。连接热路径由一个事件循环拥有，跨线程交互仅传递控制或完成消息，以减少连接对象的并发修改。

## 2. 协议帧与命令校验

MYDB v1（myDB 自定义网络协议的第一版）帧结构、字段编号、类型和命令契约集中见[设计阶段需求文档](../../设计阶段/需求文档.md#22-协议与命令范围)。本文只记录目前源码的行为与差异。

### 2.1 帧格式与增量解析

帧头固定为 24 字节，整数采用大端网络字节序。帧头包括协议标记、版本、标志、命令编号、头长度、消息体长度、请求关联标识及保留位。当前只接受版本 1、固定头长 24 字节、零保留位；压缩和分片标志尚不支持，未知标志会被拒绝。

消息体使用 TLV（类型、长度和值构成的字段序列）表达字段。FrameCodec 负责通用帧规则：单帧不得超过配置上限，保留字节必须为零，字段类型必须在已知范围；UTF-8 文本须有效，无符号/有符号 64 位整数长度固定为 8 字节，布尔值为单字节零或一，嵌套字段最多 8 层。它不解释业务命令，也不调用存储操作。

TCP 传入的字节块可能只包含半个头部或消息体，也可能含有多个完整帧。解析器保留未收齐的帧；连接处理按字节消费位置取出完整帧，并保留本次读取尚未处理的后缀，等待前序请求推进后继续解析。较早的兼容入口也可处理聚合输入，但连接主要路径使用增量消费方式。

### 2.2 命令字段规则

协议 v1 定义 14 个字段编号：协议版本、特性位、客户端名称、用户名、密码、负载、键、类型名称、值、生存时间、范围、连接标识、状态码和消息。字段编号属于线上契约，不得在后续版本中未经评审复用。

CommandParser（命令解析器）在通用帧校验后，按命令检查允许字段、类型、必填项、重复项、长度上限和 HELLO（协议协商命令）版本。校验成功才形成结构化请求。解析器识别某条命令，不代表当前执行器已经实现该命令。

## 3. 会话状态与连接顺序

### 3.1 会话协商和认证

Connection（单客户端连接状态持有者）建立后进入已接入状态；Transport（隐藏套接字读写细节的传输模块）完成握手后进入等待 HELLO 状态。Session（保存协商与身份信息的会话对象）记录协议版本、协商能力、认证主体和认证状态。只有 HELLO 成功后才完成协议协商，只有 AUTH（身份认证命令）由执行器成功处理后，会话才记录用户名并进入就绪状态。

这只是认证状态边界，并不代表实际认证已实现：当前没有凭据提供者或密码校验器，不能把解析到 AUTH 命令或用户名等同于身份认证成功。当前公开的存储绑定使用阶段性存储执行器，该执行器不实现 HELLO/AUTH，通常返回不支持。因此借助当前存储桥接无法完成 HELLO/AUTH 到就绪的完整客户端流程；PING（探活命令）和 QUIT（响应后关闭连接的命令）有执行响应。

### 3.2 同连接顺序

每个连接最多有一个业务请求在执行。完整帧校验后进入有界请求队列，再按队首顺序提交；前一个请求完成后才推进下一个请求。同一个连接内不能并行执行；已经解析的后续请求和未解析字节均受到队列/缓冲上限约束，达到限制后暂停读取或解析。不同连接之间允许并行。

完成结果返回拥有连接的 Reactor 后，必须匹配当前连接标识和请求标识。网络层统一构造响应或错误标志、状态码和可选消息，再放入输出队列。QUIT 或执行器要求写完后关闭时，会在已排队的响应发出后关闭连接。

### 3.3 协议错误与对端关闭

若帧格式错误且不能可靠地在字节流中重新同步，连接停止接收后续输入，清理等待的后续请求，尝试发送有界错误响应后关闭。若对端关闭读取方向，连接停止接受新请求；当前实现会尽量收尾已有请求和响应。不可恢复的 I/O 错误会立即关闭连接。

## 4. 线程归属与异步完成

### 4.1 线程职责

- Acceptor 接入线程：等待监听套接字就绪、接受连接、设置套接字选项并分派新连接；不解析业务命令，也不修改已有连接。
- Reactor 工作线程：运行事件循环，单线程维护所拥有连接的状态、输入输出和套接字 I/O；不等待存储任务。
- 阶段性存储执行器工作线程：调用过渡存储接口并等待异步结果；不直接访问连接对象或套接字。
- 其他完成线程：向连接所属 Reactor 的有界队列投递结构化结果并唤醒事件循环；不直接修改连接状态。

Reactor 使用 Linux epoll（Linux I/O 多路复用机制）的水平触发模式和 eventfd（Linux 事件计数文件描述符，用于唤醒事件循环）。任务放入有界队列后由 eventfd 唤醒等待中的 Reactor。每轮按顺序处理控制任务、普通任务和完成结果，再处理 I/O 事件；执行外部任务时不持有队列锁。

### 4.2 迟到完成结果

接入时分配单调递增的稳定连接标识，并生成连接代际。完成回调持有 Reactor 状态的弱引用、连接标识和代际。结果回投后需验证连接仍存在且代际吻合；连接关闭或标识被复用时，迟到结果丢弃，避免误投到新连接。

### 4.3 阶段性存储桥接

StorageControllerExecutor（将网络命令临时映射到现有存储控制接口的执行器）不是最终命令路由。它使用 4 个工作线程和最多 1,024 个等待任务；队列满时返回忙错误。工作线程可能因等待存储操作而阻塞，但 Reactor 不会阻塞。执行器停止时会唤醒并等待工作线程退出；存储控制对象必须在执行器及其在途任务结束前保持有效。

当前桥接器直接响应 PING 和 QUIT；GET、ADD、UPDATE 因网络类型未注册而不能返回完整数据；DELETE、PERSIST（请求持久化）、FLUSH（清理并刷盘）、REWRITE（整理持久化文件）只有有限的存储映射；其他未实现命令返回不支持。当前没有正式网络类型编解码注册，不得把 cereal 持久化字节发给客户端。

## 5. 容量控制与过载行为

以下是当前源码中的主要硬上限，不代表经过性能调优：

| 项目 | 当前值或规则 | 超限行为 |
|---|---|---|
| 活跃客户端 | 默认 10,000 | 接入线程不再接受新客户端 |
| 单帧 | 默认 16 MiB，可配置 | 作为帧错误处理并关闭连接 |
| 单连接请求队列 | 默认 64，包含在途请求 | 暂停继续解析或读取 |
| 单连接未解析输入 | 单帧上限加 64 KiB | 暂停后续套接字读取 |
| 单连接输出积压 | 固定 16 MiB | 编码失败或将超限时关闭连接 |
| 普通事件循环任务队列 | 4,096 项 | 入队失败，后续普通任务不执行 |
| 控制任务队列 | 256 项 | 入队失败；接入方按失败路径释放连接槽位 |
| 完成结果队列 | 4,096 项 | 结果无法入队时关闭对应连接，避免永久等待 |
| 阶段性存储桥接 | 4 个工作线程，最多 1,024 个等待任务 | 拒绝本次执行并返回忙错误 |
| 单轮 epoll 事件 | 最多 128 项 | 余下就绪事件在后续轮次处理 |
| 单次连接读写预算 | 读取 64 KiB，写入 256 KiB | 预算耗尽后留待后续事件循环 |

达到请求队列限制时，连接输入缓冲中的完整后续帧会保留，暂停进一步套接字读取；当前网络模块说明对“超额请求直接丢弃”的描述与源码不符。本轮没有修改该网络模块说明。

当前没有设计中的完整输入/输出高低水位滞回策略，也没有全局业务在途请求总量限制。连接上限、单连接上限和跨线程队列上限不能替代全局执行准入，也不能证明已经具备完整生产级过载治理。

## 6. 服务启动与停止

### 6.1 启动

默认监听回环地址 127.0.0.1 的 6380 端口。事件循环数量设为零时约按逻辑处理器数量的一半计算，至少为一个且不超过 16；默认连接上限为 10,000，单连接请求队列上限为 64，单帧上限为 16 MiB。

当前启动校验要求执行器有效、配置值位于实现允许范围，并明确允许开发明文传输。若监听地址不是实现明确认可的回环形式，还须设置远程明文许可；不会通过主机名解析推定回环地址。TLS（传输层安全协议）传输尚未实现，因此默认要求 TLS 的配置会拒绝启动。这是安全默认，不表示加密传输已经可用。

启动先建立事件循环组，再启动监听接入模块；任一阶段失败会停止已启动组件并释放资源。接入线程等待监听套接字可读后接受连接，并设置 TCP_NODELAY（禁用小包合并延迟）、SO_KEEPALIVE（启用 TCP 保活）、非阻塞和执行时关闭等属性。

### 6.2 当前停止实现与新目标方案

当前实现支持非排空停止和可选的有界排空。非排空路径关闭监听与连接，丢弃未执行的跨线程任务和尚未派发的连接请求；已经交给执行器的业务操作不会因网络停服自动回滚，但连接关闭后不再返回结果。可选排空路径停止接收新请求，继续推进已经接收的请求，最多等待 30 秒后关闭剩余连接。

上述可选排空能力与用户确认的新目标不一致。设计阶段的新目标方案是不排空：停止网络接入并关闭连接，丢弃所有尚未派发的请求；已经开始执行的业务继续运行，但不再返回响应。派发前若服务端已观察到客户端 TCP 连接关闭或重置，则丢弃该请求；响应发送前若已观察到连接关闭，则丢弃响应。服务器无法绝对获知远端进程是否存活，只能依据最近已观察到的 TCP 状态，客户端也可能在检查后断开。二轮源码修改时再按新目标调整当前停止实现；本轮只写明设计及源码差异。

## 7. 构建边界

网络目标从存储测试默认构建中隔离。网络核心包含帧编解码、命令解析、会话、连接和事件循环核心；Linux 服务端目标包含 TCP 传输、epoll 轮询器、事件循环组、接入模块和服务组装；阶段性存储桥接单独连接现有存储控制接口；聚合目标统一暴露这些网络模块。它们均排除在默认构建之外，以避免网络平台实现或存储桥接污染既有存储测试。

只有完整服务确实使用存储桥接时，构建才需同时提供存储层依赖符号。纯协议与连接核心测试可以只依赖网络核心。当前 Windows 接入实现返回启动失败，真实 Linux 网络 I/O 以 Linux 为目标；Windows IOCP（Windows 异步 I/O 完成端口机制）服务端尚未实现。

## 8. 实现范围、测试状态与差异

设计文档描述目标方案，不等同于当前已实现能力。当前主要未完成项如下：

1. TLS 尚未实现；默认要求 TLS 的服务配置会拒绝启动，只能在显式授权的开发配置下使用明文。
2. 认证提供者、密码校验和 ACL（访问控制列表，按主体及动作限制命令权限）数据源尚未闭环；当前阶段执行器不支持 HELLO/AUTH。
3. 完整数据 CRUD（增删改查）未完成：GET、ADD、UPDATE 因网络类型未注册而不能提供完整业务结果，磁盘序列化格式不得当作网络值格式。
4. 存储桥接只有部分 DELETE、PERSIST、FLUSH、REWRITE 映射；STATS（读取统计）、CLIENT_LIST（查询连接快照）、CLIENT_KILL（按连接标识请求关闭连接）尚无可用网络业务实现。
5. ConnectionRegistry（按连接标识提供有限快照并投递关闭请求的管理抽象）尚未装配，连接查询及远程关闭能力不可用。
6. 握手、协议协商、认证、组帧和空闲超时尚未实现。
7. 全局在途请求准入和完整的全局背压策略尚未实现；现有仅为局部连接、队列及缓冲限制。
8. 正式网络指标聚合和延迟统计模块尚未完整实现。
9. Windows 网络服务端尚未实现。
10. 初步测试状态：用户确认代码已经进行初步测试并通过，但未提供该次测试对应的源码版本、环境、用例清单或报告，本文件不据此推断覆盖范围或性能结果。本轮运行工作区现有网络测试可执行文件时，在 HELLO 命令解析用例失败；该可执行文件早于当前测试源码和解析器源码，未按当前源码重建，因此只能说明旧构建产物状态，不能作为当前源码的测试结论。正式结果仍需保存可追溯的构建和测试证据。
11. 网络模块说明文档对请求队列超限行为和回环地址范围的描述与源码存在差异，本文件分别在容量边界与启动说明中指出，尚未修改该源码目录文档。
12. 当前源码仍支持可选的有界停服排空，与新设计确定的立即停止目标不一致；按用户安排，二轮再修改源码，本轮只记录该差异。
