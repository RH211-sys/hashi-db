## 1. 两个子目录的分工

| 目录 | 写什么 | 能否出现代码 |
|---|---|---|
| [核心逻辑](./核心逻辑/) | 这一层对外表现出的业务规则：整体链路、各模块职责、状态流转、限额与错误语义 | **不能**。读者不看代码也要能读懂 |
| [代码细节](./代码细节/) | 值得记录的实现手法：为什么这样写、容易踩的坑、关键片段 | 可以，并配最小片段说明 |

判断标准很简单：如果一段内容能帮助人理解“这个服务对外是什么行为”，写进核心逻辑；如果只在解释“这行代码为什么这么写”，写进代码细节。

## 3. 当前实现范围

已经实现并可以运行的部分：

- **协议层**：固定头与字段的编解码、长度与类型校验、增量拆包、粘包切分、UTF-8 校验。
- **命令解析**：按命令校验字段集合、必填项、类型、长度与重复项，并还原成结构化请求。
- **会话状态**：协商与认证两个阶段的命令白名单检查。
- **连接处理**：非阻塞读写、单连接请求串行、输入/输出限额、协议错误收尾关闭。
- **Linux 事件循环**：非阻塞 TCP、level-triggered epoll、eventfd 跨线程唤醒、连接线程亲和、有界任务队列。
- **接入与服务装配**：监听、接入、客户端容量控制、多事件循环分派、优雅停止。
- **阶段测试桥接**：把命令转成存储层调用，并在独立线程上等待结果。

## 4. 明确没有实现的部分

以下内容在设计文档中出现过，但**当前代码里没有**，不要按已实现来理解：

1. **TLS 传输**：没有 TLS transport；因此默认配置（要求加密）会直接拒绝启动，只有显式打开明文开发许可才能跑起来。
2. **认证提供者与 ACL**：没有真正的认证来源。命令执行桥接只实现存储类命令，协商与认证请求都会被它以“不支持”拒绝，因此会话实际上停在最初阶段（详见 [核心逻辑/03](./核心逻辑/03-会话与认证.md)）。
3. **连接超时**：没有空闲超时、认证超时或请求组装超时。
4. **全局在途背压**：限额只做到“每连接”和“每个事件循环的队列”，没有跨连接的全局在途请求上限。
5. **连接管理能力**：连接注册表目前只有一个接口定义，没有实现、也没有被装配进去；连接列表与踢出命令只有协议定义，没有执行逻辑。
6. **统计命令**：统计命令只有协议定义，执行侧未实现。
7. **业务数据读写**：查询、新增、修改三类命令当前返回“类型未注册”，因为还没有确定的可上线数据编码约定。

## 5. 与设计文档的关系
