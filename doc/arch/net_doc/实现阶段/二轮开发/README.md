## 1. 本轮交付

本轮二次开发由两部分组成：`f73b5a1b` 完成网络服务端、TLS、Reactor、测试目标和基础测试模块；`5fd881a` 在此基础上补充连接请求处理中间态，并修复协商请求排队时的顺序问题。

### feature

- 接入基于 OpenSSL 的非阻塞 TLS 服务端传输，服务端默认要求加密连接。
- 完成 TLS 配置装载、证书和私钥校验，以及 TLS 连接在 Reactor 中的握手、读写和关闭接入。
- 建立有界的 Reactor 通用任务、控制任务和完成回投队列，并用唤醒事件驱动跨线程任务处理。
- 完成连接注册、轮询事件动态刷新、连接代际和一次性槽位释放等生命周期基础设施。
- 增加连接请求处理的三态模型，将空闲、正在处理和断开从协议协商及传输生命周期中分离出来。
- 允许客户端在 HELLO（协议协商命令）完成前连续发送 AUTH（身份认证命令）及后续请求，并由单连接流水线暂存。
- 保证同一连接最多只有一个业务请求进入执行层，其余请求按照接收顺序等待。
- 保留已派发请求的响应路径，支持前序请求完成后继续派发后续请求。
- 增加网络正确性测试、连接流水线压力测试和 Linux 回环服务集成测试目标。

### fix

- 将服务停止语义统一为立即停止，移除服务端排空状态和停服排空超时，避免停止期间继续接收或等待新任务。
- 修复 TLS 的 WANT_READ/WANT_WRITE 交叉等待，避免非阻塞握手、读取和写入在错误的轮询方向上停滞。
- 修复 Reactor 轮询器重复注册、连接关闭后槽位重复释放以及完成队列溢出后连接悬挂的问题。
- 修复 AUTH 在 HELLO 完成回调到达前被提前拒绝的问题。
- 修复后续协议错误清理在途请求和等待队列，导致 HELLO 响应丢失的问题。
- 修复排队请求读取过早的会话信息，避免认证完成后后续请求继续使用旧主体。
- 修复对端半关闭时提前丢弃已接收请求的问题。

### improvement

- 解析器接管完整帧字段所有权，减少帧字段复制；传输写接口使用字节视图，避免额外构造发送缓冲。
- 存储执行器在请求移动到工作队列前保存连接标识和请求标识，队列满时仍能返回可关联的 BUSY 响应。
- 将会话阶段校验延后到请求即将派发时执行，使校验依据与实际会话结果保持一致。
- 将协议错误延后到同一连接中更早的请求处理完成后再生成错误响应。
- 使用有界流水线和读取暂停机制维持单连接内存上限，并保持请求与响应顺序。

## 3. 验证结果

- 网络连接压测通过：100000 个请求，输入 2400000 字节，输出 4000000 字节，耗时 0.446487 秒，报告吞吐为 223971 请求/秒。
- 网络正确性测试全部通过。
- 正确性测试覆盖帧编解码、命令字段校验、会话权限、连接顺序、错误收尾、半关闭排空、Linux 回环服务启动策略和跨线程唤醒。
- [二轮测试文档](../../test/period2/README.md)保留测试范围、测试思路和测试报告的独立记录。
- 本轮不改变存储层 CRUD（增删改查）业务映射；网络命令执行器对存储层的既有接入能力仍以当前实现为准。
