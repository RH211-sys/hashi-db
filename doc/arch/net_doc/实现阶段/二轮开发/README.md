## 1. 本轮交付

### feature

- 增加连接请求处理的三态模型，将空闲、正在处理和断开从协议协商及传输生命周期中分离出来。
- 允许客户端在 HELLO（协议协商命令）完成前连续发送 AUTH（身份认证命令）及后续请求，并由单连接流水线暂存。
- 保证同一连接最多只有一个业务请求进入执行层，其余请求按照接收顺序等待。
- 保留已派发请求的响应路径，支持前序请求完成后继续派发后续请求。

### fix

- 修复 AUTH 在 HELLO 完成回调到达前被提前拒绝的问题。
- 修复后续协议错误清理在途请求和等待队列，导致 HELLO 响应丢失的问题。
- 修复排队请求读取过早的会话信息，避免认证完成后后续请求继续使用旧主体。
- 修复对端半关闭时提前丢弃已接收请求的问题。

### improvement

- 将会话阶段校验延后到请求即将派发时执行，使校验依据与实际会话结果保持一致。
- 将协议错误延后到同一连接中更早的请求处理完成后再生成错误响应。
- 使用有界流水线和读取暂停机制维持单连接内存上限，并保持请求与响应顺序。

## 3. 验证结果

- 网络连接压测通过：100000 个请求，输入 2400000 字节，输出 4000000 字节，耗时 0.446487 秒，报告吞吐为 223971 请求/秒。
- 网络正确性测试全部通过。
- 本轮不改变存储层 CRUD（增删改查）业务映射；网络命令执行器对存储层的既有接入能力仍以当前实现为准。
