## 1. 服务创建与启动

- **思想逻辑链：** 上层创建网络服务控制入口并提供配置 → 绑定命令执行器 → 创建并启动 Reactor 组 → 创建监听器 → 服务进入运行状态。
- **代码逻辑链：** `project/net_level/controller/controller.cpp` 的 `Controller::bindStorageController` 绑定阶段存储执行器 → `Controller::start` 创建 `NetworkServer` → `project/net_level/server/network_server.cpp` 的 `NetworkServer::start` 检查启动条件 → 按配置创建共享 TLS 上下文 → 启动 `ReactorGroup` → 启动 `Acceptor` → 设置运行状态。

## 2. 连接接入与 Reactor 分配

- **思想逻辑链：** 监听端点发现新 TCP 连接 → 接收端取得 socket 和客户端地址并预留连接容量 → 按服务配置决定是否套上 TLS → 分配连接标识 → 轮询选择一个 Reactor → 在该 Reactor 线程创建并独占管理连接。
- **代码逻辑链：** `project/net_level/server/acceptor.cpp` 的 `Acceptor::start` 启动监听线程并执行 `accept` → 创建 `TcpTransport`、整理对端地址并预留客户端槽位 → `project/net_level/server/network_server.cpp` 的接入回调按配置创建 `TlsTransport` → `ReactorGroup::dispatch` 通过轮询位置选择目标 Reactor → `project/net_level/reactor/reactor.cpp` 的 `Reactor::addConnection` 将控制任务放入目标 Reactor → `Reactor::Impl::processInbox` 在事件线程创建 `Connection` 并登记 Poller。

## 3. Reactor 事件循环与跨线程唤醒

- **思想逻辑链：** Reactor 等待连接就绪事件或跨线程任务通知 → 先在所属线程处理已入队任务 → 再处理本轮连接事件 → 根据连接当前状态更新监听方向 → 回到等待。
- **代码逻辑链：** `project/net_level/reactor/reactor.cpp` 的 `Reactor::Impl::run` → `processInbox` 取出控制、通用和完成任务并在事件线程串行执行 → `EpollPoller::wait` 返回连接事件或唤醒事件 → `handleEvents` 分派到对应 `Connection` → `refreshInterest` 更新 Poller 登记 → 继续下一轮事件循环；跨线程入队后由 `EpollPoller::wakeup` 写入 `eventfd`，打断等待。

## 4. TCP 与 TLS 传输建立

- **思想逻辑链：** 新连接先拥有非阻塞 TCP socket → 若启用 TLS，则创建单连接 TLS 会话并绑定共享服务端上下文 → 握手根据底层可读或可写状态分多轮推进 → 握手成功后连接进入等待协议协商阶段。
- **代码逻辑链：** `project/net_level/transport/tcp_transport.cpp` 的 `TcpTransport` 接管 socket，`handshake` 对普通 TCP 立即返回可用 → 启用 TLS 时，`project/net_level/transport/tls_transport.cpp` 的 `TlsServerContext::create` 装载证书和私钥 → `TlsTransport` 创建 OpenSSL 会话并绑定 socket → `Connection` 构造时调用传输握手 → `WOULD_BLOCK` 时由 `interestEvents` 暴露等待方向、Poller 事件再次调用握手 → 成功后转入 `WAIT_HELLO`。

## 5. 接收字节、解码帧与解析命令

- **思想逻辑链：** 连接可读 → 传输模块取得 TCP 字节或 TLS 明文 → 字节暂存到连接输入缓冲 → 帧编解码器从字节流拼出完整帧 → 命令解析器按命令含义生成结构化请求 → 请求进入该连接的有序队列。
- **代码逻辑链：** `project/net_level/reactor/reactor.cpp` 的 `handleEvents` → `project/net_level/server/connection.cpp` 的 `Connection::onReadable` → `Transport::read`（TCP 由 `recv` 读取，TLS 由 `SSL_read_ex` 解密读取）→ `Connection::processInput` 调用 `project/net_level/protocol/frame_codec.cpp` 的 `FrameCodec::feed` → 完整帧交给 `Connection::handleFrame` → `project/net_level/command/command_parser.cpp` 的 `CommandParser::parse` → 形成携带连接标识、请求标识、命令码、字段和对端地址的 `CommandRequest` → 放入 `pipeline`。

## 6. 单连接顺序与会话阶段

- **思想逻辑链：** 请求按接收顺序排队 → 只取队首请求检查当前会话阶段 → 允许时标记为正在处理并提交执行器 → 后续请求留在队列 → 前序结果返回后更新会话，再按更新后的状态处理下一项。
- **代码逻辑链：** `Connection::processInput` 将完整请求放入 `pipeline` 并在已有请求进入执行时停止继续派发 → `Connection::dispatchNext` 只取队首、设置在途请求标识并把活动状态改为 `PROCESSING` → `project/net_level/server/session.cpp` 的 `Session::canExecute` 检查协商和认证阶段 → `Connection::complete` 只在 HELLO 成功时提交协商结果、只在 AUTH 成功时保存认证主体 → 清除当前在途状态并继续处理缓冲输入和队首请求。

连接生命周期阶段和请求处理状态分别记录：`ConnectionState` 表示 TCP/TLS、协议阶段及关闭进度；`ConnectionActivityState` 表示请求为空闲、正在处理或已断开。这样 HELLO/AUTH 的协议阶段变化不会代替请求队列的忙闲状态。

## 7. 命令执行与存储桥接

- **思想逻辑链：** 网络层把结构化请求交给执行器契约 → 执行器按命令选择立即响应、返回当前不支持状态或提交存储任务 → 工作线程等待存储结果 → 存储结果转换为网络层状态和响应。
- **代码逻辑链：** `project/net_level/command/command_executor.h` 的 `ICommandExecutor` 定义请求和完成回调边界 → `project/net_level/command/command_executor.cpp` 的 `StorageControllerExecutor::execute` 直接处理 PING、QUIT 和未注册值类型的 CRUD 请求 → 其余请求进入 `WorkerPool` → 工作线程调用存储 `Controller` 并等待 future → `mapStorageCode` 将存储结果转换为 `ErrorCode` → 构造 `CommandResponse` 并调用完成回调。

当前具体分支为：PING 返回成功状态；QUIT 返回成功并要求响应写完后关闭；GET、ADD、UPDATE 返回 `TYPE_NOT_REGISTERED`，不提交存储任务；DELETE_DATA、PERSIST、FLUSH、REWRITE 进入存储桥接；其余已解析命令由桥接器返回 `UNSUPPORTED`。存储等待发生在执行器工作线程，不发生在 Reactor 事件线程。

## 8. 业务完成回投

- **思想逻辑链：** 执行器完成请求并生成带关联标识的结果 → 连接提供的完成回调把结果送回原连接所属 Reactor → Reactor 被唤醒 → 在线程内确认连接仍存在且仍是同一代连接 → 将结果交给连接处理。
- **代码逻辑链：** `Connection::dispatchNext` 向执行器传入完成回调 → `project/net_level/reactor/reactor.cpp` 的 `Reactor::addConnection` 为该连接创建捕获 Reactor 弱引用、`ConnectionId` 和连接代际的完成投递器 → 投递器将结果放入目标 Reactor 的完成队列并唤醒 Poller → `Reactor::Impl::processInbox` 执行回投任务 → 校验连接表和代际 → 调用 `Connection::complete`。

目标 Reactor 在连接接入时已经确定，完成回投沿该连接保存的投递器返回，不遍历 Reactor 组，也不通过客户端 IP 重新查找。

## 9. 响应生成与发送

- **思想逻辑链：** 连接收到业务完成结果 → 核对其对应当前在途请求 → 按结果更新会话并构造响应帧 → 编码后进入输出队列 → Poller 等待可写 → 传输模块分段发送 → 响应写完后继续推进同连接队列。
- **代码逻辑链：** `Connection::complete` 核对 `ConnectionId` 和 `RequestId` → 设置响应命令码、响应标志、状态字段和可选消息字段 → `FrameCodec::encode` 编码 → `outputQueue` 保存响应和发送偏移 → `Connection::interestEvents` 请求可写事件 → `Connection::onWritable` 按写入预算推进偏移 → `TcpTransport::write` 或 `TlsTransport::write` 发送 → 当前响应发送完成后继续解析和派发后续请求。

同一连接最多只有一个业务请求在途，且响应队列按完成顺序依次写出，因此后续请求要等前序结果完成后才会派发，响应也保持该连接的请求顺序。

## 10. 协议错误与会话拒绝

- **思想逻辑链：** 无法从字节流恢复帧边界时关闭连接 → 完整帧中的命令字段不符合规则时暂存错误并暂停继续读取 → 先完成更早的请求 → 再按序返回错误响应并关闭；会话阶段不允许的请求则单独返回阶段错误，不提交业务执行器。
- **代码逻辑链：** `FrameCodec::feed` 返回非法帧或超大帧 → `Connection::processInput` 关闭连接；若完整帧到达 `CommandParser::parse` 后字段规则失败 → `Connection::handleFrame` 保存 `PendingProtocolError` 并暂停读取 → `Connection::dispatchNext` 等待前序 `pipeline` 请求处理完后调用 `queueProtocolError` → 错误响应排入输出队列并在写完后关闭。会话阶段拒绝发生在 `dispatchNext` 的 `Session::canExecute` 检查处，直接构造关联响应，不调用执行器。

HELLO 成功前的 AUTH 会留在请求顺序中等待 HELLO 完成；HELLO 失败后，AUTH 出队时因会话仍未协商而被阶段检查拒绝，不提交执行器。字段解析错误也不会清除更早的在途请求或提前丢弃它的完成结果。

## 11. 容量控制、背压与处理公平性

- **思想逻辑链：** 服务为连接数、单连接请求和缓冲数据设上限 → 达到单连接接收上限时暂停继续读取，让请求处理推进后再恢复 → 每轮读写和 Poller 事件数量受预算限制 → 工作或回投队列无法接收任务时返回忙状态或关闭无法完成的连接。
- **代码逻辑链：** `Acceptor` 在达到 `maxClients` 时拒绝新 socket → `Connection::processInput` 受 `maxPipelineRequests` 限制 → `Connection::onReadable` 和 `onWritable` 分别受读写预算及输入、输出缓冲上限约束 → `Connection::interestEvents` 在暂停期间移除读关注 → `Reactor::Impl::run` 每轮最多取固定批次 Poller 事件 → `WorkerPool::submit` 队列满时返回 BUSY → Reactor 完成队列溢出时记录并关闭对应连接。

这些预算限制单个连接一次占用的网络读写量，但不构成绝对的 CPU 公平调度：同一 Reactor 仍串行处理其连接；`processInbox` 会依次执行取出的任务，没有单个任务的执行时间预算。耗时存储操作由当前存储桥接器放到工作线程执行，避免正常存储等待阻塞 Reactor。

## 12. 连接关闭与服务停止

- **思想逻辑链：** 收到 QUIT 时停止接收和派发后续请求并先发送其响应 → 对端半关闭时处理已接收请求并排空响应 → 传输错误或不可恢复协议错误立即清理连接 → 服务停止时先停止接入，再唤醒并停止所有 Reactor，关闭其连接和剩余任务。
- **代码逻辑链：** QUIT 的 `CommandResponse` 设置写后关闭 → `Connection::complete` 清理等待请求并进入关闭状态 → `onWritable` 写完输出后调用 `Connection::close`；对端半关闭经 `onPeerHalfClose` 停止读取、继续处理已缓存输入和输出，排空后关闭；传输失败由连接关闭路径释放 socket 和客户端槽位。服务停止由 `NetworkServer::stop` 先调用 `Acceptor::stop`，再调用 `ReactorGroup::stop` → `Reactor::stop` 唤醒并 join 事件线程 → `Reactor::Impl::run` 关闭全部连接并丢弃未执行任务。

当前停服语义是立即关闭，不等待业务队列或连接响应排空。

## 13. 当前实现范围与注意事项

- `StorageControllerExecutor` 尚未实现 HELLO 和 AUTH 的成功业务逻辑。`Connection` 已包含“执行器成功后提交协商或认证状态”的路径，但当前阶段桥接器会把 HELLO、AUTH 送入工作队列后按未实现命令返回 `UNSUPPORTED`；只有注入能够成功处理它们的执行器，连接会话才会进入对应后续阶段。
- GET、ADD、UPDATE 的网络字段虽然可解析，但当前值类型编解码未接入存储接口，执行器返回 `TYPE_NOT_REGISTERED`。DELETE_DATA、PERSIST、FLUSH、REWRITE 是当前桥接器实际调用存储接口的命令；STATS、CLIENT_LIST、CLIENT_KILL 等命令尚未由该桥接器实现。
- PING 当前返回成功状态，不访问存储；虽然解析器接受可选 PAYLOAD，当前执行器没有把该字段复制到响应中。
- `ICommandExecutor` 的注释约定完成回调调用一次；当前工作任务中的异常捕获范围包含一个提前调用完成回调的分支。如果该回调本身抛异常，异常可能进入同一 catch 并触发第二次回调。这是当前实现的风险，不属于预期的正常完成链。
- `ConnectionRegistry` 目前未接入上述请求处理主链，本文不把它描述为正在运行的连接查询或管理路径。
