## 1. 总体结论

在当前 C++20/Linux 单机项目中增加 TCP 网络层是可行的。工程难点不只是监听和收发，而是确保连接状态由单一线程拥有、存储延迟不会阻塞 I/O、客户端协议不依赖磁盘格式，并为所有排队和缓冲确定资源上限。

本方案以现有存储线程模型为前提，不通过网络层重新划分缓存或磁盘任务。文中所述是目标实现思路和成立条件，不代表已经实现或已经通过测试。

## 2. 连接接入与事件循环

采用独立接入者监听 TCP 端口，并由多个事件循环管理已经接入的连接。连接分配完成后固定归属于一个事件循环；该循环独占该连接的读写、状态更新和事件订阅修改。跨线程控制操作只发送消息给连接所属循环，不直接触碰连接对象或套接字。

该模型比每连接一个线程更节省常驻线程资源，也比单一事件循环更容易利用多个 I/O 核。稳定连接标识和连接代际用于区分已关闭连接与后续可能复用的操作系统文件描述符。

事件循环采用有界任务队列和单轮读写预算。预算耗尽后在后续轮次继续推进，以避免一个高流量连接长时间占用执行机会。LT（水平触发）事件方式在描述就绪状态时更直观，适合首轮建立正确性；是否改用 ET（边缘触发）应以测量结果和专项测试为依据。

连接固定事件循环归属不意味着数据按网络线程分片。myDB 的共享缓存、写线程和磁盘线程已有各自的并发及资源归属；首轮网络设计不改变这些存储所有权。

### 术语说明

- LT（水平触发）：资源处于可读或可写状态时，事件轮询器会持续报告就绪状态，直到状态改变。
- ET（边缘触发）：只在就绪状态发生变化时报告事件，应用必须主动处理完当前可处理数据。
- eventfd：Linux 提供的事件计数文件描述符，可用于唤醒正在等待 I/O 的事件循环。
- 文件描述符：操作系统用于标识打开文件或套接字的整数；关闭后可能被新对象复用。
- ConnectionId：网络服务进程内分配给一个客户端连接的稳定标识，不等同于文件描述符。
- owner Reactor：从连接加入开始，唯一拥有该连接 I/O 和可变状态的事件循环。
- ReactorGroup：负责组织多个事件循环并为新连接选择所属循环的管理模块。
- Poller：等待套接字等 I/O 资源就绪并提供事件结果的轮询抽象。
- Transport：统一描述非阻塞握手、读写和关闭的传输模块。

## 3. 协议解析与命令执行

TCP 只提供字节流，不提供应用帧边界。采用长度明确的基础头和字段序列，解析器可保存尚未收全的帧，并允许调用方继续处理同一输入中的多帧。长度应先检查再申请大块内存，通用帧校验与命令字段规则分开，使协议错误在进入业务前被识别。

选择自定义的二进制请求/响应格式，是为了容纳版本、请求关联标识和业务类型编码；它不声明兼容 RESP。RESP 即 Redis 序列化协议，可以借鉴其长度前缀和二进制安全经验，但命令和数据含义不同。若未来需要兼容 Redis 客户端，应使用独立转换入口，而不是混淆核心协议。

网络帧解析层只负责字节、帧头和字段结构；命令解析层校验某条命令允许的字段；命令执行层负责业务规则和存储映射。不同层各自处理自己的错误，不把业务语义放入字节解析过程。

网络协议 v1 固定基础头为 24 字节，字段包括协议标记、版本、标志、命令编号、头长度、消息体长度、请求关联标识和保留位，整数以大端顺序传输。消息体用 TLV 表示字段。v1 命令定义覆盖协议协商、认证、探活、退出、数据增删改查、持久化、刷盘、重写、统计与连接管理。字段编号、类型、各命令必填字段及用途见[需求文档的协议与命令范围](./需求文档.md#22-协议与命令范围)。这组契约应由单一版本的协议表维护，任何编号和语义变更都需要兼容性评审。

### 术语说明

- 帧：从字节流中按协议边界切出的一个完整消息单位。
- 消息体：帧头之后承载命令字段的部分。
- TLV：由字段编号/类型、长度和值组成的编码结构。
- 请求关联标识：由客户端提供并由响应原样带回、用于匹配请求与结果的编号。
- 大端顺序：多字节整数按最高有效字节在前的顺序传输。
- schema：某条命令允许、要求或禁止的字段规则集合。

## 4. 与存储层异步衔接

若存储入口只返回 future，网络事件循环不能等待其完成。同步等待会让某个存储慢操作阻塞该循环管理的其他连接；反复轮询完成状态则持续消耗事件循环时间，且增加额外调度状态。

首选做法是让命令/存储边界提供异步完成回调，同时保留旧 future 接口供已有调用者兼容。若前置接口改造暂时不能完成，可设置固定数量的过渡等待线程和有界任务队列：工作线程负责等待 future，完成后把结果交回连接所属事件循环；入队失败时返回明确过载结果。禁止每个请求新建等待线程、禁止无限等待队列、禁止在事件循环内调用 future 等待操作。

业务类型需要独立的网络编解码规则，明确类型名称、网络版本和字节表示。注册缺失或不能往返还原的数据类型应明确拒绝。磁盘序列化是存储内部实现细节，不是稳定的跨语言网络格式。

## 5. 安全、资源和停机

生产配置默认要求加密传输。安全传输初始化失败或证书不可用时服务启动失败；明文只允许由显式的开发/测试选项开启，非回环明文额外需要远程许可。认证提供者和访问控制规则必须由独立的安全/管理边界提供，不能仅因网络协议存在认证命令就声称认证已完成。

资源治理分层执行：先限制连接数量，再校验帧大小；连接输入、待执行请求和输出分别受限；业务执行入口限制全局在途数量；事件循环的普通任务、控制任务和完成结果队列分别有容量上限。达到容量后按契约拒绝、暂停读取、恢复读取或关闭连接，避免无界扩展。

服务停止采取立即停止网络的目标方案，不等待排空：先关闭监听入口，再关闭客户端连接并丢弃尚未派发的请求。已经提交给执行层的业务继续运行，但网络层不再向已关闭连接返回响应。请求派发前若服务端已观察到 TCP 连接关闭或重置，则丢弃该请求；响应发送前若已观察到关闭，则丢弃待发响应。TCP 是传输控制协议，提供可靠有序字节流；服务端不能直接探知远端进程实时状态，只能依据本地已观察到的读写或关闭状态，且远端仍可能在检查后断开。异步结果关联稳定连接标识及代际，避免服务关闭后访问已释放的连接状态。

### 术语说明

- TLS：传输层安全协议，用加密传输和端点身份验证保护网络连接。
- ACL：访问控制列表，描述已认证主体可以执行的操作。
- future：表示某个异步操作未来产生结果的 C++ 对象；仅持有 future 不会让事件循环自动得到完成通知。
- wire codec：定义业务值如何在网络字节与程序数据之间相互转换的规则。
- admission：执行层接收新请求前的容量准入判断。
- backpressure：容量不足时通过拒绝、暂停读取或关闭慢连接控制上游输入的机制。
- PERSIST：请求持久化数据的维护命令；FLUSH 是请求清理并刷盘的维护命令；REWRITE 是请求整理持久化文件的维护命令。
- CLIENT_LIST：查询连接快照的管理命令；CLIENT_KILL：按连接标识请求立即关闭连接的管理命令；STATS：查询运行统计的管理命令。

## 6. 管理接口可行性

术语说明：审计是为事后追责和排查保存的受控管理操作记录，不等同于调试日志；CLIENT_LIST 是查询连接快照的命令，CLIENT_KILL 是按连接标识请求立即关闭连接的命令，STATS 是查询运行统计的命令。

管理操作可以通过本地管理入口和受限远程命令两类路径实现。二者进入统一的管理动作校验和业务执行边界，但认证方式不同：本地身份来自可信宿主调用上下文，远程身份必须先经身份提供者验证，再按 ACL（访问控制列表，根据主体和动作判断权限）对每条命令单独授权。这样可复用连接快照、立即关闭请求、指标和维护操作的业务能力，同时避免通过网络帧伪造本地管理员身份。本轮只设计脱敏配置查询，不设计在线配置修改、凭据管理或角色管理命令。

连接查询可在连接所属事件循环上收集有限快照，再合并为有界结果；不承诺跨事件循环的严格同时刻一致性。关闭连接必须通过连接稳定标识和代际定位，并把关闭请求投递给连接所属 Reactor。网络事件循环不直接持有或修改其他 Reactor 的连接状态。

高成本维护操作使用异步命令执行边界并受容量准入限制；网络管理请求返回关联标识和稳定错误类别。身份/策略不可用时默认拒绝远程管理命令。审计至少覆盖主体、动作、目标、时间与结果，秘密和数据值不得入审计记录。凭据管理、审计存储和角色生命周期依赖尚需明确的安全/管理提供者，因此管理协议和接口可先定约束、后分阶段接入，不能把定义命令编号当作安全功能已经可用。

具体入口、能力矩阵、响应、审计与资源约束见[管理接口设计](./管理接口设计.md)。

## 7. 风险及缓解方式

| 风险 | 可能影响 | 可行性措施 |
|---|---|---|
| 存储等待阻塞事件循环 | 多个连接同时出现延迟 | 使用完成回调；过渡阶段用固定线程和有界队列等待 |
| 完成结果晚到或文件描述符复用 | 错误连接收到响应或访问已释放对象 | 使用稳定连接标识、代际校验及所属循环投递 |
| 慢客户端不读响应 | 输出缓冲持续增长 | 设置输出水位和硬上限，必要时暂停读取或关闭连接 |
| 非法长度或畸形字段 | 超额分配或解析状态破坏 | 先做边界校验，为非法帧定义确定的关闭或错误处理 |
| 网络类型未注册 | 值无法可靠还原 | 类型和版本显式注册，未注册时拒绝，不暴露磁盘格式 |
| TLS 配置或降级错误 | 明文暴露或凭据泄漏 | TLS 默认强制；明文需显式开发开关和远程许可 |
| 任务队列耗尽 | 完成结果滞留，连接无法推进 | 队列按用途限额；无法回投完成结果时关闭对应连接 |
| 热点连接独占事件循环 | 其他连接响应变慢 | 设置读、写、事件和解析预算，并观测事件循环延迟 |
| 存储层成为吞吐瓶颈 | 增加网络线程没有端到端收益 | 分别测缓存命中、磁盘未命中和维护操作，不推断网络单层吞吐 |

## 8. 实施次序与阶段条件

1. **稳定跨层契约**：约定结构化请求、异步完成、类型编码和错误映射；确认不破坏现有存储行为。
2. **协议核心**：实现帧编解码和命令字段规则；验证拆包、粘包、非法输入和长度边界。
3. **单循环连接闭环**：实现 TCP 连接状态和异步执行交接；验证读写部分完成、连接关闭及同连接顺序。
4. **多个事件循环与资源控制**：实现连接分配、有界跨线程队列、公平预算和容量压力测试。
5. **安全与管理能力**：实现加密传输、认证/授权、连接查询/关闭和优雅停机，并注入失败场景。
6. **性能测量与调优**：按连接数、数据大小、加密状态和存储命中情况记录吞吐、尾延迟、CPU、内存及错误率。

阶段完成以代码和测试证据为准。服务停止按立即关闭实现，不做排空：停止新网络接入和 I/O，丢弃尚未派发的请求；已提交执行层的业务继续运行，但连接关闭后不返回结果。若派发前或响应发送前已观察到客户端 TCP 连接关闭/重置，则分别丢弃该请求或响应。服务端无法绝对判断远程客户端进程是否存活，检查只能依据最近已观察到的 TCP 状态；客户端可能在检查后断开。配置建议和可行性分析不构成性能承诺；未实际测量的目标不得写作测试结果。
