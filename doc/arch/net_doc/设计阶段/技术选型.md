## 1. 选型原则

技术选择服务于当前单机存储服务，不以追求抽象层数量或远期连接数作为起点。首要条件是连接所有权清楚、资源可设上限、协议可演进，且不会要求重写存储层并发模型。

跨平台公共接口尽量只暴露端点、连接标识、字节和事件概念；Linux 网络实现留在平台目标内。第三方网络库或新依赖只有在明显降低风险且与现有构建和生命周期匹配时才引入。

## 2. 平台与 I/O 模型

| 技术/模块 | 功能 | 解决的需求与采纳原因 | 未选方案或边界 |
|---|---|---|---|
| Linux 非阻塞 TCP 套接字 | 建立监听和客户端连接，以非阻塞方式收发有序字节流 | 满足首发 Linux 服务端需求；平台 API 直接，便于与 epoll 组合 | 当前不承诺 Windows 服务端；避免线程阻塞于单连接 I/O |
| Acceptor 接入模块 | 监听配置端点、接受新客户端、设置必要套接字选项并将连接交给事件循环组 | 将连接接入与已建立连接的 I/O 分离，限制接入职责范围 | 首版为单一接入者；多监听者只有在实测接入瓶颈后再评估 |
| epoll 水平触发模式 | 等待多个连接的读写就绪事件 | 满足连接并发处理需求；水平触发在单轮预算耗尽后仍会报告就绪状态，首轮更易建立正确性 | 首轮不选边缘触发模式，以避免应用漏读后永久失去事件通知；仅在性能证据和专项测试具备后重评 |
| eventfd | 向阻塞等待中的事件循环发出可读唤醒信号 | 让跨线程任务投递能及时唤醒事件循环，不必周期性短轮询 | 只作为唤醒通知，不用于传递任务内容，也不替代有界队列 |
| 多 Reactor 与连接固定归属 | 每个事件循环管理自己的连接集合，每连接只由一个事件循环修改状态 | 以固定数量线程服务多个连接，减少连接状态共享锁并可利用多个 I/O 核 | 不选每连接一个线程；连接归属不是存储数据分片，不能据此重写现有存储线程模型 |
| 有界任务队列及 I/O 预算 | 限制跨线程投递量、事件批次和每连接读写工作量 | 满足资源硬上限与公平性要求，避免热点连接长期占用事件循环 | 具体数值待测试校准；不同控制任务和完成结果须有明确的队列满行为 |
| Poller 轮询抽象 | 将事件等待、注册、修改、移除与核心连接逻辑隔离 | 支持 Linux epoll 实现及独立替身测试，限制平台 API 外溢 | 抽象不代表已有 Windows 实现；Windows 需另行评估 IOCP 等机制 |
| Transport 传输抽象 | 为连接提供非阻塞握手、读取、写入和关闭能力 | 将套接字细节与连接状态机分开，为后续 TLS 传输留边界 | Transport 是接口边界，不意味着当前已具备 TLS 实现 |

术语：Reactor 指拥有一组连接并运行事件循环的线程及其状态；ReactorGroup 管理多个 Reactor 并分配新连接；LT 为水平触发，资源持续就绪时反复报告事件；ET 为边缘触发，主要在就绪状态改变时通知；Poller 等待 I/O（输入/输出）事件；Transport 统一传输操作；eventfd 是 Linux 事件计数文件描述符。

## 3. 网络协议与编码

| 技术/模块 | 功能 | 解决的需求与采纳原因 | 未选方案或边界 |
|---|---|---|---|
| MYDB 自定义二进制长度前缀协议 | 描述完整消息帧、协议版本、命令、请求关联标识及字段 | 满足客户端/服务端双向传输、二进制安全和协议演进要求；长度前缀使接收端能先校验边界 | 借鉴 RESP（Redis 序列化协议）的长度和二进制安全经验，不承诺 Redis 命令或客户端兼容 |
| 固定 24 字节基础帧头 | 标记协议、版本、方向/错误标志、命令编号、头/体长度、请求关联标识和保留位 | 接收端可在分配完整消息体前验证版本、标志、保留位和长度；字段定义稳定 | 不直接发送 C++ 结构体内存，不随主机 ABI 改变格式 |
| TLV 消息体 | 用字段编号、类型、长度和值表达命令参数与结果 | 支持二进制数据、文本和整数，并为向后兼容的字段扩展留空间 | 未知标志、非零保留位、重复字段及当前不支持的嵌套内容必须按契约拒绝 |
| 大端网络字节序 | 规定所有多字节数值在线上的字节顺序 | 消除不同主机字节序差异，满足跨平台客户端互操作 | 不沿用平台本机数值布局 |
| FrameCodec 帧编解码 | 从 TCP 字节流增量恢复完整帧并将结构化帧编码为字节 | 解决 TCP 拆包、粘包和部分帧问题，并集中落实基础帧边界与类型校验 | 不在此模块决定某命令的业务含义 |
| CommandParser 命令字段解析 | 按每条命令允许的字段、类型、必填项、重复项和长度规则生成结构化请求 | 让畸形字段在业务执行之前被拒绝，并使业务规则与字节收发隔离 | 不执行存储调用，不将存储私有错误码直接作为网络协议 |
| 网络类型编解码注册 | 将业务类型名称、协议版本与序列化/反序列化规则显式关联 | 支持完整值的网络往返解码，避免不同程序或版本依赖内部布局 | 不把 cereal 等磁盘持久化字节直接暴露为网络格式；类型未注册时拒绝 |

协议字段和命令细节由[需求文档](./需求文档.md#22-协议与命令范围)集中维护。协议评审负责字段编号、错误类别、长度限制和版本兼容；已发布字段编号不得复用，也不得无版本协商地更改含义。

术语：TCP 是传输控制协议，提供可靠、有序但没有应用消息边界的字节流；帧是协议切分出的完整消息单位；TLV 是类型/编号、长度、值构成的字段表达方式；请求关联标识由客户端提供并由响应带回；schema 是命令可用字段规则；wire codec 是业务类型与网络字节之间的转换规则；FrameCodec 是负责帧边界转换的模块；CommandParser 是负责命令字段检查的模块。

## 4. 连接并发和业务衔接

| 技术/模块 | 功能 | 解决的需求与采纳原因 | 未选方案或边界 |
|---|---|---|---|
| 连接固定 Reactor 归属 | 一个事件循环独占连接 I/O、可变状态、输出队列和事件订阅 | 满足连接状态线程安全要求，减少跨线程锁与状态竞争 | 不允许其他线程直接操作连接或套接字 |
| 稳定连接标识及代际 | 标记连接实例，并让迟到的完成结果可校验目标仍为原连接 | 规避文件描述符复用、连接关闭后回调迟到等问题 | 文件描述符本身不作为跨线程连接身份 |
| 同连接有序、跨连接并行 | 同一连接的命令按接收顺序提交和响应；不同连接可以并行 | 保持客户端可预测的写后读与操作顺序，又利用连接间并发 | 首版不支持同连接业务请求并行完成再重排响应 |
| ICommandExecutor 命令执行边界 | 接收结构化请求并异步返回结构化结果；它是网络层与业务执行层之间的请求交接模块 | 隔离网络协议、业务逻辑和存储层生命周期，防止连接对象被业务线程访问 | 不让网络层直接依赖缓存、磁盘或存储控制器的私有行为 |
| 一次性完成回调与 owner 投递 | 业务完成时通知结果，并由连接所属事件循环继续响应 | 让网络线程在等待业务时继续服务其他连接，且连接状态仍单线程修改 | 禁止事件循环等待 future 或轮询 future |
| 固定有界等待桥接 | 仅在旧存储接口只能提供 future 时，由固定工作线程等待，再向 Reactor 投递结果 | 渐进接入现有存储接口而不阻塞 I/O 线程 | 临时兼容手段；不采用每请求创建线程或无限等待队列，后续应改为原生异步通知 |
| 单元替身与 Linux 端到端测试 | 分别替换 Poller、Transport、时钟和执行器；再测试真实 Linux 套接字 | 单元测试定位状态机和协议错误，集成测试验证操作系统边界 | 模拟测试不替代 Linux epoll、eventfd 和真实客户端测试 |

### 4.1 连接所有权及顺序

连接建立后固定分配给一个 Reactor。该 Reactor 独占连接读写、状态机、输出队列及事件订阅修改。其他线程使用稳定连接标识、连接代际和完成消息投递，不保存可直接操作的文件描述符身份。同连接请求按顺序串行执行，跨连接并行；等待请求必须有容量上限。

### 4.2 异步完成

优先由命令或存储执行边界提供完成通知。完成结果回到连接所属事件循环后再编码响应。若阶段适配只能等待 future（表示未来结果的 C++ 对象），则在固定、有界的过渡工作线程中等待，明确标记为临时方案。业务执行器拥有命令到存储操作的映射、网络类型编解码和业务错误翻译；连接模块不调用存储 Controller。

术语：future 是异步操作的结果句柄，本身不提供事件循环通用完成通知；完成回调是在操作完成后通知调用方的机制；owner Reactor 是连接唯一的 I/O 状态所有者。

## 5. 安全、资源治理与可观测性

| 技术/模块 | 功能 | 解决的需求与采纳原因 | 未选方案或边界 |
|---|---|---|---|
| TLS 传输模块与 OpenSSL | 加密客户端与服务端之间的 TCP 通信并验证通信端点 | 满足生产凭据和数据保密要求；OpenSSL 提供成熟 TLS 基础，Transport 抽象隐藏加密握手和读写状态 | 默认要求加密，配置失败启动错误；不静默降级。当前实现未完成 TLS |
| 认证提供者与 ACL 策略 | 验证用户身份并按主体与操作授予或拒绝权限 | 满足会话认证与命令级授权要求，管理命令需独立权限 | 认证凭据来源和策略存储由安全/管理边界提供；AUTH 语法存在不等于认证实现完成 |
| 分层容量上限与背压 | 限制连接、帧、输入/输出、每连接待处理请求、全局在途和各类任务队列；背压指暂停读取、拒绝请求或关闭连接以控制输入速度 | 满足内存与过载可预测性，避免慢客户端拖垮进程 | 不允许用无界队列换取短期吞吐；队列满须有明确定义的拒绝、暂停或关闭行为 |
| 分桶时间轮 | 为握手、认证、组帧、空闲与停机设置期限 | 有大量连接定时任务时减少逐连接定时器扫描成本 | 作为可选实现方向，须通过延迟和精度需求验证；不代表当前已有时间轮 |
| 分层错误分类和脱敏日志 | 区分协议、权限、执行、存储和依赖错误，记录生命周期而不泄漏秘密 | 便于客户端稳定处理和运维排错，同时满足秘密不落日志要求 | 不直接透传存储内部错误编号、密码、令牌或完整数据值 |
| NetMetrics 线程内计数与低频聚合 | 观测连接数、流量、队列/缓冲、事件循环延迟、请求时延和背压；NetMetrics 是网络运行指标汇总模块 | 满足运行观测要求，并避免热路径全局指标锁 | 指标为观测而非事务真相；延迟直方图等具体实现须评估开销 |
| CMake 网络目标隔离 | 分离协议核心、Linux I/O、存储桥接和聚合入口 | 保证存储测试默认构建不被 Linux 网络实现或额外序列化依赖污染 | 不以网络层改写存储层默认构建和生命周期 |

术语：TLS 是传输层安全协议；OpenSSL 是提供加密与 TLS 能力的开源库；ACL 是基于主体和操作的访问控制列表；背压指过载时限制上游输入；时间轮是将大量定时任务分桶、按时间片推进的调度结构；NetMetrics 是网络层运行指标汇总模块。以上选型描述目标方案，不代表当前实现已完成 TLS、认证/ACL、时间轮、全部背压策略或正式指标聚合。

## 6. 开源项目参考及本土化

1. [Redis 协议规范](https://redis.io/docs/latest/develop/reference/protocol-spec/)说明 RESP 如何用类型和长度前缀表达二进制安全数据。可借鉴其明确边界的经验来检验 MYDB 帧格式；由于业务命令和类型语义不同，不复用其协议作为客户端接口，也不宣称兼容 Redis。
2. [muduo 网络库](https://github.com/chenshuo/muduo)提供 C++ Reactor 事件循环模型参考，其连接事件处理和线程归属有助于理解“一线程一个事件循环”的组织方式。myDB 仅采纳连接固定 owner、跨线程投递的原则，不直接引入整个框架，避免把其对象生命周期和依赖带入存储工程。
3. [Linux epoll 手册](https://man7.org/linux/man-pages/man7/epoll.7.html)定义 epoll 注册事件和 LT/ET 通知语义。采用 LT 是首轮可维护性取舍；ET 只有在正确处理就绪状态及基准验证后才考虑。
4. [Dragonfly 架构说明](https://github.com/dragonflydb/dragonfly/blob/main/docs/df-share-nothing.md)介绍其 I/O 线程和数据库分片线程的组合，可用于讨论线程亲和与消息交接。但其 share-nothing 分片绑定自身的数据分区；myDB 当前有共享缓存及专属写/磁盘线程，故只借鉴连接亲和和清晰线程边界，不照搬按核拆分存储数据。

当前不将 Boost.Asio 或 libevent 作为必需核心运行时：项目首发平台为 Linux，现有需求可由专用 Poller/Transport 模块满足，直接采用框架会增加依赖和生命周期适配成本。若未来出现多平台服务端、更多传输协议或维护成本证据，再基于同一接口重新比较。

## 7. 决策摘要

| 决策 | 首选方案 | 重新评估条件 |
|---|---|---|
| 首发平台 | Linux TCP | 明确需要 Windows 服务端时增加独立 IOCP 设计 |
| 事件通知 | epoll 水平触发模式与 eventfd | 基准证明当前方式成为瓶颈且边缘触发风险测试齐备 |
| 连接并发 | 单接入者与多个 Reactor、连接亲和 | 接入或跨循环调度成为实测瓶颈 |
| 网络协议 | MYDB 自定义二进制字段协议 | 需要兼容第三方协议时建立独立转换适配器 |
| 存储衔接 | 异步完成；短期固定有界工作线程过渡 | 存储原生完成回调稳定后移除等待桥接 |
| 安全 | 默认强制 TLS，禁止隐式降级 | 仅测试环境显式开启明文 |
| 数据分片 | 不在网络层改造 | 存储层完成独立的数据分片与一致性设计后再讨论 |

## 8. 术语说明

- Reactor：独占维护所属连接 I/O（输入/输出）和可变状态的事件循环及其线程。
- Poller：等待套接字等 I/O 资源就绪，并将事件交给事件循环的轮询抽象。
- Transport：屏蔽平台套接字细节，提供传输握手、读取、写入和关闭能力的模块。
- Acceptor：监听服务端口、接受新连接并将连接交给事件循环的模块。
- ConnectionRegistry：按稳定连接标识提供连接快照并投递关闭请求的管理抽象。
- NetworkServer：装配监听模块和事件循环、编排网络服务生命周期的模块。
- eventfd：Linux 事件计数文件描述符，可用于唤醒阻塞等待中的事件循环。
- epoll：Linux 的 I/O 多路复用机制，可报告多个套接字的就绪状态。
- 水平触发：资源持续就绪期间，轮询机制会持续报告就绪状态。
- 边缘触发：轮询机制主要在就绪状态发生变化时报告事件，应用需主动处理现有数据。
- MYDB 网络协议：myDB 自定义的版本化请求/响应格式，不承诺与其他数据库客户端协议兼容。
- RESP：Redis 序列化协议；在本文中仅指开源参考协议。
- TLV：类型、长度和值组成的字段编码方式，用来在一个帧体中表示不同类型的字段。
- 网络类型编解码注册：将稳定类型名称与指定版本的网络编码和解码规则显式关联的机制。
- future：表示异步操作结果的 C++ 标准库对象；它自身不提供事件循环所需的通用完成通知。
- 完成回调：操作结束时被执行、用于把结果交给调用方的函数式通知机制。
- ACL：访问控制列表，用于约束已认证主体可以执行的操作。
- OpenSSL：常用开源加密库，可为网络传输提供 TLS 能力。
- IOCP：Windows 的 I/O 完成端口机制，用于异步 I/O 事件调度。
- Boost.Asio：提供跨平台异步网络和 I/O 能力的 C++ 库。
- libevent：提供事件驱动 I/O 抽象的跨平台 C 库。
