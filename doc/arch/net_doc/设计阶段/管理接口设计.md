# 管理接口设计（后续单独设计）

> 状态：占位文档。本轮只确定边界，不定义管理命令的最终字段、权限矩阵或实现方式。

## 1. 边界

管理接口负责服务启停、配置查看、认证/ACL 管理、连接查询与踢出、指标和维护操作的管理面协议。
它与业务数据协议分开演进，不能因为网络层已经存在 `STATS` 或 `CLIENT_KILL` 就把管理语义散落到普通 CRUD 代码中。

## 2. 已确定原则

1. 本地管理优先直接调用同一 `IRequestHandler`，携带 `source=LOCAL_ADMIN` 和管理员身份，不绕过 Reactor，也不伪造网络 socket。
2. 远程管理必须经过独立的认证、ACL、审计和限频策略；管理权限不能由普通读写权限推导。
3. 管理请求需要独立的 admission 配额或带权调度，避免本地维护任务永久饿死外部业务请求，也避免外部请求阻塞停机控制。
4. 管理操作的副作用、幂等性、审计字段、失败回滚和停机语义在本文件后续版本中明确。
5. 密码、令牌、完整缓存值和证书私钥不得出现在管理响应或日志中。

## 3. 待单独评审的内容

- 本地管理通道：命令行、Unix domain socket 或进程内 API；
- 远程管理通道：复用二进制协议还是独立管理端口；
- 认证方式、角色模型、ACL 表达式和凭据轮换；
- `CLIENT_LIST`、`CLIENT_KILL`、`STATS` 等命令的字段、分页和一致性；
- 审计日志格式、保留期限、脱敏规则和失败限频；
- drain、reload、flush、rewrite 等运维操作的确认与超时。

本文件完成前，网络层只实现已经在《协议设计》中定义的最小管理命令占位和统一 `IRequestHandler` 边界，不扩展管理功能。
