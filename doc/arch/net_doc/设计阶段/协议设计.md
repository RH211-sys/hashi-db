# 网络协议设计

## 1. 选择与边界

协议采用自定义二进制、长度前缀、请求-响应模型。它借鉴 RESP 的二进制安全和流水线经验，但**不宣称 RESP 兼容**。TCP 是可靠字节流，不保留消息边界；帧解码必须支持半包和多帧粘连。

## 2. 固定帧头与字节序

所有多字节整数使用 network byte order（big-endian）。固定头为 24 字节：

```text
offset: 0..3       4       5       6..7    8..9       10..13     14..21      22..23
        magic     version flags   opcode  header_len body_len   request_id  reserved
```

| 字段 | 类型 | 长度 | 说明 |
|---|---|---:|---|
| magic | bytes | 4 | ASCII `MYDB` |
| version | u8 | 1 | 当前为 1 |
| flags | u8 | 1 | request/response/error 标记 |
| opcode | u16 | 2 | 未知值由命令层映射 `UNKNOWN_COMMAND` |
| header_len | u16 | 2 | 首版必须是 24 |
| body_len | u32 | 4 | 不超过配置帧上限减去 header_len |
| request_id | u64 | 8 | 请求响应关联 ID |
| reserved | u16 | 2 | 必须为 0 |

Flag 位 0 为 RESPONSE，位 1 为 ERROR；位 2/3（COMPRESSED/MORE）暂不支持，设置后拒绝。其它未定义位同样拒绝。

## 3. TLV 与 v1 字段

Body 编码为 `field_id:u16 | field_type:u8 | reserved:u8 | field_len:u32 | value`，整数均 big-endian。Field type：BYTES=1、UTF8=2、U64=3、I64=4、BOOL=5、NESTED=6；U64/I64 长 8，BOOL 长 1，NESTED 深度最多 8。UTF8 字段必须是合法 UTF-8。各命令不允许重复字段。

| field_id | 名称 | 类型 / 限制 | 用途 |
|---:|---|---|---|
| 1 | protocol_version | BYTES，2 字节 big-endian | HELLO 必填 |
| 2 | feature_bits | U64 | HELLO 可选 |
| 3 | client_name | UTF8 | HELLO 可选 |
| 4 | username | UTF8 | AUTH |
| 5 | password | BYTES | AUTH |
| 6 | payload | BYTES | PING 可选 |
| 7 | key | BYTES，最多 32 字节 | GET/ADD/UPDATE/DELETE/PERSIST |
| 8 | type_name | UTF8，最多 32 字节 | ADD/UPDATE，GET response |
| 9 | value | BYTES | ADD/UPDATE，GET response |
| 10 | ttl | U64 秒 | ADD 可选，GET response |
| 11 | scope | UTF8 | STATS 可选 |
| 12 | connection_id | U64 | CLIENT_KILL |
| 13 | status_code | U64 | 每个 response 必填 |
| 14 | message | UTF8 | response 可选 |

该 field_id 表是实现期确定的 v1 wire contract，不得在发布后复用；代码源为 `project/net_level/command/protocol_fields.h`。

## 4. 命令与会话

首版 opcode：HELLO/AUTH/PING/QUIT、GET/ADD/UPDATE/DELETE、PERSIST/FLUSH/REWRITE/STATS、CLIENT_LIST/CLIENT_KILL。`CommandParser` 检查 opcode 的字段集合、必填项、类型、长度、UTF-8、重复项和 HELLO 版本。FrameCodec 只处理通用帧/TLV，不实施业务路由。

连接建立后客户端先发送 HELLO，再认证；认证 provider 尚未接入，因此当前网络连接会拒绝未认证业务命令，AUTH 也未能形成可用认证闭环。PING/QUIT 是前认证阶段允许的操作。不得把明文密码用于非可信网络。

## 5. 响应与错误

响应设置 RESPONSE，错误响应另设置 ERROR。响应 body 包含 status_code (U64)、可选 message (UTF8) 与业务结果字段。网络错误码独立于存储内部错误值：协议/会话类 1xx，命令/权限类 4xx，服务/依赖类 5xx；`TYPE_NOT_REGISTERED` 表示未显式注册 wire codec。

## 6. 分帧与执行顺序

一次 socket read 可能包含多个帧。增量解码器每次只消费一个完整帧，调用方必须保留并继续处理未消费后缀，直到读缓冲耗尽或 pipeline 达上限。单连接业务请求串行执行，异步完成必须回投 owner Reactor，响应按接收顺序输出。Pipeline、输入缓存、帧体和输出都需要显式上限。

## 7. 当前实现状态与限制

当前目标平台为 Linux，采用非阻塞 plain TCP、LT epoll 与 eventfd 唤醒。TLS 尚未实现，`ServerConfig` 默认拒绝启动；仅显式开启开发明文许可可运行，非回环地址另需显式允许远程明文。连接认证/ACL provider、超时和全局在途背压尚未完成；CLIENT_LIST/KILL 仅有协议定义/schema，没有管理执行实现。存储适配器如提供，必须由独立有界 worker 等待存储 future，不得阻塞 Reactor。
