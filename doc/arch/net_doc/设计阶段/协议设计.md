# 网络协议设计

## 1. 选择与边界

协议采用自定义二进制、长度前缀、请求-响应模型。它借鉴 RESP 的二进制安全和流水线经验，但**不宣称 RESP 兼容**。
原因是当前值类型由服务端 C++ 注册表决定，网络协议还必须携带请求 ID、类型名、wire codec 版本和稳定错误码。

TCP 是可靠字节流，不保留消息边界。FrameCodec 必须支持：半个头、半个 body、多个 frame 一次读、非法长度、
未知版本、连接半关闭和 TLS 加解密后的同样场景。

## 2. 字节序与整数

- 所有多字节整数使用 network byte order（big-endian）；
- `u16/u32/u64` 只表示线上的无符号字段，解析后检查转换和加法溢出；
- body 内的字符串不是 C 字符串，允许任意字节；文本字段约定 UTF-8，但协议只按字节校验长度；
- 协议版本和特性位未知时按兼容规则忽略或返回 `UNSUPPORTED`，禁止静默改变语义。

## 3. 基础帧

基础头固定 24 字节，之后紧跟 `header_len - 24` 字节扩展头和 `body_len` 字节 body：

```text
offset:  0..3       4       5       6..7       8..9       10..13       14..21       22..23
        magic     version  flags   opcode   header_len   body_len     request_id    reserved
```

为避免图示位置歧义，实际字段按顺序定义如下：

| 字段 | 类型 | 大小 | 说明 |
|---|---|---:|---|
| magic | bytes | 4 | ASCII `MYDB` |
| version | u8 | 1 | 当前 `1` |
| flags | u8 | 1 | request/response/error、压缩、特性位 |
| opcode | u16 | 2 | 命令码，未知码返回 `UNKNOWN_COMMAND` |
| header_len | u16 | 2 | `24..256`，基础头为 24 |
| body_len | u32 | 4 | `0..max_frame_bytes - header_len` |
| request_id | u64 | 8 | 客户端生成；响应原样返回 |
| reserved | u16 | 2 | 必须为 0，未来扩展 |

固定头合计 24B。`header_len` 当前必须为 24；保留扩展字段是为了将来加入 trace/route，而不是首版偷偷解析未知头。

### 3.1 flags

| 位 | 名称 | 请求 | 响应 |
|---:|---|---|---|
| 0 | `RESPONSE` | 0 | 1 |
| 1 | `ERROR` | 0 | 1 |
| 2 | `COMPRESSED` | 保留 | 保留 |
| 3 | `MORE` | 保留 | 保留 |
| 4..7 | feature bits | 按协商 | 按协商 |

压缩首版关闭；收到设置但未协商的保留位返回 `UNSUPPORTED`，防止双方误解 body。

## 4. Body 编码

Body 使用 TLV，字段按 opcode 定义，长度均为 u32 big-endian：

```text
field_id:u16 | field_type:u8 | reserved:u8 | field_len:u32 | field_bytes[field_len]
```

首版允许的 field type：`BYTES=1`、`UTF8=2`、`U64=3`、`I64=4`、`BOOL=5`、`NESTED=6`。
解析器拒绝重复必填字段、未知必需字段、长度越界和嵌套深度超过 8。

这样做比空格分隔文本更适合 binary-safe value，也比把 C++ cereal 二进制直接暴露在 wire 上更容易版本化。

## 5. 会话握手

连接建立后客户端必须发送 `HELLO`，再发送 `AUTH`（配置为 anonymous 时可省略 AUTH）：

```text
HELLO request:
  protocol_version:u16 = 1
  client_name:utf8 (optional)
  feature_bits:u64 (optional)

HELLO response:
  protocol_version:u16
  server_name:utf8 = "mydb"
  server_version:utf8
  feature_bits:u64
  connection_id:u64
```

```text
AUTH request:
  username:utf8
  password:bytes

AUTH response:
  principal:utf8
  permission_bits:u32
```

密码默认只允许出现在 TLS 加密传输中；仅在显式开发/测试配置下允许本地回环明文，服务端不回显密码、不记录密码。非回环明文必须额外显式开启，生产配置拒绝该组合。
HELLO/AUTH/PING/QUIT 可在未认证阶段使用，业务命令返回 `NOAUTH`。

## 6. 首版命令集合

opcode 仅作为 wire 稳定编号，命令解析/执行层负责具体映射：

| opcode | 名称 | 权限 | 请求字段 | 成功响应 |
|---:|---|---|---|---|
| `0x0001` | HELLO | public | version, features | negotiated map |
| `0x0002` | AUTH | public | username, password | principal, permissions |
| `0x0003` | PING | public | optional payload | same payload |
| `0x0004` | QUIT | public | none | OK then close |
| `0x0010` | GET | read | key | type, value, ttl |
| `0x0011` | ADD | write | key, type, value, ttl | result code |
| `0x0012` | UPDATE | write | key, type, value | result code |
| `0x0013` | DELETE | write | key | result code |
| `0x0020` | PERSIST | admin/write | key optional | result code |
| `0x0021` | FLUSH | admin | none | result code |
| `0x0022` | REWRITE | admin | none | result code |
| `0x0030` | STATS | admin/read | scope | stats map |
| `0x0031` | CLIENT_LIST | admin | none | connection list |
| `0x0032` | CLIENT_KILL | admin | connection_id | result code |

批量、多 key、事务、发布订阅和脚本不在首版集合中；新增命令必须更新版本/权限/幂等语义文档。

## 7. 响应与错误

响应固定带 `RESPONSE` 和可选 `ERROR`，body 至少包含：

```text
status_code:u16
message:utf8 (optional, bounded)
result fields...
```

错误码分层：

| 范围 | 类别 | 示例 |
|---:|---|---|
| 0 | 成功 | `OK=0` |
| 1xx | 协议/会话 | `BAD_FRAME`, `UNSUPPORTED`, `NOAUTH` |
| 2xx | 存储映射 | `SUCCESS`, `KEY_EXIST`, `FIND_FAILED`, `EXPIRED` |
| 3xx | 容量/限流 | `MEMO_OUT`, `BUSY`, `TOO_LARGE`, `RATE_LIMITED` |
| 4xx | 命令/权限 | `UNKNOWN_COMMAND`, `FORBIDDEN`, `TYPE_NOT_REGISTERED` |
| 5xx | 服务/依赖 | `INTERNAL`, `STORAGE_UNAVAILABLE`, `TLS_ERROR` |

存储层原始码（200/201/202/204/300/301/400/500）保留在响应的 `storage_code` 字段，
网络 `status_code` 不与其数值复用，避免客户端把内部错误码当 HTTP/RESP 语义。

GET 成功必须返回 `type_name` 和 wire 编码的 value；失败不得返回可能残留的 value。

## 8. 分帧、流水线和顺序

1. 每读入一段字节，先尝试解析固定头；头不完整则等待，不分配 body；
2. 校验 magic/version/header_len/body_len 后，只有 body 完整才产生 Request；
3. 一次读可产生多个 Request，pipeline 达上限立即暂停读事件；
4. 每连接最多一个 active request；completion 到达后才推进下一项；
5. request_id 可不连续，但同一连接不得重复；重复则返回 `DUPLICATE_REQUEST_ID` 并关闭；
6. 响应必须按接收顺序发送，即使未来内部允许多个业务任务并行，也要由 sequence gate 排序。

## 9. 传输关闭与重试语义

- TCP RST、TLS alert、协议错误和输出硬限触发立即关闭；
- QUIT、管理踢出和服务 drain 可发送最后一个小响应后关闭；
- 客户端收到超时/断连时不能据此重试非幂等 ADD/UPDATE；
- 业务层可在未来为请求增加 idempotency token，但首版不承诺跨重连去重；
- 服务器关闭时未执行的 pipeline 请求返回 `SERVER_DRAINING`（若仍可写），否则客户端视为未知状态。

## 10. 兼容与版本

- version=1 的固定头、opcode、field id 和错误码一经发布不复用；
- 新增可选字段只在 feature bit 协商后发送；
- 不识别的 opcode/field 返回错误，不依据字符串猜命令；
- 若未来提供 RESP adapter，adapter 在协议边界转换为 `CommandRequest`，核心执行层不绑定 RESP。
