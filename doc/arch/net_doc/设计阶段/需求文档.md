## 1. 背景与目标

myDB 已有独立的存储和控制接口；网络层为外部客户端提供长期运行的访问入口。网络层接收 TCP 字节流，将其转换成协议请求，交给命令执行边界，并把执行结果返回原连接。它不直接访问缓存表、磁盘文件等存储内部对象，也不能破坏现有存储线程模型。

本阶段的目标是为单机服务建立安全、资源有界、可以逐步扩展的 TCP 接入能力。首版不承诺百万连接、分布式路由、数据复制或事务能力。

## 2. 功能需求

### 2.1 连接与协议

1. 支持 IPv4 和 IPv6 的 TCP（传输控制协议，提供可靠有序字节流）监听及多个并发连接；连接总数受服务配置和操作系统资源共同约束。
2. 支持长连接上的连续请求，正确处理 TCP 拆包、粘包和不完整数据帧。
3. 使用版本化的二进制请求/响应协议，支持请求与响应关联、稳定错误分类和字段扩展。
4. 提供协议协商、认证状态和授权检查的边界；业务命令必须在认证成功并通过权限检查后执行。
5. 为 HELLO（协议协商）、AUTH（身份认证）、PING（探活）、QUIT（响应后退出）、数据增删改查、统计和受权限保护的维护操作提供协议能力。命令含义及存储操作映射由命令执行层决定。

### 2.2 协议与命令范围

MYDB 网络协议是项目自定义的二进制请求/响应协议；它借鉴 RESP 的二进制安全和长度前缀经验，但不兼容 Redis 命令语义，也不承诺 Redis 客户端可以直接连接。

基础帧头长度为 24 字节，字段依次为：4 字节**协议标记**、1 字节版本、1 字节标志、2 字节命令编号、2 字节头长度、4 字节**消息体**长度、8 字节请求关联标识、2 字节保留位。所有多字节整数使用大端网络字节序。消息体使用 TLV 字段序列，即每个字段由编号、类型、保留位、长度和值组成。

协议字段类型包括二进制数据、UTF-8 文本、无符号/有符号 64 位整数、布尔值和嵌套字段。未知标志和非零保留位应拒绝；文本必须通过 UTF-8 校验；嵌套层数、帧大小及字段长度受限；同一命令不得重复提交同编号字段。

首版命令类别为：HELLO（协商协议版本和能力）、AUTH（提交认证信息）、PING（连接探活）、QUIT（写出响应后断开）、GET（读取数据）、ADD（新增数据）、UPDATE（更新数据）、DELETE（删除数据）、PERSIST（请求持久化）、FLUSH（请求清理并刷盘）、REWRITE（请求整理持久化文件）、STATS（读取统计信息）、CLIENT_LIST（查询连接快照）和 CLIENT_KILL（按连接标识请求关闭连接）。命令出现在协议中仅表示其格式和意图需要约定，不意味着首轮必须全部接入同一个业务实现。

网络协议 v1 的字段编号和基础语义如下；编号是协议契约的一部分，新增字段使用新编号，已发布编号不得改作其他用途：

| 编号 | 字段 | 类型与范围 | 主要用途 |
|---:|---|---|---|
| 1 | 协议版本 | 2 字节 BYTES | HELLO 必填 |
| 2 | 能力位 | U64 | HELLO 可选 |
| 3 | 客户端名称 | UTF-8 | HELLO 可选 |
| 4 | 用户名 | UTF-8 | AUTH 必填 |
| 5 | 密码 | BYTES | AUTH 必填；日志不得记录 |
| 6 | 负载 | BYTES | PING 可选 |
| 7 | 键 | BYTES，最多 32 字节 | GET、ADD、UPDATE、DELETE；PERSIST 可选 |
| 8 | 类型名称 | UTF-8，最多 32 字节 | ADD、UPDATE；GET 响应可用 |
| 9 | 值 | BYTES | ADD、UPDATE；GET 响应用于返回数据 |
| 10 | 生存时间 | U64 | ADD 可选参数；单位及取值语义在正式协议冻结前评审，未实现超时/过期映射前拒绝非默认设置 |
| 11 | 范围 | UTF-8 | STATS 可选 |
| 12 | 连接标识 | U64 | CLIENT_KILL 必填 |
| 13 | 状态码 | U64 | 每个响应必填 |
| 14 | 消息 | UTF-8 | 响应可选 |

字段类型约定为 BYTES（二进制）、UTF8（合法 UTF-8 文本）、U64/I64（8 字节整数）、BOOL（单字节零或一）和 NESTED（继续使用相同字段结构的嵌套序列，最大深度为 8）。协议 v1 的命令字段集合如下：HELLO 必须带协议版本，可带能力位和客户端名称；AUTH 必须带用户名和密码；PING 可带负载；QUIT、FLUSH、REWRITE、CLIENT_LIST 不带字段；GET、DELETE 必须带键；ADD 必须带键、类型名称和值，生存时间可选；UPDATE 必须带键、类型名称和值；PERSIST 的键可选，为空时表示全部；STATS 的范围可选；CLIENT_KILL 必须带目标连接标识。命令不允许重复字段。所有响应必须有状态码，可以有消息和命令结果字段。

响应帧设置 RESPONSE 标志；错误响应同时设置 ERROR 标志。压缩和分片标志虽可为未来保留，但 v1 未支持时必须拒绝。网络错误与存储内部错误分别定义；初步状态码范围为协议/会话错误 1xx、命令/权限错误 4xx、服务/依赖错误 5xx，队列忙或容量超限归入明确的服务错误，不直接透传存储内部编号。

### 2.3 并发与管理

1. 由多个事件循环处理连接；每个连接创建后固定交由一个事件循环负责。
2. 同一连接内的请求与响应遵守接收顺序；不同连接之间允许并行。
3. 通过异步完成机制把命令结果送回原连接，网络 I/O 线程不得等待业务或存储操作完成。
4. 为连接快照、按连接标识立即关闭和服务停止提供明确管理边界；服务停止不做排空。
5. 在请求派发前及响应发送前检查服务端当前已观察到的客户端连接状态；已观察到断开时，不派发尚未开始的请求或不再发送响应。
6. 提供连接数量、流量、错误、队列、缓冲和延迟等运行观测信息。

### 2.4 术语说明

- TCP：传输控制协议，提供可靠、有序的字节流，但不保留应用消息边界。
- MYDB 网络协议：myDB 自定义的版本化请求/响应格式；它不等同于 Redis 客户端使用的 RESP。
- RESP：Redis 序列化协议，仅作为长度前缀和二进制安全等设计经验的参考。
- HELLO：客户端与服务器协商 MYDB 协议版本和能力的命令。
- AUTH：客户端提交身份凭据以请求认证的命令。
- PING：检查连接可用性的探活命令。
- QUIT：请求服务器返回响应后关闭客户端连接的命令。
- Reactor：负责等待 I/O 事件并独占维护一组连接状态的事件循环及其线程。
- Connection：表示一个客户端连接，并保存传输、会话、输入输出和请求处理状态。
- Acceptor：监听服务端口、接受新 TCP 连接并将其分派给事件循环的模块。
- 命令执行器：接收已经验证的结构化命令，并通过异步完成结果连接网络层与业务层的边界。
- wire codec：把业务类型与网络线上字节格式相互转换的编解码规则；它与磁盘持久化编码相互独立。
- TLS：传输层安全协议，用于对连接数据加密并验证通信端点。
- ACL：访问控制列表，用于判断已认证主体可以执行哪些命令。
- 排空：停止接收新工作后，等待已接收工作完成的停机方式；本项目目标方案不采用排空。
- ReactorGroup：负责创建和停止多个事件循环，并把新连接分配给其中一个的管理模块。
- Transport：隐藏操作系统套接字细节，向连接处理提供统一非阻塞传输能力的模块。
- Poller：等待连接 I/O 就绪并向事件循环返回事件的抽象。
- FrameCodec：在字节流与完整网络帧之间进行增量解析和编码的模块。
- CommandParser：按命令规则检查帧字段并形成结构化请求的模块。
- Session：记录一个连接的协议协商、认证主体和会话状态的对象。
- NetworkServer：组装监听器和事件循环、管理服务生命周期的模块。
- ConnectionRegistry：按稳定连接标识查询快照并投递关闭请求的管理抽象。
- NetMetrics：汇总网络连接、流量、队列、错误和延迟等运行信息的指标模块。

### 2.5 管理需求边界

1. 管理面负责服务启停、脱敏配置查看、连接查询与立即关闭、指标查看及受权限保护的维护操作，并与普通数据命令分开演进。本轮不设计在线配置修改、凭据管理或角色管理命令。
2. 本地管理请求不伪装成 TCP 客户端，不经过网络连接事件循环；它进入统一管理处理边界并携带明确的本地调用身份。
3. 远程管理必须经过身份认证、逐命令访问控制、审计和限频；管理权限不能从普通读写权限推导。ACL（访问控制列表）根据已认证主体和请求动作判断是否允许执行。
4. 管理请求需要有独立的容量配额或公平调度，避免挤占全部业务容量，也避免持续的本地任务饿死远程业务请求。
5. 具体管理命令字段、角色名称和权限矩阵、审计保留策略、失败回滚和幂等语义须另行评审；密码、令牌、完整数据值和私钥不得出现在管理响应或日志中。

## 3. 行为与一致性约束

1. 同一连接最多有一个业务请求处于执行中；后续请求留在有界的连接级等待区，不得越过前序请求。
2. 响应必须携带原请求的关联标识，并按同连接请求顺序返回；不同连接的完成顺序不作保证。
3. 客户端断开或超时不代表已提交的存储操作回滚。若响应未到达，客户端应将执行结果视为未知，除非业务协议另行提供可判定语义。
4. 网络层只把通过通用帧校验和命令字段校验的请求交给执行层；协议错误不得流入业务处理。派发前若服务端已观察到客户端 TCP（传输控制协议，提供可靠字节流）的连接关闭或重置，丢弃尚未派发的请求；无法确认远端进程即时存活，只依据本地已观察到的传输状态。
5. 服务停止立即关闭网络服务，不执行排空等待；未派发请求丢弃，已经开始执行的业务继续运行但不再返回响应。
6. 响应发送前若服务端已观察到客户端连接关闭或重置，则丢弃待发响应；服务端无法保证最近一次本地传输检查之后客户端仍存活。
7. 异步结果使用稳定连接标识和连接代际验证，不能仅凭可能被操作系统复用的文件描述符定位连接。

## 4. 安全与资源要求

1. 生产环境默认使用 TLS（传输层安全协议，用于加密连接数据并验证通信端点）；安全传输不可用或证书配置无效时启动失败，不得自动退回明文。
2. 明文传输只允许在明确的开发/测试开关下使用；非回环监听还需另一项显式许可。
3. 未认证连接仅可执行 HELLO（协议协商）、AUTH（身份认证）、PING（探活）和 QUIT（响应后退出）等约定操作。密码、令牌和完整数据值不得写入日志。
4. 在分配大型缓冲区或调用业务之前，先校验帧长度、字段长度、嵌套深度、整数边界、文本编码和保留字段。
5. 连接数、单帧、连接输入与输出、每连接待处理请求、全局在途请求和跨线程队列均必须有硬上限。
6. 过载时必须明确拒绝、暂停读取或关闭慢消费者；不得使用无界队列换取短期吞吐。
7. 单连接读写和事件处理必须设置工作预算，避免高流量连接长期独占事件循环。
8. Linux 写网络套接字不得触发进程级 SIGPIPE 信号。

首轮建议配置只作为设计和测试的起步值，并非承载能力结论：默认回环地址为 127.0.0.1，默认端口为 6380，默认要求加密传输；事件循环数量自动计算且不超过 16；连接上限 10,000；监听队列长度 1,024；单帧上限 16 MiB；单连接待处理请求上限 64；全局在途请求上限 4,096；输出高、低和硬水位分别为 4、2、16 MiB；认证超时 10 秒；请求组装超时 15 秒；空闲超时 300 秒。服务停止立即关闭网络，不设置排空等待时间。正式使用前须根据硬件、文件描述符限额、加密开销及实际负载重新校准。

## 5. 模块边界

网络层负责监听与传输、事件循环、连接状态、协议帧编解码、会话状态、请求前置校验、超时与背压、连接管理和网络运行指标。

命令执行层负责业务命令含义、类型实体构造、命令到存储接口的映射和业务错误解释。管理层提供凭据来源、访问控制规则及审计策略。存储层负责缓存、持久化与数据恢复。网络层不替代上述职责，也不直接暴露磁盘持久化格式。

网络层与命令执行层通过稳定的异步接口交换结构化请求和完成结果。业务类型必须有显式、可演进且往返一致的网络编解码规则；不得把内部磁盘序列化格式当作客户端协议。

## 6. 验收要求

1. 协议解析覆盖完整帧、逐字节及随机分片、多帧粘连、非法长度/标志/字段和编码边界；恶意输入不得导致无限循环或超额分配。
2. 连接测试覆盖协商阶段、会话命令限制、认证拒绝、短读短写、对端关闭、错误响应、请求顺序和响应关联。
3. 并发测试证明连接状态只由所属事件循环修改；迟到回调和连接标识复用不会误投到其他连接。
4. 队列与缓冲达到上限时行为确定；慢消费者、业务延迟和停止期间的完成结果不得造成无界内存或永久等待。
5. 服务测试验证加密传输默认策略、明文许可边界、认证与访问控制，以及管理权限隔离。
6. 压测记录机器和内核、编译模式、连接数、数据大小、传输加密状态、吞吐、P50/P99/P999 延迟、CPU、RSS、错误率和存储负载。性能结论必须以报告为证，不预先承诺固定吞吐值。
7. 需求通过状态不得由本文件推定；必须在实现阶段保存对应测试环境、用例和实际结果。
