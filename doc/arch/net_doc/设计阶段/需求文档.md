# 网络层需求文档

> 状态：设计评审稿。目标是给现有存储层增加可长期运行、内存有界、可演进的网络入口。

## 1. 背景与现状

现有存储层已经提供异步 CRUD、持久化和统计接口，采用“读池并发 + 写线程串行 + 磁盘线程串行”模型。
网络层不能改变该模型的正确性边界，也不能让慢客户端、恶意报文或大量排队请求耗尽进程内存。

现阶段项目结构包含网络、命令解析、执行、管理、日志和存储六层。网络层只负责连接与字节流，
不能直接依赖 `Cache`/`Disk` 私有结构。

## 2. 目标

### 2.1 功能目标

1. 接受 TCP 客户端连接，支持 IPv4/IPv6，连接数受配置与系统文件描述符上限共同约束；
2. 在一个长连接上接收多条请求，正确处理拆包、粘包和流水线请求；
3. 将完整请求交给命令/执行层，并把异步结果发回原连接；
4. 支持 `HELLO/AUTH/PING/QUIT`、CRUD、统计和受权限保护的维护命令；
5. 支持连接 ID、连接快照和按 ID 踢出客户端；
6. 支持 TLS、认证超时、空闲超时和优雅关闭；
7. 暴露连接、流量、错误、队列、事件循环延迟和请求延迟指标；
8. 为未来的复制/路由预留协议版本、特性位和请求 ID，但首版不实现分布式。

### 2.2 性能与资源目标

1. 连接使用非阻塞 I/O，不为每个连接创建线程；
2. 每个 socket 只由一个 Reactor 线程读、写和修改监听事件；
3. I/O 线程不得进行磁盘 I/O、业务序列化重活、日志文件写入或 `future.get()`；
4. 所有缓冲区、流水线、跨线程队列和全局在途请求都有硬上限；
5. 单个高流量连接不能长期独占一个事件循环；
6. 空闲连接的常驻内存必须小，缓冲区按需增长并在高峰后回收；
7. 网络层性能不能用“无限队列换吞吐”，过载必须显式拒绝或暂停读取。

“百万连接”作为远期容量探索，不作为首版承诺。首版按 10k、50k、100k 空闲连接分级验证，
最终上限由内存、文件描述符、端口、TLS 开销和压测结果决定。

## 3. 一致性与顺序语义

1. 同一连接内，请求按接收顺序执行，响应也按该顺序返回；
2. 一个连接最多有一个正在执行的业务请求，其余完整帧留在有界流水线中；
3. 不同连接之间可以并发，完成先后不保证；
4. `request_id` 在响应中原样返回，用于关联、日志和未来的多路复用扩展；
5. 首版不允许客户端通过同一连接绕过顺序语义，否则 `UPDATE` 后紧随的 `GET` 可能读到旧值；
6. 客户端超时或断连不等于已提交操作回滚。协议必须将“未收到响应”和“操作未执行”区分开。

## 4. 安全需求

1. 未认证连接只允许 `HELLO/AUTH/PING/QUIT`；
2. 认证和 ACL 由管理层提供接口，网络层维护连接会话状态并执行前置检查；
3. TLS 默认强制开启；最低版本、证书路径和客户端证书策略由配置决定。明文仅允许通过显式开发/测试开关开启，非回环明文监听必须额外显式开启，生产配置不得静默降级；
4. 密码、令牌、完整值实体不得写日志；认证失败日志需要限频；
5. 所有长度字段先校验再分配，整数运算检查溢出；未知版本/命令/标志返回稳定错误；
6. 限制单帧、连接输入、连接输出、流水线深度、认证尝试次数和请求组装时间；
7. 关闭连接时用连接 ID/代际校验异步回调，禁止仅凭已可能复用的 fd 找连接；
8. Linux 写 socket 禁止触发进程级 `SIGPIPE`。

## 5. 初始配置建议

以下是首轮实现默认值，不是性能结论，必须通过基准后定型：

| 配置 | 初值 | 说明 |
|---|---:|---|
| `listen_address` | `127.0.0.1` | 默认不暴露公网 |
| `port` | `6380` | 避免与 Redis 默认端口混淆 |
| `tls_mode` | `required` | 默认强制 TLS；明文仅供显式开发/测试配置 |
| `tls_min_version` | `TLSv1.3` | 不满足环境条件时启动失败，不自动降级 |
| `io_threads` | `0` | 0 表示自动，建议约为逻辑核数一半、最多 16 |
| `max_clients` | 10000 | 启动时与 fd soft limit 校准，并为 listener、poller、eventfd、日志和 TLS 资源预留余量 |
| `listen_backlog` | 1024 | 受系统 `somaxconn` 约束 |
| `max_frame_bytes` | 16 MiB | 覆盖常见 1 MiB 级 payload，并限制单次分配风险 |
| `max_pipeline_requests` | 64 | 每连接已解析待执行请求数，避免单连接占满执行容量 |
| `max_inflight_requests` | 4096 | 全局已提交业务请求数，约为典型 Reactor 数量的数百倍 |
| `output_high/low/hard` | 4/2/16 MiB | 高水位停读、低水位恢复、硬限关闭，采用滞回避免抖动 |
| `auth_timeout` | 10 s | 到期仍未认证则关闭 |
| `request_assembly_timeout` | 15 s | 防慢速发送超大帧 |
| `idle_timeout` | 300 s | 0 可关闭；由分桶时间轮近似执行 |
| `graceful_shutdown_timeout` | 30 s | 超时后强制关闭剩余连接 |

存储层 key/type 当前均是 32 字节定长上限，网络协议按 UTF-8/原始字节长度校验 `<=32`，不做 Unicode 归一化。

## 6. 模块边界

### 6.1 网络层负责

- listener、socket 选项、Reactor/Poller、Connection、输入输出缓冲；
- TLS 握手和加密传输；
- 帧级解析/编码、连接会话、超时、背压和连接注册表；
- 将结构化请求交给 `IRequestHandler`，把完成结果投回所属 Reactor；
- 网络指标和结构化网络事件。

### 6.2 网络层不负责

- 命令业务语义、类型实体构造、Controller 调用和存储错误解释；
- 用户配置文件的最终格式、密码哈希算法和 ACL 数据来源；
- 日志落盘、数据恢复、缓存淘汰、磁盘压缩；
- 分布式路由、复制、事务、发布订阅、HTTP/WebSocket。

## 7. 非功能验收

1. 网络代码可由 sanitizers/静态分析检查，协议解析器可独立模糊测试；
2. 客户端断开、半关闭、超时、服务过载和存储异常不会产生悬空访问或永久等待；
3. 慢客户端持续 30 分钟时，单连接与全局内存保持在配置上限内；
4. 压测报告同时给出 QPS、P50/P99/P999、CPU、RSS、连接数、错误率和存储命中率；
5. 任何性能结论都区分明文/TLS、短连接/长连接、命中/冷读和 payload 大小。

上述数值参考常见中小型缓存服务的 8-16 MiB 单请求上限、64 级 pipeline 和 MiB 级输出水位，属于首轮生产基线，不是性能承诺。上线前必须根据目标机器内存、TLS 开销、payload 分布和压测结果重新校准。详细用例和分级指标见《测试与验收》。
