## 术语说明

- 网络协议 MYDB v1：myDB 自定义的版本化二进制请求与响应格式，不是 Redis 协议。
- RESP：Redis 序列化协议，提供长度前缀和二进制安全等可借鉴经验。
- Acceptor：监听网络端口并接纳新 TCP 连接的模块。
- Reactor：等待 I/O 事件并维护所归属连接的事件循环及其线程。
- ReactorGroup：管理多个 Reactor（连接事件循环），并把新连接分配给其中一个的模块。
- Connection：保存一个客户端连接的传输、会话、缓冲和请求处理状态的对象。
- Transport：屏蔽底层套接字细节并提供非阻塞握手、读写和关闭的传输抽象。
- I/O：输入/输出操作的统称，本文主要指网络套接字读写。
- 背压：资源接近上限时，通过暂停读取、拒绝请求或关闭连接控制输入速度的机制。
- Poller：等待平台 I/O 事件并把就绪通知交给连接事件循环的抽象。
- FrameCodec：在 TCP 字节流与完整网络帧之间进行增量解析和编码的模块。
- CommandParser：检查完整帧中的命令编号和字段规则，并生成结构化请求的模块。
- Session：记录连接协商阶段、认证主体和授权上下文的会话对象。
- ICommandExecutor：网络层向命令业务层提交结构化请求并接收异步结果的边界。
- ConnectionRegistry：按稳定连接标识提供有限连接快照并投递关闭请求的管理抽象。
- NetworkServer：装配监听器和 Reactor，并编排网络服务启停的模块。
- NetMetrics：汇总连接、流量、队列、错误和延迟等网络运行指标的模块。
- TLS：传输层安全协议，用于加密连接数据并验证通信端点身份。
- ACL：访问控制列表，根据认证主体及操作权限决定是否允许执行命令。

## 文档边界

本目录描述网络层的目标设计，不等同于当前已经实现或通过测试的能力。技术和架构决策应先服务于现有存储层的线程与生命周期约束，再考虑远期扩展。设计阶段只讨论需求、实现思路和技术选择，不写源代码、伪代码、函数签名或代码示例。

当前初次实现的实际范围、与目标设计的差异及尚未闭环项，见[初次实现阶段文档](../实现阶段/初次编写/README.md)。设计阶段由需求、可行性、技术选型和管理接口四份文档构成；协议与模块概念在对应章节解释，管理接口规则集中在管理设计文档。

## 设计结论摘要

- 目标为单机 TCP 服务；首发服务端运行在 Linux，网络 I/O 与命令/存储执行分离。
- 每个连接固定交给一个 Reactor 管理；跨线程通过有界消息投递，不直接操作连接状态或套接字。
- 使用自定义长度前缀二进制协议，支持请求关联和版本演进，不承诺与 RESP 兼容。
- 同一连接中的业务请求按接收顺序执行；不同连接之间允许并行。服务停止立即关闭网络；未派发请求丢弃，已开始业务继续执行，但连接关闭后不再发送响应。
- 连接、帧、缓冲、待处理请求和跨线程队列均须有明确资源上限。
- 生产默认使用 TLS 加密传输；安全传输未就绪或配置失败时不得静默降级为明文。
- 网络层通过异步命令执行边界提交结构化请求，不操作存储内部对象，也不等待磁盘结果。

术语补充：排空指停服时停止接收新工作，并等待此前接收的工作完成；本项目目标方案不采用排空。
