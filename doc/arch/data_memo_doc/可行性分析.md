# 可行性分析

使用`写回缓存`策略

## 数据类型构建

数据构建是服务器启动的时候构建的，服务器需要事先向数据库告知有哪些数据类型

**实现方案**：

该层加一个`data_type.h`，这里用于存放数据库中所有的数据类型，只能通过`#include`的方式导入新的数据类型

- 基本数据类型写到`base_data_type.h`中，然后在`data_type.h`中导入它即可
- 用户在服务端导入该类型的时候，
  需要事先创建一个文件，在里面定义好这个数据类型，
  然后在`data_type.h`中`include`这个文件
  之后调用宏接口(`DEFINE_DATA_TYPE(std::string类型名)`)，将这个新的数据类型彻底添加
- `data_type.h`加一个unordered_set<类型名>，用于后续给客户端查询能够使用哪些数据类型，当用户调用`DEFINE_DATA_TYPE宏函数`的时候，添加进去

**注意**

- 最好让用户写好查询回调，这样也方便处理
- 修改的话可能需要进行交互优化，最好能让用户修改某个具体属性
- 自定义结构，基本结构都是`类`的方式定义

## 缓存模块

不同的数据类型均使用一个`unordered_map<std::string 变量名，val> cache`

`val`结构体结构如下：

- std::string type_name;   // 类型标记
- `std::chrono::system_clock::time_point expireTime`;  // 或 int64_t 毫秒时间过期时间(-1表示永不过期，用日期表示(字符串))
- `std::chrono::system_clock::time_point createdTime` 存在时间，现在可能不用，先创建先
- bool isDirty 是否为脏数据（1表示脏数据，0表示非脏数据）
- std::any entity;         // 值实体（使用C++17新特性）

`日期时间`格式为`xxxx-xx-xx xx:xx:xx`(2002-06-16 09:54:43)

type_name和name都很好处理

entity处理方式：依旧使用C++11，C++17新特性处理

unordered_map<变量名，偏移量> inDisk，用于存放已经持久化的变量名

unordered_set<变量名> delDisk，用于存放磁盘中待删除的变量名

- 缓存中的数据为主要数据，意思是如果缓存中存在脏数据，则缓存的数据是真实的，磁盘中的数据是旧的数据，需要等待更新



### CRUD处理方法

- 增：map中先查找是否已经存在该变量，若存在返回失败码表示已存在，若不存在则创建并插入，并返回成功，设置该数据为脏数据

- 删：map中先查找是否已经存在该变量，若不存在，再检查inDisk是否存在
  返回失败码表示不存在，若存在则删除，尝试移出cache，添加到delDisk，并返回成功

  ```
  删：
    1. 查 cache：
       - 命中 → 从 cache 移除，加入 delDisk（若 inDisk 有则标记待删，若无则无需）
       - 未命中 → 查 inDisk：
         - 在 inDisk → 加入 delDisk，返回成功
         - 不在 inDisk → 返回失败码"不存在"
  ```

  

- 改：map中先查找是否已经存在该变量，若不存在，先调用磁盘查询，等待返回结果，返回失败码表示不存在，若存在则修改，修改失败返回错误码，否则返回成功，并设置为脏数据

  ```
  如果缓存存在：修改并设置为脏数据
  如果缓存不存在但inDisk存在且delDisk不存在：新增该数据，标记为脏，等待刷盘更新磁盘
  若都不符合，则返回失败
  ```

  

- 查：map中先查找是否已经存在该变量，若不存在，先调用磁盘查询，等待返回结果，若不存在返回失败码表示不存在，并将`查询指针`置空，若存在，则填充`查询指针`（若 cache或将磁盘数据写入缓存，缓存爆满的情况前期不管，若存在爆满，则读取同时在缓存中取至多n条数据进行刷盘并删除），并返回成功

- 注意：如果`cache`未找到该变量，需要查找`inDisk`是否存在，若存在，还需要将其添加到`delDisk`，等待定时删除

## 持久化

1. 写一个持久化接口，参数：变量名
   - 若该变量不存在，返回失败码，若存在，先检测数据是否是脏数据，且是否过期，**若是脏数据，且未过期**，则调用写入磁盘接口，写入成功后在`inDisk`中插入这个变量
2. 写一个持久化接口，参数：void，表示持久化整个缓存的数据
   - 先检测数据是否是脏数据，且是否过期，**若是脏数据，且未过期**，则调用写入磁盘接口，写入成功后在`inDisk`中插入这个变量

## 磁盘数据删除

1. 定义一个接口，用于删除磁盘中的数据，删除所有在delDisk的变量

- 这个接口一般定时调度，具体时间读可取文件配置，前期调试可以先设置为30s

## 磁盘刷盘

1. 定义一个接口，用于刷盘

   - 将缓存中所有**未过期的脏数据**写入磁盘（持久化）
   - 删除所有delDisk中的变量（先检查inDisk中是否存在，若存在，则读取对应偏移量后删除），并更新inDisk
   
   这样就保证了刷盘的时候，删除和持久化只需一次文件打开/关闭

## 数据导出

导出指定变量，参数：一个List（存放导出组）

- 实现方法：

  读取List中的变量名，先结合inDisk，delDisk，cache中查看该变量是否应该存在，若可以存在，则先写入到一个数组中，遍历完所有的List

  然后判断数组是否为空，非空才打开数据库文件，读取偏移量，读取具体的值，写入到cache，完成后返回成功，关闭文件

## 过期数据

过期数据定时删除，不管是否脏的都要删除，且添加到delDisk

## 数据重写

- 由于持续进行文件写入和删除，会存在空洞的现象，造成资源的浪费，因此当文件大小达到阈值时，需要进行重写

将缓存和indisk中的数据一并写入到新的文件，然后删除旧文件，同时要记得删除掉 delDisk

## 注意

**协议**：const常量协议和协议宏，相比较下const常量更好 

作为存储层，大概率会被多线程调用。建议：

- **至少**在 `CacheManager` 中加一把 `std::shared_mutex`
  - 读操作：`shared_lock`
  - 写操作：`unique_lock`
- 刷盘操作可以**先拷贝脏数据，释放锁后再写磁盘**，减少锁持有时间
- 持久化：单文件 + 偏移量索引
- 数据层一般要用线程池处理任务，可能需要`并发编程`处理，注意必要时加锁防止竞态
