# 架构设计

分为两个模块

- 缓存模块
- 磁盘模块

- common模块，用于写一些**通用接口**，比如**数据计时**
- 数据构建模块，用于**构建基本数据**，**自定义数据**

## 缓存模块

缓存模块是用户主要操作的区块，是CRUD的频繁区块，务必要保证架构清晰，代码性能比较好

分为 **增，删，改，查**四个主要子模块

- 增：增加新的变量（key），返回操作码
- 删：删除一个存在的变量（key），返回操作码
- 改：修改一个key对应变量的值，返回操作码
- 查：查询该key对应的值，并返回值，失败返回失败码

## 磁盘模块

主要用于数据持久化操作

每个数据的持久化格式如下：

- 变量名(key) + 数据类型 + 值（类似于mongoDB的处理）

需要如下接口：

1. 持久化接口，调用该接口后，缓存中的所有数据都要持久化
2. 导出接口，调用该接口后，磁盘中的指定数据要导入到缓存，如
3. 重写接口：indisk中的数据和缓存中的数据一并写入新的文件，删除就的数据库文件

## 管理模块

用于封装disk和cache接口

## 数据Base

通过一个对象来描述该key对应的变量信息

具体需要包括

- 变量名
- 过期时间(-1表示永不过期，单位是ms)
- 是否为脏数据（0表示脏数据，1表示非脏数据）





调用操作接口后，现在缓存模块执行对应业务
