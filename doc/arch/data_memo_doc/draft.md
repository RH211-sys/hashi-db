# 草稿（整理中）

## 重写机制详解（定稿）

**前置条件**：删除 = 纯内存 `inDisk.erase`，不落任何文件标记 → 不需要删除码，校验码两态（VALID / BROKEN）；崩溃后已删数据复活，允许回溯（可容忍）。

**流程**：直接把 inDisk 中的所有数据覆盖旧文件（原地重写），全部完成后清空后面的数据（truncate）。

1. 对 inDisk 的偏移量排序（临时 `vector` 拷贝 + `sort`，重写低频，不必常驻红黑树/优先队列），从偏移量小的开始遍历
2. 若该变量**缓存中存在** → 直接持久化缓存数据（不管是否脏，缓存是权威），写完后该变量 `isDirty` 置 `false`
   - 读缓存 Val 拿**读锁**，锁内拷贝 Val；清 isDirty 拿**写锁**；序列化写文件在锁外
3. 若**不在缓存** → 从磁盘（按偏移）找到该数据，移动到前面（读一条 → 写一条）
4. 全部完成后 `_chsize_s` 截断到写游标位置

**安全性的保证**：写游标（紧凑总长）≤ 下一个待读偏移——跳过了已删数据和空洞后，紧凑长度只会比原始长度短，写永远不覆盖未读记录。

**注意**：重写遍历源是 inDisk——缓存里全新未刷盘的变量不在 inDisk 中，重写不处理它；但缓存仍持有且 isDirty，后续刷盘会落盘，不丢。

**崩溃处理**：原地重写中途崩溃 = 数据全损（文件半新半旧、偏移全乱）。概率极小，极端情况，交运维（事先备份文件）。防止崩溃的两文件方案（新文件 + 删旧文件）会把磁盘利用率降一半，用于防止极端情况大材小用。后面若真要防重写崩溃，理应在管理层做文件备份。
