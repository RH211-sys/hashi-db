## 淘汰算法（缓存容量管理）

### 触发与目标水位

- 触发：缓存占用 `缓存curSize > memoSize` 时（addData/modData/磁盘回填插入后，锁外调用 `evict()`）；
- 目标：淘汰到 `curSize < memoSize × 9/10`（留 10% 余量，防止"刚淘汰完又超限"抖动）；
- 执行者：**写线程**（串行上下文，天然无并发）；阻塞执行到容量达标。
- 淘汰对象：`Val` 条目本身（`entity` 是 `shared_ptr`，删缓存不析构实体；脏数据的 Val 浅拷贝带出，
  攒批落盘，实体零拷贝）。

### 打分公式 evictScore（分数高的先被淘汰）

```
score = level × LEVEL_DIS + ln(dataSize)      LEVEL_DIS = 30（档距）
level：距上次"读命中/插入"的时间间隔分档（静态档位表，见 cache.cpp evictScore）
```

- `level` 来自 `updateTime`（µs，relaxed 原子）距 now 的间隔：测试接口用毫秒/秒级档位
  （<1ms / <10ms / <100ms / <1s / <10s / <20s / ≥20s）；业务场景可换分钟/小时/天等档位，**可按照实际业务划分挡位**（注释示例）。
- `ln(dataSize)`：同档内偏删大 key（同字节容量下删大 key 腾空间最快）；
  档距 30 > ln(任何合理 memoSize) 上限（≈20~25）→ **跨档无法靠大小翻盘**，冷数据永远优先于热数据。
- `intervalUs < 1` 与 `dataSize < 1` 均取下限 1，防 log(0)/负档。

### 全局采样淘汰（无 LRU 链表）

不维护访问序链表，而是"随机抽样 + 大顶堆选最差"：

1. **过期先行**：独占锁内全遍历 `cache_db`，先批量删过期条目（TTL 垃圾），并把名字批量投递磁盘线程
   删 inDisk 索引（CACHE_TASK，防过期数据从磁盘"复活"）；删完若已达标则结束。
2. **采样补候选**：`SAMPLE_NUM = max(256, cache_db.size()/2)`；从**随机起点桶**起环形扫 `bucket_count()`
   个桶收样本，共享锁内只读（不阻塞并发读）；样本按 `evictScore` 入大顶堆 `(score, name)`。
3. **取堆顶淘汰**：每轮直接 pop 堆顶，堆空才补采一批（不每轮重采样）。采样与淘汰之间条目可能被并发改：
   每轮删除前**独占锁内重校验**（以当时为准）：已消失则丢弃候选；干净数据（与磁盘一致）直接删缓存；
   脏数据浅拷贝 Val 带出、删缓存减 `curSize`，攒入本批 `flushBatch`。
4. **批尾落盘**：`flushBatch` 一次投递磁盘线程 `persisData(批)`（DISK_TASK，提交即返回不等待）。

### 为什么弃用 LRU 链表（设计沿革）

- 一轮优化评估过 LRU 链表与淘汰策略细化（见 `一轮优化/LRU淘汰算法优化.md`、`LRU实现细节处理.md`）；
- 最终实现取**全局采样淘汰**：命中路径零链表维护（并发读锁内只刷一个 relaxed 原子时间戳），
  淘汰路径 O(样本) 即可收敛，与"unordered_map 快查 + 锁内临界区最小"的整体形态一致；
  热度只是近似（不保真 LRU 序），对缓存中间件足够。

## 压缩策略/重写机制（磁盘空间回收）

### 背景：追加式日志的空间问题

磁盘是追加日志（记录 = 86B 定长头 + 实体），删除/覆盖旧版本后文件只增不减（旧版本成隐式空洞），
空间回收的唯一手段是**整文件重写**。压缩策略 = "贵但少"：一次压缩在文件末聚合所有空洞、利用率 100%，
不做局部压缩（局部压缩制造细碎洞 → 利用率下降 → 压缩更频繁）。

### 触发（硬上限，写路径自动执行）

```
若 maxSize > 0 且 磁盘curSize + 本条记录长 > maxSize：
    ① flushSync()           先提交本任务此前缓冲的追加（压缩读回安全）
    ② reWrite()             自动压缩（两阶段原地重写）
    ③ 压缩后仍放不下 → MEMO_OUT(300)
批量写遇 MEMO_OUT 立即中断；maxSize ≤ 0 视为不限
```

### reWrite（重写）：两阶段原地压缩（根治"写覆盖读"）

全部在常驻文件句柄上原地完成，末尾 `resize_file` 截断；成功后清空 holes（紧凑文件无洞）。

- **阶段A**：只搬"缓存没有 / 缓存干净"的 key——整条读旧写新、**长度不变**，写游标 ≤ 读游标，
  永远不会覆盖后面还没读的旧记录（早期原地压缩失败 6348/6351 的根因即"写覆盖读"）；
- **阶段B**：缓存里的**脏 key** 最后写——此时旧区已无待读记录，可安全覆盖/追加；
  清脏前校验实体指针未变（防并发 mod 后误清）；
- **阶段C**：inDisk 里没有的全新缓存数据追加写入。
- 失败出口：返回错误（中断语义同旧版，交运维）；失败仅来自真实 IO 错误。

### 可选：提前压缩（未做）

`空洞总量 > maxSize × 阈值` 时提前压缩（空洞总量可经 holes 登记累加实时求和，实现容易）。
策略文档先列项，等空洞复用稳定后再评估（`空洞删除段设计.md` §5、§8-4）。

## 空洞/删除段与空间分配策略（删除 = 空洞 + best-fit 复用）

> 详见 `实现阶段/二轮优化/空洞删除段设计.md`（§10 已实现 1~4）。

### 段模型（段：每条数据/每条记录）

- 记录/洞段统一 86B 头语义：`CHECK_VALID`(0x5A) 活记录、`CHECK_DELETED`(0xFF) 已删/空洞段（同一语义，
  可复用）、`CHECK_BROKEN`(0x00) 残尾（重建截断）；顺序扫描一律 `offset += 86 + dataSize`。
- 洞段头实际只写 **code + dataSize 共 5B**（跳读/复用只依赖这两字段），其余头字节是旧残留，不影响 loader。
- 删除 = 空洞：`delData`/过期清理擦 inDisk 索引 + 记录首字节改 `CHECK_DELETED`（保留旧 dataSize）→
  整段成为空洞，1 字节写；旧版本被取代时同样显式变洞并登记（防"旧 VALID 残留被 loader 复活"）。

### 磁盘写路径空间相关（磁盘单线程，逐条执行）

记号：新记录总长 `V = 86 + 新dataSize`，旧槽总长 `T = 86 + 旧dataSize`。

```
① 原位覆盖 tryOverwriteInPlace（有旧记录且 V ≤ T）：
      V == T         覆盖即可（等长，无洞）
      T − V ≥ 86     覆盖，并在 偏移+V 写 DELETED 洞头(dataSize = T−V−86) → 剩余登记为洞
      T − V ∈ (0,86) 剩余不足一个合法洞段 → 不做覆盖，回退追加（见 §"回退追加的语义"）
      V > T          放不下 → 回退追加
② 空洞复用 tryUseHole（无合适覆盖）：
      holes.lower_bound(V) 取"不小于需求的最小洞"写入；剩余 R' = 洞容量 − V：
         R' ≥ 86 → 再写洞头(dataSize = R'−86) 保留剩余洞
         R' < 86 → 整段利用（浪费 <86B，不写洞头）
③ 容量检查：见"压缩策略-触发"（超限先自动压缩，仍超返回 MEMO_OUT）
④ 尾部追加 appendRecord（两段式校验码写整条；更新 inDisk/curSize）
```

- 洞索引 `holes = std::multiset<(洞容量, 偏移)>`（容量升序），分配 = best-fit；
  不用 max-heap（大洞被反复切成中/小洞，很快没有能装 1M~10M 大记录的洞 → 碎片加剧）；
  不用 first-fit（需沿偏移扫描、小洞堵前部 → 碎片与复杂度都差）。
- 索引生命周期全部在磁盘单线程维护（天然无锁）：追加无操作 / 覆盖缩小登记剩余洞 / 删除登记整段洞 /
  复用移除洞（+切洞登记）/ 压缩成功清空 / 崩溃后由 loader 顺序扫描重建。
- 写洞失败时把该段恢复为 DELETED 并放回索引、回退追加（复用失败恢复）。

### 回退追加的语义（防断链）

剩余空间不足 86B 时，该剩余区**无法表达成任何自描述段**（合法段最小 86 逻辑字节），
若直接硬覆盖会留下"无主字节" → 顺序扫描会错位
→ loader/reWrite 全错位。所以此时**放弃覆盖、改在文件尾追加新版本**（旧记录整段变洞，空间不丢，
可被 best-fit 复用或由压缩回收）。

## 写盘时序与崩溃一致性

### 两段式提交

每条记录落盘先整条写 `CHECK_BROKEN`(0x00)，写毕把首字节回写 `CHECK_VALID`(0x5A)；
顺序扫描把 0x00 段当残尾**截断文件到该处** → 崩溃窗口只丢"正在写的半条"，不产生坏记录。

### 可恢复写失败回滚（disk.cpp 失败分支）

- **尾部追加失败**：写入前记录偏移 `offset`；失败时 `clear → flush（先落盘同批此前已入 inDisk 的记录）
  → resize_file(dbName, offset)` 截掉半条残渣（写失败的区块不留）；flush 也失败则保留缓冲，
  交调用方"脏恢复 + 重试追加"自愈；
- **原位覆盖失败**：把旧 code + 旧 dataSize 写回原位置，槽恢复为"长度 = 旧槽"的自描述记录
  （body 混合旧/新、链不断，等下次成功刷盘取代/标洞）；
- 仅失败路径多一次 IO，正常路径零开销；进程崩溃无代码可执行，残尾仍由 loader 截断兜底（详见设计分析 §7.1）。

### 批 flush 时机

flush 不逐条做，随"所在写任务批"统一执行（各写路径共用 `flushSync`）；单线程内读写天然有序，
保证可见性规则一致（空洞删除段设计 §3.2/§6）。

## 并发与调度策略

### WritePrefMutex：写者优先 + 双向防饿（cache 表锁/读写锁）

- 状态：`readers` / `writing` / `writersWaiting` / `readSubWrite`（读任务累计 − 写任务累计）/
  `batchRemain`（放行批剩余名额）。Cache 组装默认 (batchSize=4, upDisEdge=10, minDisEdge=-3)。
- 读者进入 `lock_shared`：等待 `!writing && (writersWaiting == 0 || batchRemain > 0)`——
  有写者在写**或有写者排队**时新读者不插队（写者优先）；例外是持批名额的读者可插队。
- 写者进入 `lock`：`++writersWaiting` → 等 `!writing && !readers` → 持锁。
- 记账（封装在 unlock 里防漏记）：
  - 读者离开 `++readSubWrite`；若 `readSubWrite ≥ upDisEdge` 且无写者排队 → 清 0、关批（读太多且写者没等，
    历史账作废）；
  - 写者离开 `--readSubWrite`；若 `readSubWrite ≤ minDisEdge` 且批未开 → `batchRemain = batchSize`
    （写太多把读饿着 → 放一批读插队名额，防止读饥饿）。
- 读锁共享（读读并发）、写锁独占；语义对齐 `shared_mutex`，可直接配 shared_lock/unique_lock。

### DiskThread 双队列差距调度（磁盘线程内部）

- 两队列：CACHE_TASK（快，微秒：inDisk 查重/查存在/删索引）与 DISK_TASK（慢，毫秒：文件读/写/压缩）。
- 记账 `taskGap`：处理一个缓存任务 +1，处理一个磁盘任务 −1；
  阈值 `upEdge=15` / `lowEdge=-5`。
- 取任务规则：缓存任务优先；但 `taskGap ≥ upEdge` 且有磁盘任务排队时让位处理一个磁盘任务；
  处理到 `taskGap ≤ lowEdge` 清 0（磁盘连做不能把缓存任务饿死）；到上缘且无磁盘任务也清 0。
- 效果：常态缓存任务（快）不被慢磁盘 IO 堵死；慢任务也不会被无限积压的缓存任务饿死。

### 续延链投递

一次 API 请求拆成多段，按序在写线程 ↔ 磁盘线程（读在读池 ↔ 磁盘线程）间投递，段间共享
`AsyncResult<T>`（`shared_ptr<promise>`）；段体异常统一转 `set_exception`、线程停止 `fallback()` 兜底，
保证调用方 `future.get()` 永不永久等待（见 `架构总结.md` §2）。

### 读并行（经验与前提，当前未做）

- 现状：miss 读是 DISK_TASK，在**磁盘单线程**串行执行（场景2 实测读占 ~20s/30s、单条 ~215µs），
  是当前第一瓶颈；命中读走读池不受影响（这是要保留的好性质）。
- 沿革：曾有一版读并行实现（备份版本）**实测反而恶化性能，已回退**；`二轮优化/读并行设计(废弃).md`
  的完整协议（新增读磁盘池 + inDisk 读共享锁横跨整个文件读 + 偏移"发布"后移到 flush 之后 +
  压缩全程独占互斥）因此未实施。结论：要上必须按废弃稿重新设计（v2），不能只把 miss 读挪个线程池。

## 冷启动重建 loader（规则已定，实现后置）

生产前必须补（否则删除/洞与 inDisk 索引不同步会丢空间信息）。算法 = 文件顺序扫描一遍：

```
offset = 0
while offset < 文件长:
    读头 code + dataSize
    if code == CHECK_BROKEN: 截断文件到 offset; 结束           // 残尾
    if code == CHECK_DELETED: 登记空洞 (offset, 86 + dataSize) // 跳过
    else (VALID):             读入记录 → inDisk[name] = offset // 活记录
    offset += 86 + dataSize
空洞索引 = 登记的洞集合（best-fit 有序表）
```

同时校验损坏、截断残尾、恢复 inDisk 与空洞索引。实现时机：管理层阶段（`空洞删除段设计.md` §7）。

## 热度与过期策略（TTL）

- 热度度量 = `Val::updateTime`（µs since epoch，relaxed 原子）：读命中刷新、addData 置 now、
  磁盘回填**沿用磁盘记录旧时间**（回填不保活）、modData 命中不刷新（写可能是冷数据）；
  供 evictScore 分档。
- 过期判定点（惰性，不专门起清理线程）：
  1. `selData` 命中时查过期——过期返回 EXPIRED，并投两条平级清理（写线程删缓存 + 磁盘线程删 inDisk，防复活）；
  2. 磁盘读回后判定过期——过期直接在磁盘线程删索引，数据舍弃不回填；
  3. `evict()` 开头独占锁全遍历批量清过期（进入淘汰路径时顺带）。
- 统计口径：缓存中存在即算"命中"（含过期，过期属 TTL 语义不算 miss）；读盘成败都算 miss。

## 容量与账本策略

- 两本账独立：缓存 `curSize`（字节实体）与磁盘 `curSize`（文件实际大小）；
  磁盘记录偏移 `inDisk` 全链路 **64 位**（文件可超 2GiB，早期 int 溢出曾致读全失败）。
- 容量执行：缓存超 `memoSize` 触发淘汰；磁盘超 `maxSize` 触发自动压缩，
  压缩后仍放不下返回 `MEMO_OUT(300)`（双语义：内存满/磁盘满，见 protocol.h）。
- 空洞观测口径：`holeCnt/holeBytes` 是**快照**（压缩成功清空），`overwrite*/holeUseCnt` 是累计；
  read/sel 探针为 miss 去向分类（inDisk-miss / file-fail 细分 check/name/eof/type/open / ok），
  现以 `/* */` 注释保留，正式输出只留 QPS/P99/命中率。

## 附：压测台辅助算法（不属存储层，备查）

- **延迟分位**：蓄水池采样（每线程样本上限 20 万），水位线抽样保持总体分布，30s 高 QPS 不全量存样本；
- **数据尺寸**：QPS 档 4K~1M（log-uniform），命中率档 log-normal 1K~10M（均值 ~194K/条，±4σ 截断）——
  与真实"大 value 冷热不均"同量级；
- **访问模型**：热子集限 ≤0.7×memoSize 做"纯内存命中读"档；冷热 80/20 + 数据 2x/3x 缓存做命中率档；
  新增 key 缓慢注入（60 条 / 500ms ≈ 2 key/s）模拟数据集增长；`WRITE_INFLIGHT=4` 制造稳态在途写。
