# 第一部分：接口调用方式与功能

## 1. 使用前置条件

### 1.1 自定义数据类型的注册（使用接口前的第一步）

缓存中间件的"自定义类型"能力要求每个业务类型提供三样东西 + 一次注册：

| 需要提供 | 形式 | 用途 |
|---|---|---|
| 序列化 | `template <class Archive> void serialize(Archive& ar)` 成员 | 落盘打包/读盘还原（cereal 二进制） |
| 类型名 | `static` 返回类型名的函数（如 `static const char* getClassName()`） | 写进记录头、类型注册表索引 |
| 大小估算 | `static ... theSize(const T&)`（按 `THE_SIZE(类型, 对象)` 调用） | 容量记账/淘汰打分（**避免"先序列化才知道大小"的性能损失**） |

注册方式（启动后、首次使用前调用一次）：

```cpp
#include "data_type.h"        // 已含协议与注册宏
// …你的类型定义（含上面三样）…
DEFINE_DATA_TYPE(你的类型名);  // 把类型注册进 totalType + 序列化注册表

例如：
struct BenchData {
	long long size;				// 数据长度（随机内容）
	std::vector<char> data;		// 随机填充的数据体

	static std::string getClassName() { return "BenchData"; }
	template <class Archive>
	void serialize(Archive& ar) { ar(size, data); }
	static long long theSize(const BenchData& b) { return sizeof(BenchData) + b.data.size(); }
};
```

### 1.2 构造存储层对象

```cpp
Controller db(memoSize, maxSize, poolThreadNum, dbName);
// memoSize     缓存容量上限（字节），超出后写路径自动淘汰
// maxSize      磁盘文件容量上限（字节），超出后写路径自动压缩，仍超则返回 MEMO_OUT；<=0 不设限
// poolThreadNum 读线程池线程数（命中读并发度）
// dbName       数据文件名（惰性创建，首次写盘时生成）
```

构造时自动创建：缓存、磁盘、读线程池、写线程、磁盘线程并注入依赖；无需其它初始化调用。

### 1.3 异步调用约定（最重要的使用规则）

- **所有 CRUD/持久化接口都返回 `std::future`**：调用即投递、不阻塞调用线程；
  只有需要结果时才 `future.get()`（阻塞直到完成并取回错误码）；
- 多线程调用安全：内部读并发、写单线程串行、磁盘 IO 单线程，调用方无需加锁；
- `selData` 返回的实体是 `std::shared_ptr<std::any>`，**与缓存共享同一实体（零拷贝）**，
  只读约定——要修改请走 `modData`，不要直接改实体内容；
- 过期是 TTL 语义：命中但过期返回 `EXPIRED` 并自动清理，不影响调用方。

### 1.4 错误码（protocol.h）

| 码 | 含义 | 常出现于 |
|---|---|---|
| `SUCCESS`(200) | 成功 | 全部 |
| `KEY_EXIST`(201) | 变量已存在（缓存或磁盘任一） | addData |
| `FIND_FAILED`(202) | 未找到该变量 | mod/del/sel/persis |
| `TYPE_VALID`(203) | 类型未注册 | 落盘/读盘 |
| `EXPIRED`(204) | 已过期（数据被丢弃清理） | selData |
| `MEMO_OUT`(300) | 容量不足（内存满触发淘汰、磁盘压缩后仍超） | 写路径 |
| `LONG_NAME`(301) | 变量名/类型名超长（>32B） | 写路径 |
| `UNKNOWN_ERROR`(400) | 未知错误（IO 失败等） | 写/压缩 |
| `FILE_OPEN_FILED`(500) | 文件打开失败 | 磁盘读/写 |

## 2. CRUD 接口

### 2.1 addData —— 新增一条数据

```cpp
template <typename T>
std::future<int> addData(const std::string& varName, T entity,
                         bool isPermanent, std::chrono::system_clock::duration during);
```

- **功能**：插入新 key。缓存与磁盘都查重——**任一已有即冲突**（返回 `KEY_EXIST`）；
  插入的数据标记为脏（待刷盘）；若插入后缓存超容，内部自动触发淘汰。
- **参数**：`isPermanent=true` 永不过期；`false` 时过期时间 = 插入时刻 + `during`。
- **返回**：`SUCCESS` / `KEY_EXIST` / `LONG_NAME` / `TYPE_VALID`（值错误，不会插入）。
- **示例**：
  ```cpp
  int code = db.addData("k1", myData, false, std::chrono::seconds(3600)).get();
  // code == SUCCESS 才代表已生效
  ```

### 2.2 modData —— 整体修改一条数据

```cpp
template <typename T>
std::future<int> modData(const std::string& varName, T entity);
```

- **功能**：整体替换已有 key 的值。
  - 缓存命中：直接替换实体并标脏（不刷新热度——写可能是冷数据）；
  - 缓存未命中但磁盘有：回填缓存并标脏（磁盘数据无过期信息，回填默认永久）；
  - 都不存在：`FIND_FAILED`。
  - 替换后缓存超容会触发淘汰。
- **返回**：`SUCCESS` / `FIND_FAILED` / `LONG_NAME` / `TYPE_VALID`。

### 2.3 delData —— 删除一条数据

```cpp
std::future<int> delData(const std::string& varName);
```

- **功能**：从缓存删除 + 磁盘索引删除（磁盘记录标记为"已删/空洞"，文件不物理回收，空间可复用/被压缩回收）。
- **返回**：缓存或磁盘任一处找到并删除即 `SUCCESS`；两处都没有 → `FIND_FAILED`。

### 2.4 selData —— 查询一条数据

```cpp
std::future<SelResult> selData(const std::string& varName);
// SelResult { int resCode; std::shared_ptr<std::any> entity; }
```

- **功能**：缓存命中直接返回实体（零拷贝，**只读**）；缓存未命中则读磁盘并**后台回填**缓存；
  磁盘也没有 → `FIND_FAILED`。
- **返回**：`resCode` = `SUCCESS`/`EXPIRED`/`FIND_FAILED`；`SUCCESS` 时 `entity` 指向查询实体
  （与缓存共享），失败时为空。
- **示例**：
  ```cpp
  SelResult r = db.selData("k1").get();
  if (r.resCode == SUCCESS) {
      auto& v = std::any_cast<const BenchData&>(*r.entity);   // 只读使用
  }
  ```

## 3. 持久化与维护接口

| 接口 | 功能 | 返回 |
|---|---|---|
| `std::future<int> persisVar(const std::string& varName)` | 单条显式刷盘：把该 key 的脏数据落盘 | `SUCCESS`/`FIND_FAILED`/… |
| `std::future<int> persisAll()` | 持久化缓存中**全部脏数据**（未过期） | `SUCCESS`/… |
| `std::future<int> flushDisk()` | 维护式刷盘 = 清过期（缓存+磁盘删除） + 全部脏数据落盘 | `SUCCESS`/… |
| `std::future<int> reWrite()` | 磁盘数据重写压缩：整文件整理、回收空洞并截断（自动压缩的内部实现，也可手动调用） | `SUCCESS`/`UNKNOWN_ERROR` |

说明：`persisVar`/`persisAll`/`flushDisk`/`reWrite` 均为"提交即返回"，需要确定完成时 `get()`；
本层不内建定时器，定时调用由上层/管理层负责（如每 30s `flushDisk`）。

## 4. 观测接口

| 接口 | 内容 |
|---|---|
| `CacheStat getStat()` | 命中数/未命中数/淘汰次数/淘汰条目数/淘汰耗时（relaxed 快照；命中率 = hit/(hit+miss)） |
| `DiskIoStat getIoStat()` | 磁盘 IO 分相统计（序列化/文件写/flush/读/空洞/压缩…） |
| `DiskQueueStat getQueueStat()` | 磁盘线程队列深度/worker 忙碌观测 |

> 注意：`getIoStat`/`getQueueStat` 对应的探针计数当前已被 `#if 0` 禁用（Release 口径），
> 现返回**全 0 快照**；需要观测时删除 `disk.h`/`taskThreads.h` 中 `#if 0` 标记即可恢复。

## 5. 一段最小完整用法（串联全部接口）

```cpp
DEFINE_DATA_TYPE(MyData);                       // 1. 注册类型（MyData 需含 serialize/theSize/getClassName）

Controller db(100 * 1024 * 1024,               // 缓存 100MB
              500 * 1024 * 1024,               // 磁盘 500MB
              8, "mydb.dat");                  // 读池 8 线程

db.addData("k1", MyData{...}, true, std::chrono::seconds(0)).get();   // 2. 新增（永久）
db.persisVar("k1").get();                       // 3. 显式刷盘
SelResult r = db.selData("k1").get();           // 4. 查询（命中/回填）
db.modData("k1", MyData{...}).get();            // 5. 修改（标脏）
db.persisAll().get();                           // 6. 全部脏数据落盘
db.flushDisk().get();                           // 7. 清过期 + 刷盘
db.delData("k1").get();                         // 8. 删除（缓存+磁盘标记）
CacheStat s = db.getStat();                     // 9. 观测：命中/未命中/淘汰
```

# 第二部分：接口实现原理

## 1. 实现所依赖的底层模型（先讲清背景）

- **三层线程**：写线程（缓存写+淘汰，串行）、磁盘线程（inDisk 索引+文件 IO，串行=无锁区）、
  读线程池（命中读，并发）；所有慢 IO 只发生在磁盘线程，服务线程"只投递不等待"。
- **AsyncResult<T> 续延桶**：一段请求跨线程拆段执行，`shared_ptr<promise>` 跨段共享；
  段体异常统一 `set_exception`、线程停止 `fallback()` 兜底——保证 `get()` 永不永久等待。
- **磁盘记录**：86B 定长头（code/dataSize/时间/类型/名字）+ 实体；三种头码
  `VALID(0x5A)` / `DELETED(0xFF，删除=空洞)` / `BROKEN(0x00，残尾)`；
  两段式写：整条先以 BROKEN 落盘、写毕回写 VALID。
- **inDisk**：`名字→64 位偏移`；**holes**：`(容量,偏移)` best-fit 空洞索引（磁盘线程私有）。

## 2. 写路径公共流水线（appendRecord，所有持久化共用）

任何"把某 Val 写进磁盘"的调用最终走 appendRecord，决策顺序：

```
① 原位覆盖 tryOverwriteInPlace  旧槽放得下（等长或缩小且剩余≥86 写剩余洞头）
② 空洞复用 tryUseHole          holes 取 ≥需求的最小洞（best-fit），剩余≥86 再切洞
③ 容量执行                     curSize+本条 > maxSize → flushSync → 自动 reWrite()；仍超 MEMO_OUT
④ 尾部追加                     整条两段式写；更新 inDisk/curSize
```

失败即返回错误且**不更新 inDisk/curSize**；失败路径已做文件一致性回滚：尾部追加失败时
`clear → flush（先落盘同批此前记录）→ resize_file(dbName, 写入前 offset)` 截掉半条残渣；
原位覆盖失败时把旧 code + 旧 dataSize 写回原位置（槽恢复自描述长度）。详见设计分析 §7.1。

## 3. 各接口原理

### 3.1 addData（三段续延）

1. **段1（写线程）**：共享锁探测 `cache_db`，已有 → `KEY_EXIST`；
   锁外构造 Val（实体移进堆、`updateTime=now`、非永久计算 `expireTime`、标脏、算 `dataSize`）。
2. **段2（磁盘线程）**：查 `inDisk`（`containsVar`，微秒级）——磁盘已有 → `KEY_EXIST`（防重复新增）。
3. **段3（写线程）**：独占锁内重校验后 `emplace` + `curSize` 记账；锁外判断
   `sizeNow > memoSize` → 触发 `evict()`（全局采样淘汰，见 §6）。

### 3.2 modData（两路径续延）

1. 锁外算好新实体大小与 `shared_ptr`（只动一次堆）；
2. **缓存命中**（独占锁内）：替换实体指针 + 记大小差 + 标脏，旧实体移出锁外析构；
   不刷新 `updateTime`（写可能是冷数据）；
3. **缓存未命中**：段2（磁盘线程）查 `inDisk`，没有 → `FIND_FAILED`；
   有 → 段3（写线程）回填缓存（默认永久、标脏、大小记账），超容则淘汰。

### 3.3 delData

- **段1（写线程）**：独占锁内删缓存条目、减 `curSize`（`cacheHit` 记真）；
- **段2（磁盘线程）**：`disk->delData`：擦 `inDisk` → `markDeleted`（把该记录头 1 字节改
  `CHECK_DELETED`，dataSize 保留 → 整段登记为空洞可复用）→ 随任务 flush；
- 返回映射：磁盘 `FIND_FAILED` 但缓存删成功 → `SUCCESS`（数据从未落盘，删除已生效）；
  两处都无 → `FIND_FAILED`。

### 3.4 selData（两段：读池 → 磁盘线程）

1. **段1（读线程池）**：共享锁内查缓存 + 过期判定：
   - 命中且未过期 → `SUCCESS` + 实体指针（零拷贝），并把 `updateTime` 刷新为 now（relaxed 原子）；
   - 命中但已过期 → `EXPIRED`，同时投两条平级清理（写线程删缓存 + 磁盘线程删磁盘索引防复活），不等待；
2. **段2（磁盘线程，DISK_TASK）**（缓存 miss 时）：
   `disk->selData`：inDisk 取偏移 → 常驻句柄读回整条 → 校验头码/名字 → **零拷贝反序列化** →
   过期则直删磁盘索引（不回填）返回 `EXPIRED`；否则把读出的 Val 投**写线程后台回填**
   （沿用磁盘记录旧时间、`isDirty=false`，回填超容触发淘汰），并把同一实体指针返回给调用方。

### 3.5 persisData 四个重载（单条/带数据/批量×2）

共同点：**先清脏、后写盘、失败置回**。
1. 共享锁内拷贝 Val（短临界区）；2. 独占锁内把 `isDirty` 置 false（**写盘前**——
   防止写盘期间产生的新脏数据被误清）；3. `appendRecord` 走 §2 流水线；4. `flushSync()`
   （单条 = 一条一 flush；批量 = 循环写完后整批一次 flush）；5. 失败则锁内把 `isDirty` 置回 true。
   批量版遇 `MEMO_OUT` 立即中断（避免反复触发压缩），并统一回滚已清的脏标记。

### 3.6 flushDisk（维护式刷盘）

独占锁内全遍历缓存一次：
- **过期**：删缓存条目 + 收集名字 → 批量 `delData`（磁盘索引删 + 文件标记 + 批 flush，防过期复活）；
- **未过期脏数据**：收集名字 → 批量 `persisData`。
返回值是批量结果。

### 3.7 reWrite（两阶段原地压缩）

磁盘线程执行（自动压缩与手动调用同一实现）：
1. **准备**：删过期缓存数据（不搬移）；`flushSync` 提交此前缓冲追加（压缩读回安全）；
   `inDisk` 按旧偏移排序快照；
2. **阶段A**：只搬"缓存没有/干净"的 key —— 整条读旧写新、**长度不变**（写游标 ≤ 读游标，
   不会覆盖未读记录 = 根治"写覆盖读"）；
3. **阶段B**：缓存**脏 key** 最后写（旧区已无可读记录，变大也安全）；清脏前校验实体指针未变；
4. **阶段C**：缓存里 inDisk 没有的全新数据追加；
5. **收尾**：`flushSync` → `resize_file(dbName, 写游标)` 截断回收 → `curSize=writePos` →
   `clearHoles()`（紧凑文件无洞）。
   失败仅来自真实 IO 错误（中断交运维）。

### 3.8 观测接口

`getStat`/`getIoStat`/`getQueueStat` = 各模块原子计数器的 **relaxed 快照**（观测用途，不强一致）。
命中/未命中在 `selData` 热路径 relaxed 自增；淘汰计数在写线程 `evict()` 内累加；
磁盘 IO 分相与队列观测当前被 `#if 0` 禁用（详见第一部分 §4 说明）。

## 4. 过期与 TTL 的三判定点（被各读/维护接口寄生）

1. `selData` 命中时（过期 → EXPIRED + 双清理）；
2. `selData` 磁盘读回后（过期 → 磁盘直删索引，不回填）；
3. `evict()`/`flushDisk()` 开头全扫（批量清过期，防其占容量/从磁盘复活）。
统计口径：**缓存中存在即算命中（含过期）**；过期属 TTL 语义不算 miss（见 cache.h 注释）。

## 5. 容量执行如何从写接口内部触发

- **缓存**：addData/modData/回填插入后 `sizeNow > memoSize` → 锁外调用 `evict()`：
  先全扫清过期 → 全局采样（随机桶环形扫 + evictScore 大顶堆）→ 删前独占锁内重校验 →
  淘汰脏数据浅拷贝攒批、批尾一次投磁盘线程落盘；目标 = 降至 `90% × memoSize`（留余量防抖动）；
- **磁盘**：写路径容量检查（§2 第③步）：超 `maxSize` 先自动 reWrite 回收空洞，
  压缩后仍放不下 → `MEMO_OUT`。
