# memo_test2 性能预估（运行前推演）

> 状态：跑测试前的预估，供运行结果对照。偏差大 = 我们对成本的理解有错，值得追查。
> 依据：对代码路径逐跳的成本推演 + 量级估算，**不是**承诺值。

## 0. 口径与前提

- 环境：笔记本 SSD，无其它负载；**当前 VS 构建为 x64-Debug**——STL/模板无优化，所有路径比 Release 慢约 2~5 倍。Debug 数字只用于流程验证与相对比较，绝对性能请跑 x64-Release。
- **测量口径警告**：端到端延迟计时从请求前（含测试端 `makeData` 实体随机填充）到 `.get()` 返回。写档每次提交前都要现造一条 1K~10M 实体，**实体构造时间计入写延迟样本**——写档数字不是纯引擎耗时，QPS 会被测试端构造卡住（见 §2）。
- 引擎稳态前提：写线程单线程消化写任务；读池 4 线程；磁盘线程单线程，DISK_TASK 含文件 IO。

## 1. 单次路径成本分解（Debug 量级）

| 路径 | 成本构成 | 预估 |
|---|---|---|
| selData 命中 | 提交唤醒 ~1-3μs + 共享锁内 find/指针拷贝 ~1-3μs + future 回传 ~1-2μs（+statHit 原子自增 ~20ns） | **5~20μs** |
| selData miss 读盘 | 文件 seek/read + 反序列化（命中率档 200K 实体）→ 磁盘线程单线程串行 | **0.2~1ms** |
| modData 命中缓存 | 提交 + 新实体 make_shared + 独占锁内替换记账 + 快照 | **10~30μs** |
| evict 一轮 | 过期全遍历（锁内 ~300-450 条，固定成本）+ 采样循环删 ~10M 字节 | **1~3ms** |
| makeData 实体生成（测试端，写档瓶颈） | 8B/次 mt19937_64 填充；小档 ≤16K ~0.05ms，中档均值 ~0.5M ~1-2ms，大档 10M ~20-40ms；按档位分布（70/25/5）加权均值 | **1.5~2.5ms** |

## 2. 场景预估（x64-Debug）

| 场景 | 数据预设 | QPS | mean / P99 延迟 | 命中率 | evict 统计 | 主导瓶颈 |
|---|---|---|---|---|---|---|
| [1] QPS 全读 | 池 95M 全驻留 | **15~40 万/s** | 5-20μs / 50-200μs | ~100% | 0 次 | 读池 4 线程 + 锁 + future 传递 |
| [2] QPS 读7写3 | 池 95M + 注入器 | **1~2 万/s** | 读 ~10-40μs；写 ~1.5-2.5ms（构造主导） | 85~95% | 30~60 次，每次 1-3ms | 写请求被 makeData 构造限速（写 ≈ 3-5k/s → 总量 ≈ ÷0.3） |
| [3] QPS 全写 | 池 95M + 注入器 | **3~5k/s** | 写 ~1.5-2.5ms / P99 ~10-30ms（5% 大档实体 ~10-40ms 拉高尾部） | — | 30~60 次，每次 1-3ms | 8 worker 并行构造仍被 1.5-2.5ms 均值限速（8÷均值） |
| hit-rate 2x | 200M / 1000 key × 200K | **2~10k/s** | miss 主导 0.2-1ms | **40~50%（理论 45%）** | 数百次（churn，见 §3） | 磁盘线程单线程读回 200K |
| hit-rate 3x | 300M / 1500 key × 200K | **1.5~8k/s** | 同上 | **28~35%（理论 30%）** | 同上，更多 | 同上 |
| hit-rate 4x | 400M / 2000 key × 200K | **1~6k/s** | 同上 | **20~28%（理论 22.5%）** | 同上，最多 | 同上 |

预热耗时预估：QPS 档 95M ≈ 1-3s；命中率档 200M/300M/400M ≈ 3-15s（含 add 触发淘汰 + flushDisk 落盘屏障）。总运行 ≈ **4~6 分钟**（6 场景 × (预热 + 30s)）。

Release 预估乘数：读路径 ×3-5（可到 100 万/s 级）；写档受 makeData 影响仍限速（构造 ×2-3 → 全写 ~1 万/s）；命中率档受磁盘 IO 限制放大有限。

## 3. 命中率档的关键预期：淘汰-回填 churn

- 预热后缓存稳态 ≈ evict 目标 90M（容量比 90M/总量 = 45%/30%/22.5%，**这是理论命中率基准**，与冷热分布无关——读命中不刷新 updateTime，淘汰对访问频率无感）。
- 但 miss 会触发回填：每次回填 +200K，缓存从 90M 涨回 100M 又触发 evict → **evict 轮数 ≈ miss 数 / 50**。按 QPS 预估，命中率档 30s 内 evict 可达数百次，写线程 1-3% 时间在淘汰循环上——**淘汰对读吞吐的间接影响、以及回填数据被随机再淘汰的 churn，都会把命中率从理论值拉低几个百分点**，观测偏差大小是这次测试想看的核心信号。
- 双 miss 放大：回填是异步 push（写线程排队），同一 key 紧接着再读仍可能 miss → 命中率额外损失少量。真机后可用"二次读同一 key"验证回填延迟。

## 4. 关键观察指标与异常判据

| 指标 | 预期 | 异常（需追查） |
|---|---|---|
| [1] QPS | ≥10 万/s（Debug） | 个位数万/s → 锁或 future 传递路径异常 |
| 命中率 2x/3x/4x | ≈ 45/30/22.5% ±5pp | 显著偏低 → 淘汰/回填 churn 异常（evict 轮数爆炸）；显著偏高 → 淘汰偏袒了某些数据（非均匀） |
| evict-ratio（[2][3]） | <1-2%（淘汰次数 × 1-3ms / 30s） | >5% → 淘汰明显吃写线程：每轮 evict 固定全遍历太贵或注入过快 |
| evict 每次耗时 | 1-3ms | >10ms → 单轮删得太多（大数据全挤在同一轮）或锁等待异常 |
| [3] 写 P999 | ~10-40ms（大档构造） | 远高于此 → evict 窗口排队叠加（大实体被淘汰时构造 + evict 排队） |
| [1] 命中率 | ~100% | <99% → 池构建字节误超缓存或提前触发淘汰 |

## 5. 口径与设计取舍（跑完复盘用）

1. **写档 QPS 不是引擎上限**：被测试端实体构造限速。要看引擎写路径纯能力，需缩小实体或复用预构造实体（但会失去"写大数据"覆盖）。当前设计优先保证 1K~10M 跨度覆盖，接受写档数字偏低。
2. Debug/Release 差异可达 5 倍：同一次结论请固定构建配置。
3. 命中率理论值依赖"淘汰均匀、读不保活"：如果实测接近理论值，反证全局采样淘汰的均匀性符合预期；若系统性偏低，说明回填-churn 是主要代价（后续优化点：回填免淘汰窗口）。
