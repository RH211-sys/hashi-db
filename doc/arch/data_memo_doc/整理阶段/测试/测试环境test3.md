# 测试环境说明

> 对应代码：`test/memo_test/CacheBench/test3.cpp`（性能基准，memo_test3 目标）。
> 记录正式结果的文档：`整理阶段/测试/正式版Release.md`。
> 背景设计（为何 1:3:5、为何热子集）：见 `整理阶段/设计分析.md` §8、`实现阶段/二轮优化/优化1.md` §13.1。

test3 相对 test2 的核心差异是**写路径并发化压测**：对写请求用"环形在途窗口"
（每线程维持 `WRITE_INFLIGHT` 个在途 modData），稳态在途写 = `WORKERS × WRITE_INFLIGHT`，
真正压出多线程写能力；读请求仍同步 submit+get（读并发由读池承载）。
`WRITE_INFLIGHT = 1` 时退化为 test2 的同步写行为，可作对照。

```
cmake --build <build目录> --target memo_test3 --config Release
```

运行前须知：
- 每个场景先做**预热**（把数据集串行 add 进缓存并落盘，末尾 `flushDisk().get()` 作刷盘屏障），
  再测 30s；QPS 三档各自重建 `Controller`（互不污染），总时长 ≈ 3 ×（预热 + 30s）；
- 命中率档数据集更大（200~400MB 预热），会明显增加预热时长与 SSD 写入量；
- **场景开关在 main() 里手动切换**（当前为 QPS 三档开启、命中率档注释），改完需重新编译。

## 全局配置（test3.cpp 顶部常量，一次看懂）

| 常量 | 值 | 含义 |
|---|---|---|
| `MEMO_SIZE` | 100MB | 缓存容量上限（比例 1） |
| `DISK_SIZE` | 500MB | 磁盘容量上限（比例 5，≥ 数据集 + 压缩/写放大余量） |
| `WARM_BYTES` | 300MB | QPS 档预热数据集（比例 3 ≈ 1:3:5），约 717 keys |
| `POOL_THREADS` | 8 | 读线程池线程数 |
| `WRITE_INFLIGHT` | 4 | 每线程在途写深度（环形窗口；=1 退化为 test2 同步写） |
| `WORKERS` | 8 | 压测线程数 |
| `RUN_SECONDS` | 30.0 | 每场景固定测时（秒） |
| `INJECT_KEYS` | 60 | 写场景缓慢新增 key 数（≈24MB，数据集 300→~324M ≈ 1:3.2:5） |
| `INJECT_MS` | 500 | 注入间隔（≈2 key/s，模拟数据集缓慢增长，不做注入洪流） |
| `SAMPLE_CAP` | 200000 | 延迟样本蓄水池上限/线程 |
| `DB_NAME` | `test3_data.dat` | 数据文件（每场景重建） |

数据分布工具：
- `randSizeTiered`（预热池用）：单条 1K~10M 档位分布——70% [1K,16K] / 25% [16K,1M] / 5% [1M,10M]；
- `randSizeLogNormal`（命中率档用）：log10 均值 5.0、σ 0.5，钳位 1K~10M；
- `randSizeUpdate`（写请求用）：2^[12,20] 对数均匀 = **4K~1M**（均值 ~190KB）——削掉 10M 顶档，
  避免"随机写蹦出 10M 版本"的版本放大，贴近真实业务更新。

统计口径（`runLoad` + `printLoad`）：
- 热区 = key 池前 20%，80% 请求落在热区（80/20 热冷）；
- 写延迟 = 提交时刻到 `future.get()` 取回（端到端，含排队）；
- 分位由各线程蓄水池合并后排序取 P50/P99/P999（蓄水池采样省内存，不影响分布估计）；
- 输出只保留三行：`QPS | P99 us | hit rate %`（命中率 = hit/(hit+miss)，含过期命中口径；
  探测性明细 printDiskIo 已注释保留）。

## QPS测试

QPS 档共三档负载，各自 30s、互不污染；负载间差异只有 `readRate`（读概率，其余为 modData 热更新）。

| 档 | main 调用 | readRate | 数据集 | 注入 | 命中率预期 |
|---|---|---|---|---|---|
| 纯读 | `qpsScene("[1] QPS - read-only", 1.0)` | 1.0 | 热子集 ~70MB | 无 | ~100% |
| 7:3 读写 | `qpsScene("[2] QPS - read70/write30", 0.7)` | 0.7 | 全量 300M | 60 key 缓慢注入 | ~96% |
| 纯写 | `qpsScene("[3] QPS - write-only", 0.0)` | 0.0 | 全量 300M | 60 key 缓慢注入 | 0%（无读） |

> 1:3 数据集下"纯读全量" = 磁盘冷读（把磁盘线程打满、QPS 失真），所以纯读档只打
> **热子集（≤ 0.7×缓存 ≈ 70MB）**，语义 = 内存命中读吞吐；冷读/磁盘读行为由命中率档（hit-rate 2x/3x）覆盖。
> 含写场景用全数据集 + 注入，稳态把缓存顶在 ~90% 水位（写回缓存 + 淘汰 + 磁盘压缩都在被考验）。

### 请求分布与命中率机制（QPS 三档通用）

- **选 key = 热点 80/20 随机，不是全量随机**（`runLoad` 的 `hotSpot=true`，`pickIdx`）：
  80% 请求从前 20% key（热区）随机，20% 从后 80%（冷区）随机；热区比例与实际冷热业务对齐。
- **预热池 key 大小（QPS 档共用）**：`randSizeTiered` 档位分布——70% key 落在 [1K,16K]、
  25% 落在 [16K,1M]、5% 落在 [1M,10M]（大 key 撑起大部分字节；300MB ≈ 717 keys）。
  命中率档（hit-rate）改用 log-normal 1K~10M；写请求尺寸用 randSizeUpdate（4K~1M，见全局配置）。
- **命中率为什么能稳住**：命中会刷新 `updateTime`（relaxed 原子），`evictScore` 让常被访问的
  key 永远不在最冷档——即使回填超限触发淘汰，先被清掉的也是"本次没被访问的冷残留"，
  热 key 因命中保活而驻留；miss 只发生一次（首轮读盘回填后不再被淘汰）。
  这一机制是纯读/读7写3档高命中率的共同原因，区别只在"目标集合是否装得下"（纯读装得下→~100%，
  读7写3 是 300MB 全量、装不下→靠保活维持 ~96%）。

### 纯读

- **测什么**：缓存命中读的极限吞吐（读线程池并发 + 写优先读写锁共享读）。
- **触发**：`readRate = 1.0`；预热仍写满 300MB 数据集，但 load 池取热子集
  （shuffle 后取前缀累计 ≤ 70MB，量级约 186 keys / 70MB）。
- **请求模型**：只在这 186 个 key 上做 80/20 随机（热区 = 子集前 20% ≈ 37 key 承担 80% 请求）；
  子集是大小混合的（平均 ~0.38MB/key，偏中大型），不是全小 key。
- **命中率为什么 ≈ 100%**：① 子集 70MB < 淘汰水位 90MB（容量装得下）；
  ② 纯读无写，命中刷新热度 → 子集 key 保活，被淘汰的是预热遗留的非子集冷残留；
  ③ 唯一 miss = 预热后子集里尚未驻留 key 的首轮冷读，读回填后驻留到结束。
  实测 0.0012% miss ≈ 每 key 首轮 1~2 次冷读，与机制吻合。
- **参考结果**（正式版 Release，1:3:5 满盘档，WRITE_INFLIGHT=4）：
  `QPS 643575 | P99 58 us | hit rate 99.9988%`
- **看点**：命中读路径零磁盘 IO 时能打多高；P99 是否稳定（纯内存路径）。

### 73读写

- **测什么**：读写混合下的整体吞吐与延迟尾巴——磁盘线程（miss 读 + 刷盘 + 压缩）成为瓶颈时的表现。
- **触发**：`readRate = 0.7`；load 全数据集 + 注入线程缓慢 add 新 key（持续淘汰压力）。
- **写请求形态**：modData 热更新，尺寸 randSizeUpdate（4K~1M）；稳态在途写 = 8 × 4 = 32。
- **预期形态**：命中率 95%+（热集驻留），QPS 远低于纯读；P99 主要被磁盘 miss 读/压缩拖高。
- **参考结果**（同上档）：`QPS 124780 | P99 3787 us | hit rate 96.3445%`
- **看点**：写并发化是否带来收益（与 WRITE_INFLIGHT=1 对照）、空洞复用后压缩频率
  （追加字节 −61%、压缩 ~5% duty 的收益即在此档体现，见空洞删除段设计 §10）。

### 纯写

- **测什么**：写路径上限——每写都过"改缓存标脏 → 后台刷盘（覆盖/空洞复用/容量压缩/追加）"全链。
- **触发**：`readRate = 0.0`；全量 modData 热更新 + 注入。
- **预期形态**：命中率 0（没有读），QPS 低于混合档（写开销最大）。
- **参考结果**（同上档）：`QPS 49915 | P99 3863 us | hit rate 0%`
- **看点**：磁盘线程写/压缩吞吐天花板；P999 尾部与自动压缩触发频率的关系。

## 命中率档（补充说明；当前 main 中注释，跑 QPS 档后可切换）

```cpp
// main() 中临时切换：注释上面三行 qpsScene，取消注释下面 hitRateScene 行

// hitRateScene(3);   // 数据集 = 缓存 3x（300MB，比例 1:3:5）
// hitRateScene(4);   // 4x=400MB（≈1:4:5）可选对照；预热与 SSD 写入量大，慎跑
```

- **测什么**：冷热 80/20 + 数据量 2~3 倍缓存时的**命中率**与冷读吞吐（miss 回填/淘汰/磁盘读全链）。
- **数据形态**：总数据 = 缓存 × times（MB），每条大小 log-normal（1K~10M）；纯读 + 热区 20%。
- **预期形态**：命中率随数据量增大下降（2x ≈ 89%、3x ≈ 84% 量级）；QPS 反映"读池 + miss 磁盘读串行"的混合。
- **参考结果**（正式版 Release）：
  `2x: QPS 48356 | P99 2954 us | hit rate 89.1665%`
  `3x: QPS 38428 | P99 2867 us | hit rate 84.1872%`
- **语义提醒**：本档以大盘冷读/回填为主，与 QPS 档（命中为主）不可直接对拍；
  纯读档的"冷读/磁盘读"语义由本档承接。
