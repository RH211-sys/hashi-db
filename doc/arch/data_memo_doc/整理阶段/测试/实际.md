# memo_test2 性能实测总结（对照 预估.md）

> 状态：实测完成。三组数据：x64-Debug 一轮 + x64-Release 连续两轮（验证可重复性）。
> 对照基准：同目录 预估.md。判定口径：与预估同量级 = 正常；系统性偏差 = 列入 §4 待查。

## 0. 运行环境

- 笔记本，无其它负载；缓存 100M / 读池 4 线程 / 磁盘 500M / 8 压测 worker / 每场景 30s
- Debug 与 Release 各连跑 6 场景，总耗时 199~204s（预估 4~6 分钟，符合）
- **可重复性**：Release 两轮除 4x 场景外关键指标差 <3%；命中率两轮差 <0.05pp——测量稳定，下述以 Release #1 为准，#2 作验证

## 2. 与预估逐项对照

### [1] 全读：达标，量级内

- 实测 Debug 10.7 万/s、Release **81.6 万/s**；P50 8μs 落在预估 5-20μs 区间，P99 45μs 无长尾
- 命中 100%、0 次淘汰 ✓（判据：<99% 才算异常）
- 读池 4 线程 + 共享锁 + future 的读路径健康；Debug/Release 差 ~7.6 倍，超过预估 2-5 倍上界（见 §4-4）

### [2] 读7写3：吞吐低于预估一个数量级，尾部异常

- 实测 Release 2,375-2,866/s（预估 1~2 万/s）、Debug 972/s（预估同档）——**比预估低 4~8 倍**
- 命中率 86.8-87.5% ✓（预估 85-95%）；P50 21μs 读延迟健康
- **尾部异常**：P99 90~98ms、P999 250~300ms（Release）——远高于预估；且 evict 每轮 0.26-0.30ms 是全写场景的 ~7 倍（混写场景淘汰对象含大量脏实体，dirty 分支代价更高，与设计预期方向一致但量级待核）
- **反直觉点**：写占比更低的 [2] 总吞吐反而低于 [3] 全写（见 §4-2）

### [3] 全写：Release 落在预估下限内，Debug 偏低

- 实测 Release 2,800-3,392/s（预估 3~5k/s 下限附近）、Debug 882/s（预估 3~5k/s 的 1/4）
- P50 112-134μs、mean ~2.4-2.9ms、**P999 40-42ms** —— P999 与预估"10-40ms（大档实体构造+搬运）"吻合，尾部由 5% 的 1M-10M 大实体主导
- evict 开销健康：Release evict-ratio 0.06%，每轮仅 0.042ms（预估 Debug 口径 1-3ms，Release 快 1-2 个数量级），淘汰对写吞吐几乎无影响 ✓

### hit-rate 2x/3x/4x：吞吐达标，命中率系统性显著高于理论

- QPS：Debug 1.0-1.6 万/s（预估 2~10k，略超上界）；Release 1.6-3.1 万/s；延迟 mean 0.25-0.68ms、P99 ~1-2.6ms，由 miss 的磁盘读回 200K 主导，符合"0.2-1ms/次 miss"的成本预期
- **命中率实测 78.8% / 66.5% / 56.6%**，两轮 Release 差异 <0.05pp，稳定可复现。对照预估基准 45% / 30% / 22.5%（= 90M 淘汰目标/总量）**一致高出 ~30pp**——预估基准是"读命中零写 → 淘汰对访问频率无感"假设下的纯容量下限，漏计了 miss 回填保活效应，实测高出下限属正常（机制见 §4-1）
- 淘汰统计与"回填-淘汰 churn"机制自洽：evict 条目 ≈ miss 数（约 1:1），evict 轮数 ≈ miss/50（每 50 次回填触发一轮"100M→90M"批量淘汰），Debug/Release 下该比例一致 → 淘汰确实按设计持续发生、稳态驻留没有因命中率异常而停止运转
- evict-ratio：Release 0.86-0.94%（健康）；**Debug 8.4-11.4%**（Debug 下淘汰轮均 1-2ms × 上千轮，确实占用写线程可观时间）
- 2x/3x 两档 miss 绝对次数几乎相同（~20 万/30s），QPS 差异完全由命中率差异造成；4x 两轮 QPS 波动 ±25%，其余场景稳定（SSD/后台状态影响，见 §4-5）
- **注（跑后调整）**：命中率档原用固定 200K/条以便对照纯容量基准，实测暴露基准假设不完整（见 §4-1）；现改每条大小对数正态随机（log10 均值 100K、σ 0.5，覆盖 1K-10M），将重跑观察大小混合下命中率相对下限的抬升（预期高于本轮的 78.8/66.5/56.6）

## 3. 关键结论

1. **读路径达标**：Release 全读 81.6 万/s、P50 8μs、P999 156μs，共享锁 + 指针零拷贝 + 统计零写（原子自增除外）的读链设计符合预期。
2. **淘汰机制开销健康**：Release 下 evict 每轮 0.04-0.3ms、各场景 evict-ratio ≤0.94%，全局采样淘汰不是写路径瓶颈；Debug 下每轮 1-2ms、hit 档 ratio 8-11%，是 Debug 构建特有问题（§4-3）。
3. **写档吞吐由实体搬运主导**：[3] Release P50 仅 ~120μs 但 mean ~2.4-2.9ms、P999 40ms——中位数与均值的巨大落差来自 25% 中档 + 5% 大档实体（构造 + 写线程内拷贝），与预估"实体大小分布主导尾部"一致；引擎纯写能力不能从本测试数字直接读出（构造与搬运混在测量内）。
4. **命中率高于纯容量下限属正常**：预估基准（90M/总量）漏计 miss 回填保活——回填刷新 updateTime、淘汰删最旧 → 热区高频 key 持续保活，冷热 80/20 放大该效应；实测 78.8/66.5/56.6% 与该机制一致（§4-1）。数据分布已从均匀 200K 改为对数正态随机，重跑检验"大小差异大 → 命中率更高"。
5. 测试框架本身验证可靠：预热 shuffle、flushDisk 屏障、蓄水池采样、注入器均按设计工作，三组数据自洽（hit+miss=请求总数、evict 条目与 miss 守恒、轮数与容量模型自洽）。

## 4. 遗留疑点（现象清单，供后续追查，本次未定位）

1. ~~命中率系统性偏高~~（**已解释，非疑点**）：预估把基准定为"淘汰目标 90M / 总量"，前提是读路径零写 → 淘汰对访问频率无感；但 **miss 回填本身刷新 updateTime**，淘汰删最旧 → 高频 key（80% 流量打的热区）经反复回填持续保活，热区驻留率远超均匀假设，命中率系统性高于纯容量下限是预期行为。可验证预测：命中率档访问改为均匀（hotSpot=false）后，命中率应回落趋近 90M/总量下限。
2. **[2] 吞吐反低于 [3]**：混读写下写线程负载更低（~30% × 写入），总 QPS 却低于全写档，且 P99/P999 恶化 3-4 倍（90ms/300ms 级）——混读场景存在额外尾部来源（候选方向：读池与写线程的锁竞争、磁盘读回/回填与写任务在写线程的叠加、注入大实体对写线程的冻结）。
3. **Debug hit 档 evict-ratio 8-11%**：Debug 下淘汰轮均 1-2ms × 千轮级，写线程 8-11% 时间在淘汰上——Debug 特有的膨胀（Release 同场景仅 0.9%），与 §2 观察一致。
4. **Debug/Release 差异达 7.6 倍**（读路径），超出预估 2-5 倍；写与磁盘受限档差异仅 1.3-3 倍——CPU 受限路径的 Debug 无优化代价比预估更大。
5. **4x 场景两轮 Release QPS 波动 ±25%**（15,763 vs 11,808），其余场景 <3%；该场景磁盘驻留数据 400M 接近磁盘负载上限，波动来源待核。
