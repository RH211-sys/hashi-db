# 架构总结

本次存储层 —— 一个面向**"总数据量超出缓存、热工作集可驻留、读多写少、单条数据大小差异大"**场景的**缓存中间件存储层**（Cache + Disk 两级），
最终定型为：**内存热层 + 单写线程 + 追加式磁盘日志 + 空洞复用 + 全量压缩**的形态。
本文档是对该存储层最终状态的架构梳理与优化结论总结（整理阶段收尾用）。

---

## 1. 定位与总体形态

- **两级存储**：`Cache`（内存热层，容量 memoSize）+ `Disk`（持久化文件层，容量 maxSize）。
  命中走内存零 IO；未命中才读磁盘；写先改缓存标脏，异步刷盘。
- **淘汰**：使用淘汰算法，全局采样淘汰（无 LRU 链表），容量超限时在写线程内阻塞执行到达标。
- **磁盘**：追加式日志文件，记录 = 定长 86B 头 + 实体字节；删除/覆盖产生的空间**显式化为空洞段并可复用**，
  文件逼近上限时做**整文件两阶段原地压缩**。
- **异步形态**：存储层所有后台任务均在专属线程执行，服务线程"只投递不等待"，
  接口返回 `std::future`，只有最终调用方 `get()` 才阻塞。磁盘慢 IO 永远不会占死写线程/读线程池。
- **崩溃语义**：两段式写（先写校验码 `CHECK_BROKEN`、写完后校验码改为 `CHECK_VALID`）+ 批 flush；
  残尾在重建时截断。冷启动 loader（顺序扫描重建索引）后置到管理层阶段实现。

## 2. 线程模型与并发结构

四类执行者，职责单一、各有归属：

| 执行者 | 数量 | 职责 | 备注 |
|---|---|---|---|
| `ReadPool` 读线程池 | N（压测=8） | 执行缓存读链：共享锁命中读，命中纯内存零 IO | 可多个并发执行 |
| `WriteThread` 写线程 | 1 | 缓存写任务串行：add/mod/del 的缓存侧 + 全局采样淘汰 `evict()` | 写串行避免 `unordered_map` 结构竞争/rehash 迭代器失效 |
| `DiskThread` 磁盘线程 | 1 | 磁盘索引（inDisk 查重/查存在，微秒级）文件 IO（读盘/刷盘/压缩，毫秒级） | 双队列（CACHE_TASK/DISK_TASK）差距调度，缓存任务优先 |
| 上层调用方 | — | 消费 future | 唯一允许阻塞等待的一方 |

- **磁盘单线程 = 天然无锁区**：`inDisk`（内存索引）、文件句柄、空洞索引 `holes` 只被磁盘线程读写，
  不需要任何锁。
- **读并发**：缓存读并发由 `WritePrefMutex`（写优先读写锁，参数 batchSize/upDisEdge/minDisEdge）保证；
  写路径的续延链分段在写线程 ↔ 磁盘线程之间交替投递，临界区被压到最小（锁内只做查/指针交换/记账）。
- **磁盘线程内部调度**：缓存任务（快）优先，`taskGap` 到达上边缘且有待处理磁盘任务时让位处理一个磁盘任务
  （慢 IO），防止慢任务把快任务饿死、也防止缓存任务无限积压。
- **AsyncResult<T> 续延桶**：一段请求分多段投递，`shared_ptr<std::promise>` 跨段共享；
  段体异常统一 `set_exception`、线程停止时 `fallback()` 兜底——保证任何情况下调用方 `get()` 不会永久等待。

## 3. 模块划分（Controller / Cache / Disk）

```
Controller（组装 + 统一异步入口，透传 future）
   ├─ Cache    cache_db: unordered_map<string, Val>   ← 内存热层
   │            + WritePrefMutex + 容量记账 + evictScore 全局采样淘汰 + 统计
   ├─ Disk     常驻文件句柄 + recBuf 记录缓冲          ← 持久化层
   │           + inDisk(名→64位偏移) + holes(best-fit 空洞索引)
   │           + 两段式写/空洞复用/自动压缩
   ├─ ReadPool / WriteThread / DiskThread               ← 线程
```

### 3.1 Cache（内存热层）

- 条目结构 `Val`：
  `typeName`（类型名）、`dataSize`、`isPermanent`、`expireTime`、`updateTime`、`isDirty`、`entity`。
  - `entity = shared_ptr<any>`：写入时实体**移进堆一次**，命中/回填与缓存共享同一实体，**零拷贝**；
  - `updateTime`：µs since epoch 的 **relaxed 原子量**（读命中热度近似）。命中路径在共享锁内
    `store(µs)`——消除了多读者并发写非原子 `time_point` 的数据竞争；
  - `Val` 含原子成员，拷贝/移动均为自定义四件套（原子字段 relaxed 取值）。
- **全局采样淘汰 evict()**（无 LRU 链表）：
  随机抽样 `cache_db` 的若干桶 → 按 `evictScore` 建优先队列 → 淘汰分数最高的条目，
  循环直到容量达标（写线程内执行，阻塞语义，防止"刚插入就超限"）。
  分数 = 距上次读命中/插入的**档位 × 档距 + ln(大小)**（大条目优先淘汰，冷数据优先淘汰）。
  淘汰的脏数据 fire-and-forget 刷盘。
- 过期是 TTL 语义：命中但过期按未命中处理（读走磁盘、并提交磁盘删除）；统计口径上过期不算缓存 miss。

### 3.2 Disk（持久化层/磁盘模块）

- **常驻文件句柄** `std::fstream file`（惰性打开/异常重建 `ensureFileOpen`，读+写复用，免每次 open/close）；
  单条记录组装缓冲 `recBuf`（定长头 + 实体字节，序列化直写缓冲、整条一次 `write`）。
- **内存索引 `inDisk`**：`unordered_map<string, long long>`，记录名 → 文件偏移（**64 位**，数据文件可超 2GiB）。
- **空洞索引 `holes`**：`std::multiset<pair<long long,long long>>` =（段容量, 偏移）按容量升序，
  **best-fit**（`lower_bound`）取用。容量口径统一为 86 + dataSize。
- 所有磁盘操作经磁盘单线程执行（`appendRecord/tryOverwriteInPlace/tryUseHole/addHole/markDeleted/...`）。

### 3.3 Controller

- 组装 `Cache/Disk/ReadPool/WriteThread/DiskThread` 并注入依赖（Cache 持三者 shared_ptr、Disk 持 Cache 的
  weak_ptr，无循环引用）；`bind()`/`setCache()` 双向绑定。
- 统一透传异步 API：`addData/modData/delData/selData/persisVar/persisAll/flushDisk/reWrite` 均返回 future；
  `flushDisk` 直接投递磁盘线程执行；观测快照 `getStat/getIoStat/getQueueStat`。

## 4. 磁盘记录格式（86B 定长头 + 实体）

```
┌ code(1) ┬ dataSize(4) ┬ time(17) ┬ type(32) ┬ name(32) ┬ 实体(dataSize 字节) ┐
│         │ 实体字节数 │ 更新8+过期8+永久1 │ 类型名 │ 变量名   │ cereal 二进制  │
└─────────┴───────────┴──────────┴──────────┴──────────┴──────────────────┘
```

- 整条记录长 = **86 + dataSize**；头为**活记录与洞段统一格式**，顺序扫描跳读规则只有一种。
- 状态码（`protocol.h`）：
  | 码 | 含义 | 顺序扫描行为 |
  |---|---|---|
  | `CHECK_VALID`(0x5A) | 活记录 | 读入，`offset += 86 + dataSize` |
  | `CHECK_DELETED`(0xFF) | **已删 / 空洞段（同一语义，可复用）** | 跳过，`offset += 86 + dataSize` |
  | `CHECK_BROKEN`(0x00) | 残尾（写一半崩溃） | 文件截断到此处 |
- **两段式写**：先整条写 `CHECK_BROKEN`，写毕把首字节回写 `CHECK_VALID`；
  flush 按所在任务批执行，不逐条 flush。
- 洞头实际只写 **code + dataSize 共 5B**（跳读/复用只需这两字段，其余头字节保留旧残留不影响 loader）。
- 序列化（使用`cereal`开源技术）：类型注册表 `typeReg`（typeName → toBytes/fromBytes，启动注册、运行期只读）；
  `toBytes` 序列化**直写记录缓冲流**、`fromBytes` 用只读内存流 `MemInBuf` 让 cereal **直接在读出字节区上解析**，
  读写两侧均无 stringstream 整块中间拷贝。

## 5. 数据流

### 5.1 写路径（addData / modData / delData）

- `addData`（新增）：续延链 **段1（写线程）共享锁查缓存** → **段2（磁盘线程）查磁盘索引 inDisk**
  （缓存、磁盘任一已有即 `KEY_EXIST` 冲突）→ **段3（写线程）独占锁插入 + 记账** → 超限则锁外 `evict()`。
- `modData`（整体修改）：锁外先算好新实体；**独占锁内命中即替换指针并标脏**（旧实体移出锁外析构）；
  缓存未命中则段2（磁盘线程）查 inDisk，存在 → 段3（写线程）回填缓存标脏（磁盘数据默认永久）；
  都不存在 → `FIND_FAILED`。命中替换不刷新热度（写的可能是冷数据）。
- `delData`（删除）：整链在写线程：缓存删 + 磁盘线程标删（见下）。

### 5.2 磁盘写顺序（persisData / 淘汰刷盘统一入口）

磁盘线程内，对每条要落盘/更新的记录按以下优先级（记录先由 `buildRecord` 组装进 recBuf）：

```
① 原位覆盖 tryOverwriteInPlace —— 有旧记录且 新总长 V ≤ 旧槽 T：
       V==T        覆盖即可（等长，无洞产生）
       T−V ≥ 86    覆盖 + 偏移 V 处写 DELETED 洞头（dataSize=T−V−86）→ 剩余登记为洞
       T−V ∈ (0,86) 剩余不足一个洞头 → 回退追加（否则链断重建错位）
② 空洞复用 tryUseHole —— 无合适覆盖/旧记录在洞中：
       holes.lower_bound(V) 取不小于需求的最小洞写入；
       剩余 ≥86 → 再写 DELETED 洞头登记剩余洞；剩余 <86 → 整段利用（浪费 <86B）
③ 容量检查：maxSize>0 且 curSize+本条 > maxSize → 先 flushSync 提交已缓冲追加，
       再自动压缩 reWrite()（回收空洞碎片、截断）；压缩后仍放不下 → MEMO_OUT(300)
④ 尾部追加 appendRecord —— 追加位写整条（两段式校验码），更新 inDisk/curSize
```

- 旧版本被追加/复用取代时，旧槽一律 `markDeleted`（1 字节改 DELETED，保留旧 dataSize）**显式变洞并登记**，
  顺带修复"旧版本 VALID 残留会被 loader 复活"的隐患；
- 写洞失败时把该段恢复为 DELETED 并放回索引、回退追加（复用失败恢复）。
- 覆盖前需读旧头 dataSize（磁盘线程读(dataSize大小4B)）。
- 采用 best-fit 而**不用 max-heap/first-fit**：大洞不被切成碎片、保留给大记录（记录 1K~10M 严重不均时碎片最少）。

### 5.3 读路径（selData）

- 链在**读线程池**执行：共享锁内查缓存——**命中直接返回实体指针**（零拷贝，与缓存共享同一实体，
  只读约定），并把热度 `updateTime` relaxed 刷新为 now；命中过期只提交清理任务不等待。
- **未命中**（miss）：投递磁盘线程 `selData` 单条——inDisk 取偏移 → 常驻句柄读回整条 →
  零拷贝反序列化 → 过期判定（过期则直删磁盘）→ 回填交**写线程**后台处理（实体指针保活）。
  只有调用方 `get()` 阻塞等待结果。
- 观测点：命中/未命中计数 relaxed 自增；miss 去向分类（inDisk-miss / file-fail 细分 check/name/eof/type/open / ok）。

### 5.4 压缩（reWrite：两阶段原地，唯一回收手段）

- 触发：**容量硬上限**——追加将超 maxSize 前自动执行（见 ③）。整体策略"贵但少"：整文件重写一次把所有洞收拢。
- 执行（全在常驻句柄上，末尾 `resize_file` 截断，成功后清空 holes 索引）：
  - **阶段A**：只搬"缓存没有 / 缓存干净"的 key —— 整条读旧写新、**长度不变**，写游标 ≤ 读游标，
    永远不会覆盖后面还没读的旧记录（"写覆盖读"的根治）；
  - **阶段B**：缓存里的**脏 key** 最后写——此时旧区已无待读记录，可安全覆盖/追加；清脏前校验实体指针未变
    （防并发 mod 后误清）；
  - **阶段C**：inDisk 没有的全新缓存数据追加写入。
- 失败只可能来自真实 IO 错误（返回错误交运维）；压缩前 `flushSync` 保证已缓冲的追加先落盘（读回安全）。

## 6. 正确性机制清单（历轮关键修复的沉淀）

| 机制 | 解决的问题 |
|---|---|
| `updateTime` 原子化（µs, relaxed） | 多读者并发写同一非原子字段 = 数据竞争 UB；命中路径跨核写缓存行 |
| 偏移全链路 64 位化 | 数据文件超 2GiB 后 `int` 偏移溢出为负 → 磁盘读全失败 |
| maxSize 容量执行 | 此前从未生效、文件无界增长（几十 GB）；超限先自动压缩，仍超返回 MEMO_OUT |
| reWrite 两阶段原地压缩 | 原地压缩"写覆盖读"→ 压缩反复失败（fail 6348/6351）、索引陈旧 |
| 删除 = 空洞（CHECK_DELETED）+ best-fit 复用 | 整版本追加只增不减 → 高频顶上限全量压缩；压缩频率/盘写大幅下降 |
| AsyncResult 异常/停止兜底 | 线程池吞异常/线程停止会令调用方 `get()` 永久等待 |
| 反序列化零拷贝 + miss 读复用常驻句柄 | 单条磁盘读 avg ~1,480µs → ~750µs 以下 |
| 序列化直写连续记录缓冲、整条一次 write | 每写多条 write/两轮整块拷贝（stringstream→string→vector） |

## 7. 观测与统计（性能归因用，非功能）

- `CacheStat`：hit / miss / evictCnt / evictItems / evictUs（命中/未命中热路径 relaxed 自增）。
- `DiskIoStat`：磁盘 IO 分相——writeCnt/writeBytes（追加量）、buildUs（序列化）、fileUs（文件写）、
  flushUs/flushCnt、readCnt/readUs（磁盘读单条 avg）；miss 归类探针（selCalls / selInDiskMiss /
  selFileFail 细分 selFailCheck/Name/Eof/Type/Open / selOk）；compact（次数/失败/耗时/前后文件大小）、
  overwrite（总数/等长/缩小）、hole（段数/字节快照、复用次数）。
- `DiskQueueStat`：提交量 / 队列积压深度（avg/max）/ worker 执行数与忙碌耗时（busy %）。
- **探针治理**：miss 去向分类与失败现场打印等观测代码已用 `/* */` 注释保留（未删除），
  正式输出只保留 **QPS / P99 / 命中率** 三行，符合"测试点代码已注释"的 Release 口径。

## 8. 基准测试结论（正式版 Release）

> 数据出处：`整理阶段/测试/正式版Release.md`（探针代码注释后的正式版跑批）。

### 8.1 压测编排比例 缓存:数据集:磁盘 ≈ 1:3:5（按 Redis Auto Tiering 容量建议推导，**非行业标准值**）

- 1:3:5 不是查到的行业公式，是本项目**为压测推导的编排值**：按 Redis Enterprise Auto Tiering 的
  容量建议（适用"工作集 << 总数据 + 热点"；RAM 至少放全部 value 的 ~20%；闪存 ≥ 总数据 +
  写缓冲/写放大余量）与 80/20 热集假设换算——缓存 100M ≈ 数据集 300M 的 33%（贴合"RAM≥20% 值 +
  热集余量"），磁盘 500M ≈ 1.67× 数据（含压缩/写放大余量），凑整为 1:3:5；Pika 为反例（无此分层模型）。
- test3 定型参数：缓存 **100MB**、数据集 **~300MB**、磁盘 **500MB**（≥ 数据集 + 压缩/写放大余量）；
  `POOL_THREADS=8`、`WRITE_INFLIGHT=4`（每线程在途写深度，=1 退化为 test2 同步写）。
  写请求尺寸 4K~1M 同量级（削掉 10M 顶档的版本放大）；新增 key 缓慢注入（60 条 / 500ms 间隔 ≈ 2 key/s）。
- 纯读档说明：1:3 比例下"全数据集读"= 磁盘冷读（失真），故纯读档限定在 ≤70MB（≤0.7×缓存）热子集，
  语义为"内存命中读"；冷读/磁盘读语义归入命中率场景。

> 依据出处：[Redis Enterprise Auto Tiering / Flex 官方文档](https://redis.io/docs/latest/operate/rs/databases/flash/)：
> 适用场景"working set << dataset（RAM 高命中率）"；建议"RAM 至少存放全部 value 的 ~20%"；
> 闪存空间须 ≥ 数据库总量（RAM+Flash），余量用于写缓冲与**写放大**。本文 1:3:5 即按该模型缩放
> （缓存 100M ≈ 数据集 300M 的 33%，命中率场景实测 84~96% 高命中；磁盘 500M ≥ 数据 + 压缩/写放大余量）。
> Pika/PikiwiDB 为反例（面向全量落盘的磁盘型 KV，非"RAM≥20% 热层"定容模型，见 [PikiwiDB 讨论](https://github.com/OpenAtomFoundation/pikiwidb/discussions/2052)）。

### 8.2 结果（无网络因素，裸接口）

**① 无预热数据（缓存充足：数据全量热驻留；下表为详细档 132 keys / 30MB）**

| 场景 | QPS | P50 | P99 | P999 | 读命中率 |
|---|---|---|---|---|---|
| read-only | 818,778 | 5µs | 90µs | 372µs | 100% |
| read70/write30 | 394,017 | 5µs | 603µs | 1,318µs | 100%（读口径） |
| write-only | 156,807 | 174µs | 635µs | 2,977µs | 0%（无读） |

> 另一轮对照（344 keys / 101MB）：650,117 / 361,925 / 145,117，同量级。
> 缓存充足档：无淘汰（evict 0）、无磁盘读（disk-read 0）、零压缩——cache 全驻留，
> 主要反映"纯内存命中读/写"上限（read70·30 的 11.8M 请求里读 ~8.3M、写 ~3.5M）。

**② 缓存爆满（1:3:5；717 keys / 301MB 预热，WRITE_INFLIGHT=4；下表为详细档）**

| 场景 | QPS | P50 | P99 | P999 | 命中率 |

### 8.3 读数口径提醒

- 命中 = 缓存中存在即命中（含过期——过期是 TTL 语义，不算缓存未命中）；读盘成功与否都算缓存 miss；
- 绝对值受构建模式（Debug/Release）与机器影响大，**横向比较看同轮次相对变化**；
- QPS 档与命中率档是不同场景（命中率档以大盘冷读/回填为主），不可直接对拍。

## 9. 当前瓶颈与遗留工作

- **当前瓶颈（按数据归因）**：磁盘线程在混合场景约 ~98% 忙碌，构成以**磁盘读为主**（读 ~20s/30s，
  单条 ~215µs 上下）。写/压缩在空洞复用 + 自动压缩后已降到零头。下一步候选：**读并行 v2（之前设计的读并行实测无效，可能是被其他因素干扰的原因）**
  （每线程缓存句柄、inDisk 并发读安全、压缩与并发读互斥或"写新文件+原子换名"），结构级改造，需单独一轮设计。
- **压缩尾巴**：cap 触发时整块全量压缩单次占住磁盘线程上百 ms → P999 尾部大；根治依赖调度/并发改造。
- **写放大**：淘汰新版本整条追加 + 压缩全量重写，大记录高 churn 下盘写字节 ≈ 数倍活跃数据——
  追加式日志 + 全量压缩的结构成本。
- **遗留（后置）**：
  1. 冷启动 loader（管理层阶段）：按空洞删除段设计 §7 顺序扫描一次重建 inDisk + 空洞索引 +
     截断残尾/校验损坏——生产使用前必须补齐（否则删除/洞与索引不同步会丢空间信息）；
  2. （可选）软水位压缩：空洞占比超阈值提前压缩，待复用稳定后评估。
