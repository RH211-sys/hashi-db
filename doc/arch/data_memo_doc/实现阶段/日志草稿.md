## 再次梳理大致架构和需求，以及要做的待办

### 整体梳理

读线程池只用来读取缓存的资源，配合lock_shared
写线程只用来更新缓存的资源，配合lock
磁盘线程仅用来操作磁盘的索引缓存和持久化文件，后台线程

上层调用后，存储引擎异步处理，返回future，上层需要的时候用get阻塞等待

```
上层（以selData为例）：
auto res = contoller.selData(...);		// 异步处理
...一系列操作
if(res.get().resCode == SUCCESS) {		// 阻塞等待结果
	cout << res.get().entity << endl;
}

res:future对象
struct selRes{		// 以查询结果的返回对象为例
	int resCode;
	std::any entity;
}
可能有的返回对象只有操作码，不用selRes
```

所以，`controller`，`cache`，`disk`，以及对应的线程池和单线程返回的都是`future<selRes>`或者`future<int>`，如果是一组查询的话能可能还要用`future<vector<selRes>>`，不同操作对应的返回类型可能不一样

- sel: `future<selRes> / future<vector<selRes>>`
- del: `future<int>`
- add: `future<int>`
- mod: `future<int>`
