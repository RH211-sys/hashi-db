# 设计更改

## 磁盘模块

1. 线程磁盘用双队列（缓存任务队列 + 磁盘任务队列），设置任务处理数量差距上下限

2. 磁盘模块的`inDisk`定义为`std::unordered_map<std::string, int>`，删除`delDisk删除标记`仅存储数据在单文件中的偏移量

   > 校验码(1B) + 数据实体大小(4B) + 时间信息(17B) + 变量名(定长 NAME_LEN) + 数据实体

   变量名是变长的，需要设置上限

   可能存在追加写一半崩溃的的现象，我需要设置一个`校验码`，来校验数据完整性，不完整的数据不读取

   用单文件存储数据，方案如下
   将数据存储+ 索引存储合并到一个数据，数据格式如下： 

   ```
   校验码(1B) + 数据实体大小(4B) + 时间信息(17B) + 变量名(定长 NAME_LEN) + 数据实体
   时间信息(顺序列出)：
   创建时间(8B, 和 std::chrono::system_clock::time_point 有关)
   过期时间(8B, 和 std::chrono::system_clock::time_point 有关)
   是否永久(1B)
   ```

   - 校验码的话先写一个无效码，然后等数据写完后，再改成有效码

   ```
   偏移+0: [校验码 1B] [数据大小 4B] [创建时间 8B] [过期时间 8B] [是否永久 1B] [变量名 NAME_LEN] [实体 dataSize 字节]
            └────────────── 头部固定 22+NAME_LEN 字节 ──────────────┘ └── 实体(大小由 4B 字段给出) ──┘
            
   重建读头:先读偏移+0 那 1 字节 → CHECK_BROKEN 截断 / CHECK_DELETED 按大小跳过 / CHECK_VALID 读入
   跳读:下一条 = 当前 + 22 + NAME_LEN + 数据大小
   删除:写偏移+0 为 CHECK_DELETED(数据完整,大小可信)
   全局协议常量：
   const char CHECK_VALID   = 0x5A;	// 完整数据
   const char CHECK_BROKEN  = 0x00;	// 不完整数据，需要跳过
   ```

   - 边长变量名建议设置为 64，写不满补 `\0`，超过长度限制返回失败码

   **为什么不用索引文件和数据文件**：减少磁盘IO次数

   **为什么不要删除码和`delDisk`**：允许崩溃回溯，并减少项目复杂度

   

3. 重写机制详解：直接把inDisk中的所有数据覆盖旧文件就行，然后清空后面的数据 
   我们需要对偏移量进行排序，从偏移量小的开始遍历，

   - 如果这个数据缓存中存在，则直接持久化(不管是不是脏数据都应如此)，然后缓存中该数据`isDirty`设置为`false`
   - 如果不在，则从磁盘中找到该数据后，移动到前面
   - 如果**重写时崩溃**：会出现数据全损，这是极端情况，出现概率极小，交给运维处理即可（**事先备份文件**）
     若需要防止重写崩溃，那么重写的时候只能开一个新文件，删除旧文件，这样会将磁盘利用率降低一半，而这种方式用于防止极端情况大材小用
     后面如果真需要防止重写崩溃，**理应做文件备份（可在管理层做文件备份）**

   全部完成后清空后面的数据

   > （一般不考虑极端情况，给运维 人员自己去维护，而且到时候我会在其他层设置配置文件，维护人员可以配置分配的磁盘空间大小）

4. `数据序列化`：序列化使用`cereal`技术，它能对任意数据类型进行序列化和反序列化操作，这需要用户提前写好序列化方法声明

## 缓存模块

基本不变，主要是实现过程中C++的语法特性和其他实现逻辑

1. future判断和引用修改的区别

   这个意思是：如果我调用一个接口，这个接口存在返回值（如返回操作是否成功），那么我要用future对象接收还是用引用传递，

   ​    引用传递：一定要在同步的场景，如果调用接口后，该线程继续执行代码，那么引用对象可能会因为结束生命周期，被回收，而接口函数此时再向这个引用对象写入数据就会崩溃，这就是悬垂引用
   ​    future：更适合异步的场景，即异步等待接口执行，等待需要取这个数据的时候再调用future.get阻塞取数据即可

2. 写优先，读不饥饿读写锁

   核心逻辑：加的`边界处理变量`(`readSubWrite`/`upDisEdge`/`minDisEdge`/`batchRemain`)和`批放行`机制

    读：`unlock_shared`和`lock_shared`，保证读并发（读线程共享临界资源），每完成一个任务差距+1
           达到上限，读太多且无写者排队：差距清零，重新统计；同时关闭放行批
           无写者排队 -> 直接进；有写者排队 -> 需持有批名额才可进批名额：当处理的写任务过多时，会给读任务让出一部分名额，防止读饥饿
       写：`lock`和`unlock`，保证读串行，每完成一个任务差距-1
           达到下线，放出一批名额给读任务
       整体保证读写互斥，写优先

3. `addData` 参数:`isPermanent` + `during`(持续时间),过期时间 = 创建时间 + during

4. 所有操作函数先统一加 `int& resCode`(后来异步类改成 `std::future<int>`,同步类保留 resCode)

5. 锁粒度原则:锁内只做检查/替换,构造一般在锁外
