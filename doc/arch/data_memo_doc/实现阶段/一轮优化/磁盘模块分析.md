1. 线程磁盘用双队列（缓存任务队列 + 磁盘任务队列），设置任务处理数量差距上下限

2. 磁盘模块的`inDisk`定义为`std::unordered_map<std::string, int>`，仅存储数据在单文件中的偏移量

   > 校验码(1B) + 数据实体大小(4B) + 时间信息(17B) + 变量名(固定空间) + 数据实体信息

   变量名是变长的，需要设置上限

   可能存在追加写一半崩溃的的现象，我需要设置一个`校验码`，来校验数据完整性，不完整的数据不读取

   用单文件存储数据，方案如下
   将数据存储+ 索引存储合并到一个数据，数据格式如下： 

   ```
   校验码(1B) + 数据实体大小(4B) + 时间信息(17B) + 变量名(固定空间) + 数据实体信息
   
   时间信息(按照顺序存储)
   - 创建时间(8B 和 std::chrono::system_clock::time_point 有关)
   - 过期时间(8B 和 std::chrono::system_clock::time_point 有关)
   - 是否永不过期(1B)
   
   ```

   - 校验码的话先写一个无效码，然后等数据写完后，再改成有效码
   - 变量名固定大小建议设置为 64,超长返回错误

   ```
   重建读头:先读偏移+0 那 1 字节 → CHECK_BROKEN 截断 / CHECK_DELETED 按大小跳过 / CHECK_VALID 读入
   跳读:下一条 = 当前 + 22 + NAME_LEN + 数据大小
   删除:写偏移+0 为 CHECK_DELETED(数据完整,大小可信)
   全局协议常量(你加到 protocol.h 或单独文件):
   const char CHECK_VALID   = 0x5A;	// 完整数据
   const char CHECK_DELETED = 0xFF;	// 逻辑删除，重建跳过
   const char CHECK_BROKEN  = 0x00;	// 写一半残尾，重建截断
   ```

   **为什么不分索引文件和实体文件：**减少磁盘IO次数

3. 重写机制详解：先写新文件，再删旧文件，一般情况下，只要服务器磁盘容量够，就没问题（一般业务不考虑极端情况，给运维人员自己去维护，而且到时候我会在其他层设置配置文件，维护人员可以配置分配的磁盘空间大小，配置不好是运维和产品的事）
