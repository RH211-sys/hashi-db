# 日志层需求分析

> 状态：设计阶段，本文档只描述目标和约束，尚未实现日志模块或存储恢复代码。

## 1. 背景

当前项目已经实现了 Cache + Disk 两级存储层：

- Cache 保存内存热数据，写操作由写线程串行执行；
- Disk 维护数据文件、inDisk 索引和运行期 holes 空洞索引；
- 磁盘文件采用追加、原位覆盖、空洞复用和重写压缩；
- 当前 Disk 构造时还不会扫描已有文件重建索引，冷启动恢复是遗留工作。

日志层服务于管理层和启动流程，不把日志写入动作混入缓存热路径，也不把普通错误日志当作数据恢复依据。

## 2. 设计目标

### 2.1 日志目标

日志层首版需要：

1. 异步记录错误和关键生命周期事件；
2. 区分服务端日志和客户端日志；
3. 每条日志带有事件发生时间；
4. 日志队列满载时保护高优先级错误，允许低优先级日志被丢弃；
5. 记录日志写失败、队列丢弃和线程停止等自身异常；
6. 禁止记录密码、令牌等敏感内容。

### 2.2 存储恢复目标

重启时需要能够：

1. 顺序扫描数据文件；
2. 重建 Disk::inDisk；
3. 根据 CHECK_DELETED 记录重建运行期 holes；
4. 识别尾部残写、长度错误、校验失败和无法验证的记录；
5. 把活动文件恢复到第一个不可验证记录之前；
6. 恢复结果以结构化对象返回给管理层；
7. 恢复失败时不破坏原始数据文件，并允许管理层拒绝启动。

这里的“恢复”是重建存储索引和可读文件前缀，不是命令重放，也不是逐条历史版本恢复。

## 3. 范围

### 3.1 本阶段范围

- INFO/WARN/ERROR/FATAL 四级文本日志；
- server_log.log 和 client_log.log 两类日志文件；
- 单工作线程、有限队列、批量写入和定时 flush；
- 高优先级日志的旁路同步写入；
- Controller::recover() 同步恢复入口；
- RecoveryResult 结构化恢复结果；
- 数据文件扫描、索引重建、损坏前缀恢复；
- magic/version + CRC32C 的新格式方向。

### 3.2 明确不在本阶段范围内

- 命令日志、AOF、WAL 和命令重放；
- 使用日志文件恢复数据内容；
- 独立的空洞索引日志文件；
- 信息快照（在线用户、用户空间、服务器空间）；
- 日志查询服务、远程日志上报；
- 日志轮换和损坏备份清理的最终参数；
- 旧版 86B 数据文件格式兼容。

## 4. 使用者和边界

### 4.1 管理层

管理层负责：

- 创建和关闭日志模块；
- 在启动阶段调用 Controller::recover()；
- 根据恢复结果决定是否开放服务；
- 将 Controller 返回的错误结果和关键生命周期事件写入日志；
- 在服务关闭阶段等待日志队列排空。

### 4.2 Controller/Disk

Controller 对外提供恢复入口；Disk 负责文件扫描和索引重建。

日志层不直接解释 Disk 的记录格式，避免日志模块和存储协议形成循环依赖。存储层通过结构化返回值报告恢复结果，管理层负责把结果转换为日志事件。

### 4.3 日志模块

日志模块只负责：

- 接收结构化日志事件；
- 排队、格式化、写入对应文件；
- flush、关闭和错误兜底。

## 5. 日志事件需求

### 5.1 服务端关键事件

- 服务启动开始、启动完成；
- 数据恢复开始、恢复完成；
- 恢复发生截断、恢复失败；
- 数据文件打开失败、校验失败、序列化/反序列化失败；
- 日志线程异常、磁盘线程异常；
- 服务关闭开始、关闭完成；
- 日志队列丢弃、日志文件写入失败。

### 5.2 客户端关键事件

- 客户端启动、连接建立、连接关闭；
- 登录成功、登录失败；
- 主动下线、被踢出；
- 网络或协议层错误。

不记录每次成功 CRUD；业务操作失败是否记录，由管理层按照错误级别决定。

### 5.3 必备字段

每条日志至少包含：

- time：本地时区 ISO 8601 时间，精确到毫秒；
- level：INFO/WARN/ERROR/FATAL；
- role：server 或 client；
- module：产生事件的模块；
- event：稳定的事件名称；
- message：人类可读描述；
- 可选扩展字段：错误码、文件路径、偏移、恢复计数、客户端标识等。

字段值必须经过统一转义，不能因为消息中含有换行而破坏“一行一条记录”。

## 6. 故障和数据损失语义

日志层不承诺最近事件一定落盘。普通日志采用异步批量策略，进程突然崩溃时可能丢失尚未 flush 的日志。

存储恢复保证：

- 不使用未经验证的偏移；
- 不把损坏点之后的内容当作正常记录；
- 允许丢弃第一个损坏点之后的文件后缀；
- 不承诺保留原位覆盖之前的逐条历史版本；
- 更早版本恢复依赖后续的完整文件备份能力。

## 7. 验收标准

设计进入实现前应满足：

1. 日志事件格式、级别、优先级和线程模型有明确文档；
2. Controller::recover() 的调用时机和结果字段明确；
3. 数据文件是恢复唯一权威源；
4. 中间损坏不会导致错误偏移继续读取；
5. 备份或修复文件创建失败时不会截断原文件；
6. 命令日志/WAL 不再作为本阶段隐含需求。
