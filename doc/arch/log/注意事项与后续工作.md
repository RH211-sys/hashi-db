# 日志层注意事项与后续工作

> 状态：设计阶段。本文用于保存约束、风险和未完成事项，防止后续实现时遗漏。

## 1. 并发注意事项

- Logger 队列必须由互斥量和条件变量保护；
- Logger 工作线程不能直接持有 Cache 锁或等待 Disk 锁；
- ERROR/FATAL 旁路写入要避免与工作线程并发写同一文件，必须经过统一文件互斥；
- shutdown() 必须保证生产者停止后再 join，不能让日志任务访问已析构对象；
- 存储线程停止时，不能因为日志投递失败导致 future 永久等待；
- 日志模块发生异常时不得递归记录同一异常。

## 2. 日志内容注意事项

- 不记录密码、密码明文、认证令牌、完整网络报文和实体内容；
- key、用户名、远端地址等字段按需要脱敏；
- message 和字段值必须转义，保证一行一条记录；
- 事件名应稳定、可检索，不能只依赖自由文本；
- 时间由日志模块统一生成，避免不同调用方格式不一致；
- 日志文件编码统一使用 UTF-8。

## 3. 文件和空间注意事项

- 日志文件空间不属于 Disk::maxSize；
- .corrupt.<timestamp> 备份文件也不属于 maxSize，但必须有单独的运维清理策略；
- 日志目录不存在时需要明确创建失败行为；
- 文件打开、写入、flush 和关闭失败都要有兜底路径；
- 日志轮换、保留数量和备份自动清理尚未冻结，不能在实现中自行假定。

## 4. 恢复正确性注意事项

- 数据文件是唯一权威源，不能把不存在或未验证的空洞索引文件当作权威；
- inDisk 和 holes 必须在扫描完成后再对外提供；
- 第一个无法验证的记录之后不能继续猜测偏移；
- dataSize 必须检查非负、不会整数溢出且不会超过文件剩余长度；
- CHECK_BROKEN 只能作为未完成记录处理；
- CHECK_DELETED 也必须验证其长度信息，否则可能造成扫描错位；
- 未注册类型不等于文件损坏，恢复阶段不应仅因类型未知而截断；
- 修复前必须保留原文件，备份或活动文件生成失败时拒绝启动；
- 恢复完成后必须重新打开文件并验证句柄状态；
- 当前原位覆盖模型不保证保留旧版本，版本回溯范围只到有效文件前缀；
- 后续完整文件备份可以提供更早版本恢复，但不属于本阶段日志层能力。

## 5. 未决设计

以下事项在实现前必须单独确认：

1. 新记录头的精确 magic、version 和字段排列；
2. CRC32C 放在固定头、记录尾，还是采用头尾双校验；
3. code 是否排除在 CRC 覆盖范围之外；
4. 空洞记录是否执行完整 CRC 校验；
5. 日志队列上限、批量大小和 flush 周期；
6. 日志文件大小上限、轮换命名和保留数量；
7. .corrupt 备份按时间还是按数量清理；
8. Windows 下活动文件替换的最终原子流程；
9. 是否需要旧 86B 文件迁移工具。

## 6. 后续开发任务

按依赖顺序执行：

### 第一阶段：存储协议和恢复

- 冻结新记录格式；
- 实现 CRC32C；
- 实现 Disk 冷启动扫描；
- 实现损坏文件备份和有效前缀修复；
- 增加 RecoveryResult；
- 增加 Controller::recover()。

### 第二阶段：异步日志核心

- 实现 LogLevel、LogRecord 和 Logger；
- 实现有界队列和优先级丢弃；
- 实现普通异步写入；
- 实现 ERROR/FATAL 旁路同步写；
- 实现 flush、shutdown 和写失败兜底。

### 第三阶段：管理层接入

- 接入服务启动、关闭和恢复事件；
- 接入客户端登录、下线、踢出事件；
- 接入存储错误和恢复失败事件；
- 增加敏感字段过滤。

### 第四阶段：测试和运维能力

- 尾部 BROKEN 测试；
- 中间记录损坏测试；
- 长度字段错误测试；
- CRC 错误测试；
- DELETED 空洞扫描测试；
- 重复 key 最新版本测试；
- 未注册类型恢复测试；
- 备份失败、恢复文件创建失败测试；
- 日志队列满载和优先级测试；
- 日志线程停止和 flush 失败测试；
- 日志轮换、备份清理和信息快照另行设计。

## 7. 本阶段完成定义

本阶段设计文档完成的标志：

- 需求边界不再包含命令日志/WAL；
- 空洞索引明确为存储层扫描得到的运行时状态；
- 日志层和存储恢复层的职责边界清晰；
- 恢复失败不会静默破坏原文件；
- 所有未决事项都有记录；
- 后续实现可以按照任务顺序推进，不依赖口头约定。
