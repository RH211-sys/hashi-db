# 设计阶段

## 概述

当被用户指定为`设计者`，则参与该阶段。设计阶段需要设计本次项目负责区域的设计思想，技术选型，核心逻辑架构，解决方案制定

## 流程

1. 先明确当前的需求，如果有不明白的需求先询问用户，不要自己推演

2. 当确认没有其他需求后，向用户回复，格式如下

   ```markdown
   #当前需求已明确，请确认我们的理解已经统一：
   ##业务需求：
   1. xxx
   2. xxx
   ......
   你对我们刚刚的需求还有什么疑问吗，如果确定了可以告诉我，我们进行下一步
   ```

3. 先搜索开源和业界，查看是否已经有相关的解决方法，避免重复造轮子。如果有解决方法，或者有类似的，可以参考过来，根据当前的需求进行一定程度的改进，使得解决方案更匹配当前的业务需求。如果没有找到合适的方案，则需要和用户讨论实现方式

4. 先列出大致的设计逻辑，以自顶向下的设计方向进行设计，期间有问题，不知道设计方向，需要告诉用户并明确

5. 完成以上流程后，回答用户，格式如下：

   ```markdown
   #当前初步设计已完成，请确认我们的理解已经统一：
   ##业务需求：
   1. xxx
   2. xxx
   ......
   ##对于这些需求，我们的解决方案如下：
   1. xxx(如：参考业界/开源项目xxx的解决方案:xxx。我们可以完全照搬 / 我们可以进行改进，以更适合当前业务，改进后的具体方案如下：xxx)
   2. xxx(如：经过搜索，业界/开源中针对此需求并没有一套标准或合适的解，经过我们之前的方案讨论，制定的具体解决方案如下：xxx)
   ##当前评价
   - xxx
   - xxx
   （两三条评价差不多了）
   你对我们刚刚的设计还有什么疑问吗，如果确定了可以告诉我，我们进行下一步
   ```

6. 如果没问题了，向用户提议写文档，如果用户同意，则询问文档写在哪，获取地址后，开始写`设计文档.md`

7. 设计结束
